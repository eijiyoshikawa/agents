## Step 4. 45日無料トライアル・不正対策の把握（System）

### 4.1 実装事実
- **トライアル期間: 45日間**（全プラン共通、クーポン不要で自動付与）
- トライアル終了後に自動継続（命日課金）
- **二重利用防止策（実装済）**:
  1. メールカノニカル化（Gmailのドット・+エイリアスを除去して正規化）
  2. 使い捨てメール 16+ ドメインのブラックリスト
  3. `hasUsedTrial` フラグ + Stripe 過去サブスク履歴の二重チェック
- 決済: Stripe（主要6ブランド対応）
- 解約: Stripe Customer Portal でセルフ解約可、日割返金なし
- クーポン運用で特定プランへの延長トライアルや限定提供が可能

### 4.2 45日トライアルの戦略的意味

- **業界最長クラス（SocialDog 7日、多くのSaaS 14日）** → **LPの強力な訴求軸**
- 長期間の「価値体験」を作れる → **Aha誘発機会が格段に増える**
- 反面、**CAC回収サイクルが最長で45日延びる** → 広告投資のキャッシュサイクル悪化
- **トライアル完了率とTrial→Paid CVR**が最重要KPI

### 4.3 戦略上の重要論点

| 論点 | 検討事項 |
|------|---------|
| トライアルの長さは強みか弱みか | **強み**。ただし45日間のエンゲージメントを維持する仕組み必須 |
| 有料転換をどう最大化するか | Day7/Day14/Day30/Day44 のマイルストーン通知・使用ログレポートを設計 |
| 不正利用（Trial周回）の兆候監視 | 実装済の仕組みは有効。ただし **IPアドレス＋端末fingerprint** の追加強化を推奨 |
| トライアル期間を短縮すべきか | **短縮不要**。むしろ「45日」を訴求の中心に据える |
| 年払導入の設計 | 年額 = 月額 × 10（2ヶ月分割引）で導入推奨 |

### 4.4 45日間にユーザーが経験すべき体験の設計
```
Day 0:  会員登録・メール検証・オンボーディング開始
Day 1:  X API キー接続完了 → 初回投稿生成プレビュー
Day 2〜3: 初自動投稿実行 → 「夜の10時に届く初投稿通知メール」
Day 7:  初週レポート（生成数・反応数・推定インプレ）
Day 14: Standard/Pro アップグレード訴求 + 30日保証メール
Day 21: 目的別プロンプト切替提案（engagement/followers/infoproduct）
Day 30: 月初レポート + 「残り15日のAha総仕上げ」メール
Day 40: トライアル終了予告＋決済確認
Day 44: 最終リマインド＋延長クーポン（退会寸前層向け）
Day 45: 自動課金 or 離脱 → ウィンバック用リスト登録
```

→ Day7/14/30/44 を **CSの設計ターゲット**に固定する。

### 4.5 v1からの変更点
- v1「14日無料＋30日成果保証」 → **45日無料単独でリスクリバーサル完遂**
- 30日返金保証は「45日も試せて、さらに保証？」と冗長に見えるため撤回
- クーポン活用で Early Cancel 防止（例: 「もう1ヶ月無料延長クーポン」を Day40 配布）

## Step 5. AI生成機能（Claude Sonnet 4・目的別プロンプト）の把握（System）

### 5.1 実装事実
- 採用モデル: **`claude-sonnet-4-20250514`**（Anthropic Claude API）
- 生成条件: 140文字以内、日本語/英語、ハッシュタグ最大2個、URL無し、人間らしい文体
- **目的別プロンプト3種**:
  - `engagement` — インプレッション最大化
  - `followers` — フォロワー増加
  - `infoproduct` — 情報商材・販売支援（専門知識を「チラ見せ」してリード化）
- **トーン**: Professional / Casual / Humorous / Educational の4プリセット、Proはカスタム指定可
- 投稿時刻デフォルト: 09:00 / 12:00 / 18:00
- Vercel Cron で実行、ステータスは posted / scheduled / failed で管理
- ダッシュボードでプレビュー可

### 5.2 戦略的示唆

#### 5.2.1 目的別プロンプトという独自性
3目的の分離は **competitorに対する明確な差別化軸**。
特に `infoproduct` は、情報商材・コーチ・講座販売者というクリアな ICP が存在し、
彼らにとって「専門知識のチラ見せ文面」は最も再現困難かつ高価値。
→ **infoproduct 目的の利用者を第一ICPに置く戦略が成立する**可能性大。

#### 5.2.2 トーン4種の汎用性
Professional／Casual／Humorous／Educational の4種は、個人事業主のペルソナを
ほぼ網羅できる。Pro のカスタム文体で「自分らしさ」をさらに追加できる設計も強み。

#### 5.2.3 Claude Sonnet 4 の価値訴求
- 最新世代モデル（料金概要で `claude-sonnet-4-20250514`）
- 他社AI投稿SaaSがGPT-3.5系を使うケースが多い中、**明確な品質優位**
- **「Anthropic Claude 搭載」** はテック感度の高い層に刺さるキーワード
- ただし、ユーザー目線ではモデル名より **「文面の自然さ・日本語精度」** を訴求するほうが効く

#### 5.2.4 投稿時刻デフォルトの改善余地
- デフォルト 09:00/12:00/18:00 は無難だが、X のエンゲージメントピークは **朝7-8時／夜21-23時** という研究もあり、
  プラン別や目的別で推奨時刻テンプレを変える余地あり（「フォロワー増プリセット」等）

### 5.3 機能の戦略的優先度（マーケ活用視点）

| 機能 | マーケ活用度 | LP訴求度 | コンテンツ化難易度 |
|------|------------|---------|------------------|
| AI自動投稿生成 | ★★★★★ | ★★★★★ | 低 |
| 目的別プロンプト3種 | ★★★★☆ | ★★★★☆ | 中 |
| トーン4種 | ★★★☆☆ | ★★★☆☆ | 低 |
| スケジューリング | ★★☆☆☆ | ★★★☆☆ | 低 |
| マルチアカ（Pro） | ★★★★☆ | ★★★★☆ | 中 |
| レポート/CSV（Pro） | ★★☆☆☆ | ★★☆☆☆ | 低 |

→ **マーケの主力訴求**は「AI自動投稿生成」+「目的別プロンプト」の2点セット。

### 5.4 v1からの変更点
- v1の「自動いいね／自動フォロー／自動DM」想定 → **実装されていない**ため訴求から除外
- v1で示した「攻めの自動化」は、XProの実装ではなく **「賢い自動投稿」** に再定義
- 新たな強みキーワード: **「Claude AI × 目的別 × 日本語特化」**

## Step 6. 技術スタック（Next.js14/Prisma/Neon/Stripe）の把握（System）

| レイヤ | 技術 | 特記事項 |

| AI | Anthropic SDK 0.80（Claude Sonnet 4） | - |

### 6.2 主要APIエンドポイント（実在）
- 認証: `/api/auth/register` `/api/auth/verify-email`
- 決済: `/api/stripe/checkout` `/api/stripe/portal` `/api/stripe/webhook`
- 投稿: `/api/posts/generate` `/api/posts/schedule`
- 連携: `/api/x/connect` `/api/user/plan`
- 管理: `/api/admin/*`

### 6.3 データモデル（抜粋）
`User` / `EmailVerificationToken` / `XAccount` / `PostSettings` / `Post` / `Coupon` / `AdminLog`

### 6.4 戦略的示唆（開発・運用観点）

#### 6.4.1 技術選定の強み
- **Next.js + Vercel + Neon** の組合せは運用コストを極小化できるサーバーレス構成
- **Stripe Customer Portal** によりセルフサービスが成立（CS負荷軽減）
- **Resend** のカスタムドメインメールで到達率確保

#### 6.4.2 未実装・脆弱性（リスト）
サービス概要で明示された未実装項目:
- **パスワードリセット機能** → セキュリティおよびサポート問合せの温床になる（最優先実装）
- **エラー監視（Sentry等）** → 障害時の検知遅れリスク（早期導入推奨）

#### 6.4.3 Neon Singapore リージョンの論点
- 日本からのレイテンシは 40-60ms 程度。許容範囲だが、今後PoPを東京に移すと体感向上
- 個人情報保護の越境移転について、プライバシーポリシーに明記必須

#### 6.4.4 戦略リライトへの反映
- v1 の Supabase 想定 → **Prisma + Neon + NextAuth** に完全置換
- 計測タグ（Meta CAPI 等）の実装先は **Next.js Route Handlers** 内で行う
- イベントスキーマは `events.yaml` 等を `prisma/` に併設する想定
- 開発優先度（後述 Step 23-24）は既存コードベースへの追加として書き直す

### 6.5 X API に関する重要事実
- **ユーザー自前の X Developer API キー（Consumer Key/Secret + Access Token/Secret）が必要**
- X Free プラン（1,500投稿/月）想定で設計されている
- **つまり XPro のX API費用はユーザー負担 or 0円で成立**する構造

→ これは **ビジネスモデル上、極めて大きな利点**。v1 で懸念した「Pro tier $5,000/月」の原価上昇は
発生しない。**粗利率がv1想定より大幅に高い**（後述 Step 17 で再試算）。

反面、**ユーザーがAPIキー取得できないとActivationできない**という、Activation最大の障壁を抱えている（Step 26 で詳述）。

## Step 28. 批判的検証（Devil's Advocate v2）

### 28.1 立場
v2戦略を「善意の敵」として精査。
目的は否定ではなく、実行前に想定リスクを最大化して潰すこと。

### 28.2 根本を疑う（5問）

**Q1. ARPU ¥1,699 のSaaSで広告獲得は本当に成立するか？**
- CAC許容¥7,900 / Payback 6.6ヶ月 は **極めてタイト**
- Metaの日本SaaS広告の実勢CPAは ¥5,000-15,000 が一般的
- 反論: v2計画では広告依存を50%以下に抑え、オーガニック/アフィリ/コミュ/親会社ルートで補完する設計
- **提案**: Day30でCPA上限超えが続いたら広告を即停止、コミュ施策に100%振り分ける判断ルールを追加

**Q2. 45日無料は長すぎないか？**
- 確かに業界最長だが、**45日を活用してもらえなければただの期間**
- 多くのユーザーが Day5 以内に離脱し、ゾンビトライアルが溜まる懸念
- → **Day5時点で未接続のユーザーを自動的に「新たな接続支援キャンペーン対象」化**することを提案
- また Day30時点の稼働率が30%を下回るなら、トライアル期間そのものを再検討

**Q3. X APIキー取得障壁は本当に75%まで上げられるか？**
- 現状仮説50% → 75%は **+25pp の難易度の高い改善**
- 一般ユーザーにはX Developer 申請手順が専門的すぎる
- → **提案**: 有償の「API取得代行サービス」を ¥3,000-5,000 で提供。Legal整理し、そもそも接続できない層を救う
- 代替: OAuth 2.0 フローを最大限利用し、ユーザー入力項目を減らす技術改修

**Q4. `infoproduct`プロンプトは炎上リスクを抱えていないか？**
- 情報商材販売者は法的・倫理的にグレー領域が多い
- 「AIで月100万円稼ぐ」みたいな誇張投稿が大量発生するリスク
- → **提案**: プロンプトに **違法・誇張・景表法違反ワード** の自動検閲＋警告UIを実装
- 炎上時の対応フロー（一時停止＋謝罪）を事前に用意
- 「公式アフィリガイド」で違反規約を配布

**Q5. 経営顧問会社発は強みか弱みか？**
- 強み: 信頼・既存顧客ネットワーク・コンサル経験
- 弱み: 「経営顧問屋がSaaSを作って大丈夫？」の懐疑
- → 代表の個人ブランディング（X/note）で「SaaS事業者」としての姿を前面化
- 親会社の関係明示は透明性的にOK、ただしXPro自身は **SaaS会社として独立した発信**を維持

### 28.3 失敗シナリオ3本

#### シナリオA: API接続率が50%から改善しない
- **引き金**: Day30で接続率 < 55%
- **兆候**: LP→Signup は改善でも、登録後の実効稼働がない
- **対応**: 有償代行・人手サポートを全振り、広告を止めオーガニック中心に転換

#### シナリオB: Trial→Paid CVR が10%を下回る
- **引き金**: Day45時点でTrial→Paid < 10%
- **兆候**: ユーザーの実使用は多いのに課金が渋い
- **対応**: プラン価格を再検討（Minimum ¥780へ下げ、Standardに誘導）／ 延長クーポン強化

#### シナリオC: 情報商材系で炎上・行政指導
- **引き金**: 景表法違反事例が3件以上発生
- **対応**: `infoproduct`プロンプト停止、ガードレール厳格化、公式謝罪

### 28.4 採用してはいけない施策（赤フラグ）
- **自動DM営業**（未実装でよかった。絶対に作らない）
- **フォロワー買い**: 違法・発覚時に信用崩壊
- **「絶対稼げる」訴求**: 景表法＋特商法ダブル違反
- **海外展開を焦って取り組む**: ARPU、決済、言語で別製品必要

### 28.5 見落とされている観点
- **AI出力の権利帰属**: 明確なToS規定必要（Legalで対処済）
- **Anthropic API依存**: 原価＆ベンダーロックインリスク。GPT-4 mini / Gemini等の二重化検討
- **Xアカウント連携への不安**: 「APIキー預ける」心理的ハードルをLPのFAQで解消
- **Xプラットフォーム自体の衰退**: MAUが年10%減る場合の備え（Threads/Bluesky PoC枠10%維持）
- **親会社事業との相互依存リスク**: XPro成功しすぎて親会社本業が停滞するシナリオ

### 28.6 最終提言（v2）

1. **API取得代行サービスを ¥3,000-5,000 で有償化**（Step 25、Legal整理）
2. **Day5 未接続自動介入キャンペーン**（CS）
3. **`infoproduct`プロンプトのガードレール実装**（Backend + Legal）
4. **Claude API依存の二重化計画**（90日以降のPoC）
5. **Meta/X広告のCPA上限超え時、即停止ルール**（Ad Op）
