## 1. コンテキスト（背景）

役員会議（2026-06-15）にて、以下の方針が決定された。

- **Claude・GitHub・Notion を1アカウントに統合**し、全社員がAIを活用できる環境を構築する。
- **個人PCにデータが流出しないよう、会社側でアカウントを一元管理**する。
- **Google Drive と Notion を連携**させ、ドキュメントが自動的に双方へ保存される状態を目指す。
- 運用レポート自動化（約80%完成、T-4）等、既存のAIワークフローを統合基盤に集約する。

現状の課題:

1. **シャドーIT／データ流出リスク** — 各人が個人アカウント・個人PCでClaudeやNotionを使うと、顧客情報・社外秘が個人環境に残留する。
2. **ナレッジの分散** — 議事録(Notion)・コード(GitHub)・資料(Drive)が分断され、AIが横断参照できない。
3. **アカウント管理の不在** — 退職時のアクセス剥奪・監査ログが取れない。
4. **コスト不可視** — 個人課金が乱立し、全社のAI利用コストが把握できない。

## 2. 決定（Decision）

会社が管理する **3層構成の統合AI業務プラットフォーム** を構築する。

```
┌──────────────────────────────────────────────────────────┐
│  ① ID・アクセス管理層（IdP）                               │
│     Google Workspace を会社の単一IDソースとする            │
│     - 全SaaSへ SAML/OAuth SSO で接続                       │
│     - 入退社で1箇所のアカウント停止 → 全サービス遮断       │
│     - 2要素認証(2FA)を全社必須                             │
└───────────────┬──────────────────────────────────────────┘
                │ SSO (SAML / OAuth)
┌───────────────▼──────────────────────────────────────────┐
│  ② SaaS / ツール層（会社オーナー権限で一元管理）           │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌───────────┐ │
│  │  Claude  │  │  GitHub  │  │  Notion  │  │  Google   │ │
│  │  (Team/  │  │  (Org)   │  │ (Workspace│  │  Drive    │ │
│  │  Enterprise)│ │          │  │  /Teams) │  │ (共有Drive)│ │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └─────┬─────┘ │
│       └─────────────┴──────┬──────┴──────────────┘       │
└──────────────────────────┬─┴──────────────────────────────┘
                           │ MCP / API / Webhook
┌──────────────────────────▼─────────────────────────────────┐
│  ③ 連携・自動化層（このリポジトリ = agents が司令塔）        │
│   - Claude Code + MCP（Notion / Google Drive / GitHub）     │
│   - Drive⇆Notion 双方向同期（ドキュメント自動保存）         │
│   - 運用レポート自動化パイプライン（T-4）                   │
│   - 役員会議タスク化パイプライン（board_meetings/）         │
└────────────────────────────────────────────────────────────┘
```

### 中核となる決定事項

| # | 決定 | 内容 |
|---|------|------|
| D-1 | **Google Workspace を単一IDソース(IdP)とする** | 全SaaSへSSO接続。入退社管理を1点に集約 |
| D-2 | **各SaaSは「会社オーナー権限」で開設・契約** | 個人アカウントでの業務利用を禁止。Claude=Team/Enterprise、GitHub=Organization、Notion=Workspace、Drive=共有ドライブ |
| D-3 | **このリポジトリ(`agents`)を連携層の司令塔とする** | Claude Code + MCP で Notion / Drive / GitHub を横断操作。新規基盤は作らず既存資産を活用 |
| D-4 | **Drive⇆Notion 同期は MCP/API のスケジュール同期で実現** | リアルタイム双方向は初期スコープ外。日次/オンデマンド同期から開始 |
| D-5 | **データは共有ドライブ／Workspace内に限定** | 個人PCローカル保存・個人Driveへのコピーを禁止（DLP設定） |

## 3. 検討した選択肢

| 選択肢 | 概要 | 採否 | 理由 |
|--------|------|------|------|
| **A. Google Workspace を IdP に統合**（採用） | 既に利用中のGoogleを軸にSSO化 | ✅採用 | 追加IdP契約不要・Drive連携と親和的・学習コスト低 |
| B. Okta等 専用IdP を導入 | 専業IdPで本格的なID統制 | ❌ | この規模ではオーバースペック・月額コスト過大 |
| C. 各SaaS個別にアカウント管理（現状維持） | 統合せず運用ルールのみ強化 | ❌ | 流出リスク・監査不能・退職時剥奪漏れが解消されない |
| D. 自前統合基盤を新規開発 | 独自ポータルを構築 | ❌ | 開発・保守コスト過大。MCPで代替可能 |

## 4. 影響（Consequences）

### ポジティブ
- 退職・異動時に **Google アカウント停止1回で全サービス遮断**（剥奪漏れゼロ）。
- 顧客情報・社外秘が **個人環境に残らない**（D-5 / DLP）。
- 議事録・コード・資料を **Claude が横断参照**でき、AI活用の質が向上。
- 全社のAI利用 **コストが可視化**（会社契約に集約）。

### ネガティブ / トレードオフ
- 各SaaSの **上位プラン契約コスト**が発生（Claude Team/Enterprise, Notion, GitHub Org）。→ 第5章コスト試算参照。
- SSO移行時に **既存個人アカウントからのデータ移管**作業が必要。
- 単一IDソース化により **Google Workspace が単一障害点**になる（2FA・リカバリ設計で緩和）。

### Legal / Compliance 確認事項（要 Legal レビュー）
- 顧客個人情報を Claude/Notion で扱う際の **委託先の安全管理措置**（個人情報保護法 22条）。
- 各SaaSの **データ越境・学習利用オプトアウト**設定（Claude: 学習に使われない契約形態の確認）。
- 求職者情報（現場キャリア／T-8 厚労省許可関連）の取扱いと **保管場所の制限**。

| フェーズ | 内容 | 担当 | 前提 |

- Drive⇆Notion 同期の対象範囲（全社 or 部門限定）と同期頻度。
- 既存個人アカウントのデータ移管方法と移行期間。
