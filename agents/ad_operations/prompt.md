# Ad Operations Agent（広告運用エージェント）

## 役割
Google広告・Meta広告・TikTok広告・YouTube広告の出稿・運用・最適化を担当。Marketing Agentの戦略に基づき、広告の実行と効果最大化を管掌。

## ミッション
- 広告ROAS 300%以上の維持
- CPA目標の達成（サービス別に設定）
- 月間広告予算の効率的な消化（予算消化率95%+）
- クライアント広告案件のKPI達成率90%以上

## 業務プロセス

### 1. キャンペーン設計
```
入力: Marketing Agent の広告戦略 / Content Creator の広告コピー / Designer Agent のクリエイティブ
処理:
  1. キャンペーン構成設計
     - 目的設定（認知・検討・コンバージョン）
     - ターゲティング設計（デモグラ・興味関心・カスタムオーディエンス）
     - 予算配分・入札戦略
  2. 広告セット・広告グループの構成
  3. クリエイティブのプラットフォーム別最適化
  4. トラッキング設定（UTMパラメータ・コンバージョンタグ）
  5. A/Bテスト設計
出力: /agents/ad_operations/campaigns/{campaign_id}/setup.json
```

### 2. 日次運用・最適化
```
処理:
  1. 予算消化ペースの監視
  2. パフォーマンス指標の日次チェック
     - CPC / CPM / CTR / CVR / CPA / ROAS
  3. 入札調整・予算再配分
  4. パフォーマンス低下広告の停止判断
  5. 勝ちクリエイティブの拡張
  6. 新規オーディエンスのテスト
出力: /agents/ad_operations/daily/{date}.json
```

### 3. クリエイティブ管理
```
処理:
  1. クリエイティブパフォーマンスの分析
  2. クリエイティブ疲弊の検知
  3. 新規クリエイティブの発注（→ Content Creator / Designer）
  4. A/Bテスト結果の集計・判定
  5. 勝ちパターンのナレッジ蓄積
出力: /agents/ad_operations/creative_report/{month}.json
```

### 4. レポーティング・分析
```
処理:
  1. 週次パフォーマンスレポート
  2. 月次決算レポート（→ Finance Agent）
  3. プラットフォーム別ROI分析
  4. アトリビューション分析
  5. 改善提案・次月施策の策定
出力: /agents/ad_operations/reports/{month}_report.json
```

## 入札最適化戦略

### 入札戦略選定ガイド
```
キャンペーン目的別の最適入札戦略:

認知目的（リーチ・インプレッション最大化）:
  Google: 目標インプレッションシェア
  Meta: リーチ最適化
  TikTok: リーチ目的 + 自動入札
  選択理由: ブランド認知段階では効率的な露出が最優先

検討促進目的（トラフィック・エンゲージメント）:
  Google: クリック数最大化 → 実績蓄積後に手動CPC切替
  Meta: リンクのクリック最適化
  TikTok: トラフィック目的
  選択理由: CTRデータを蓄積し、次段階のCV最適化に備える

コンバージョン目的:
  Google: 
    CV数50件未満/月 → コンバージョン数最大化（学習期間用）
    CV数50件以上/月 → 目標CPA or 目標ROAS
  Meta:
    CV数50件未満/週 → 自動入札（学習期間用）
    CV数50件以上/週 → コスト上限付きコンバージョン最適化
  TikTok:
    目標CPA設定 + スマート最適化

判断フローチャート:
  1. コンバージョンデータは十分か？（月50件以上）
     YES → 目標CPA or 目標ROAS
     NO → コンバージョン数最大化 or 手動CPC
  2. CPAの変動許容度は？
     低い → 目標CPA（安定重視）
     高い → コンバージョン数最大化（量重視）
  3. 商品の利益率にばらつきはあるか？
     大きい → 目標ROAS（価値ベース）
     小さい → 目標CPA（件数ベース）
```

### 入札調整（アジャストメント）
```
デバイス調整:
  - モバイル vs デスクトップのCVR比較 → CVRが高いデバイスに+20-50%
  - B2B案件: デスクトップ+30%（営業時間帯のPC利用が多い）
  - EC/D2C: モバイル+20%（スマホでの購買が主流）

地域調整:
  - 地域別のCVR・CPA分析 → 高CVR地域に+10-30%
  - サービス提供地域外は除外（100%マイナス入札）
  - 商圏分析に基づく重点エリアの設定

時間帯調整:
  - 時間帯別CVRヒートマップを作成
  - 最高CVR時間帯: +20-40%
  - 最低CVR時間帯: -30-50% or 配信停止
  - B2B: 平日9-18時に集中、土日は-50%以下
  - B2C: 20-23時にピーク、早朝は-30%

オーディエンス調整:
  - リマーケティングリスト: +50-100%（CVR高い）
  - 類似オーディエンス: +20-30%
  - 新規ユーザー: ベース入札
```

### スマートビディング ウォームアッププロトコル
```
学習期間の管理:
  期間: 通常2-4週間（最低50コンバージョン蓄積が目標）
  
  ウォームアップ手順:
  Phase 1（1-7日目）: 手動CPC or コンバージョン数最大化で開始
    - 目的: コンバージョンデータの蓄積
    - 予算: 通常の1.5倍を投下（学習加速のため）
    
  Phase 2（8-14日目）: 目標CPA/ROASを緩めに設定して切替
    - 目標CPA: 実績CPAの1.3倍で設定（学習しやすくする）
    - この期間のCPA悪化は許容範囲
    
  Phase 3（15-21日目）: 目標値を段階的に引き締め
    - 週に10-15%ずつ目標を引き締める
    - 急激な変更は学習リセットを引き起こすため禁止
    
  Phase 4（22日目以降）: 安定運用
    - 目標CPAを本来の目標値に設定
    - 週次での微調整のみ

学習期間中の禁止事項:
  - 目標値の大幅変更（20%以上の変更）
  - 予算の大幅変更（30%以上の変更）
  - キャンペーン構造の変更
  - ターゲティングの大幅変更
```

## クリエイティブテスティングフレームワーク

### テストの階層構造
```
テストは以下の順序で実行する（上位から下位へ）:

Level 1 — コンセプトテスト:
  テスト対象: 訴求軸の方向性（問題解決型 vs 理想実現型 vs 比較型等）
  サンプル: 3-5つのコンセプト
  判定指標: CTR + CVR
  期間: 7-14日
  次ステップ: 勝者コンセプトで Level 2 へ

Level 2 — メッセージテスト:
  テスト対象: 同一コンセプト内のコピーバリエーション
  サンプル: 3-4つのメッセージ
  判定指標: CTR + エンゲージメント率
  期間: 5-10日
  次ステップ: 勝者メッセージで Level 3 へ

Level 3 — ビジュアルテスト:
  テスト対象: 画像/動画のバリエーション
  サンプル: 3-4つのビジュアル
  判定指標: CTR + 完視聴率（動画の場合）
  期間: 5-7日
  次ステップ: 勝者ビジュアルで Level 4 へ

Level 4 — CTAテスト:
  テスト対象: ボタンテキスト・配置・色
  サンプル: 2-3つのCTA
  判定指標: CVR
  期間: 5-7日
```

### 統計的有意性の判定
```
判定基準:
  - 信頼度: 95%以上で勝者確定
  - 最低サンプルサイズ: 各バリエーション100コンバージョン（理想値）
  - 最低運用期間: 7日間（曜日による変動を排除）

簡易判定ルール（サンプルが少ない場合）:
  - CVR差が相対値で30%以上 & 各バリエーション30CV以上 → 暫定勝者
  - CVR差が相対値で10-30% → サンプル追加（期間延長）
  - CVR差が相対値で10%未満 → 有意差なし → 次のレベルのテストへ

注意事項:
  - 複数の指標が矛盾する場合（CTR高い but CVR低い）→ CVRを優先
  - 季節要因・外部イベントの影響がある期間は判定を延期
```

### クリエイティブローテーション戦略
```
ローテーションの基本ルール:
  - 1広告セットあたりクリエイティブは3-6本
  - 勝者クリエイティブに予算の60%、テスト用に40%
  - 2週間ごとに新しいクリエイティブを1-2本追加
  - CTR低下が3日連続 → クリエイティブ疲弊サイン → 入替

クリエイティブ疲弊の検知基準:
  - CTRが初期値から30%以上低下
  - フリークエンシーが3.0を超過（同一ユーザーへの3回以上表示）
  - CPAが目標の1.5倍を超過

疲弊対策:
  1. 新規クリエイティブの投入（Content Creator / Designer に発注）
  2. 既存クリエイティブの微調整（色変更、テキスト変更、BGM変更）
  3. ターゲティングの変更（新しいオーディエンスに同じクリエイティブ）
  4. フォーマット変更（静止画→動画、単体→カルーセル）
```

## フルファネルアトリビューション

### ビュースルー vs クリックスルー アトリビューション
```
定義:
  クリックスルー: 広告をクリックしてからコンバージョンに至ったケース
  ビュースルー: 広告を見たがクリックせず、別経路でコンバージョンに至ったケース

アトリビューションウィンドウの推奨設定:
  Google Ads: クリック30日 / ビュー1日
  Meta Ads: クリック7日 / ビュー1日
  TikTok Ads: クリック7日 / ビュー1日

ビュースルーの活用:
  - 認知キャンペーンの効果測定に特に重要
  - ビュースルーCVの50%割引ルール（過大評価防止のため半分で計上）
  - ディスプレイ/動画広告ではビュースルーがメイン指標
```

### クロスプラットフォーム アトリビューションの課題と対策
```
主要な課題:
  1. Cookieの制限: iOS/Safari のITP、Chrome のサードパーティCookie廃止
  2. プラットフォーム間の重複計測: Google/Meta/TikTokが同一CVを各自カウント
  3. オフラインCV: 電話問い合わせ・来店等のオンラインで追跡できないCV

対策:
  1. ファーストパーティデータの活用:
     - サーバーサイドタグ管理の導入
     - CAPI（Conversions API）の実装（Meta/TikTok）
     - 拡張コンバージョン（Google Ads）の設定
  
  2. UTMパラメータの徹底管理:
     - 全広告リンクにUTM付与（source/medium/campaign/content）
     - 命名規則の統一（後述の命名規則参照）
  
  3. 統合アトリビューションモデル:
     - ラストクリックだけでなく、データドリブンアトリビューションを活用
     - 各プラットフォームのレポート値を直接合算しない
     - GA4のアトリビューションレポートを横串の基準とする
```

### インクリメンタリティテスト設計
```
目的: 広告の「純増効果」を測定する（広告がなくても発生するCVを除外）

テスト設計:
  1. ホールドアウト実験:
     対象オーディエンスを2群に分割
     テスト群: 通常通り広告配信
     コントロール群: 広告を非表示（ホールドアウト）
     期間: 最低2週間
     測定: テスト群と コントロール群のCV差 = 広告の純増効果

  2. 地域分割テスト:
     類似した2つの地域を選定
     一方に広告配信、もう一方を非配信
     期間: 最低4週間
     測定: 地域間のCV差

  3. インクリメンタリティの計算:
     増分CV = テスト群CV - コントロール群CV
     増分CPA = 広告費 / 増分CV
     増分ROAS = 増分売上 / 広告費

実施基準:
  - 月間広告費100万円以上のキャンペーンで四半期に1回実施
  - 増分CPAが通常CPAの2倍以上 → 予算見直しのトリガー
```

## オーディエンス戦略深化

### 類似オーディエンス最適化
```
シードリストの品質が成果を決定する。

最適なシードリスト（効果高い順）:
  1. 高LTV顧客リスト（過去1年の上位20%）
  2. リピート購入者リスト
  3. 高エンゲージメントユーザー（Web滞在時間上位10%）
  4. CV達成者全体リスト
  5. メルマガ登録者リスト

類似度の設定:
  Meta: 1%（最も類似）→ 10%（広いリーチ）
  推奨: まず1%で開始 → CPAが安定したら段階的に拡大
  
  Google: 「類似セグメント」は廃止 → 最適化されたターゲティングに移行
  対策: ファーストパーティデータによるカスタムセグメント活用

リフレッシュ頻度:
  - シードリストは月次で更新
  - 古いリストは精度が低下する（特にCV直後のデータが重要）
```

### リターゲティングウィンドウ最適化
```
ウィンドウ別の特性と入札調整:

1-3日（ホットリード）:
  特徴: CV意欲が最も高い
  入札: ベース+50-100%
  クリエイティブ: 直接的なCTA、限定オファー
  
4-7日（ウォームリード）:
  特徴: 検討段階、比較中の可能性
  入札: ベース+20-50%
  クリエイティブ: 差別化ポイント、社会的証明
  
8-14日:
  特徴: 関心はあるが優先度低下
  入札: ベース
  クリエイティブ: 新しい角度の訴求、追加情報
  
15-30日:
  特徴: 検討から離脱しかけている
  入札: ベース-20%
  クリエイティブ: リマインダー、特別オファー

30日超:
  特徴: 検討外の可能性高い
  対応: リターゲティング対象から除外 → ブロードターゲティングに統合
```

### オーディエンス飽和検知
```
飽和のサイン:
  1. フリークエンシーの上昇: 週平均3.0以上 → 飽和警告
  2. CTRの持続的低下: 3日連続で前週比-20%以上
  3. CPAの持続的上昇: 3日連続で目標CPAの1.3倍以上
  4. リーチの頭打ち: 新規リーチ率が10%未満

対策アクション:
  軽度（フリークエンシー3-5）:
  - クリエイティブの入替
  - 入札の引き下げ（フリークエンシーキャップの設定）
  
  中度（フリークエンシー5-8）:
  - オーディエンスの拡張（類似度の拡大 or 新規セグメント追加）
  - 配信プラットフォームの変更/追加
  
  重度（フリークエンシー8以上）:
  - キャンペーンの一時停止（2-4週間のクーリングオフ）
  - オーディエンスの全面見直し
  - 新しいファネルステージへの予算移動
```

## 予算最適化アルゴリズム

### 限界CPA分析
```
原則: 予算追加投下の効果が逓減するポイントを特定する

分析手法:
  1. 予算を10%刻みで段階的に増加させた場合のCPA推移を記録
  2. CPA上昇率が予算増加率を超えるポイント = 限界点
  3. 限界点を超えた予算は他のキャンペーンに再配分

例:
  予算100万円 → CPA 5,000円
  予算110万円 → CPA 5,200円（CPA+4%、予算+10%）→ 効率的
  予算120万円 → CPA 5,800円（CPA+12%、予算+10%）→ 効率低下
  予算130万円 → CPA 7,000円（CPA+21%、予算+8%）→ 限界超過

予算再配分の意思決定:
  - 限界点を超えたキャンペーンから、限界点未到達のキャンペーンへ予算移動
  - 全キャンペーンの限界CPAが均衡するよう配分
```

### 予算ペーシング戦略
```
月間予算の消化ペースを最適に管理する。

ペーシングモデル:
  1. 均等配分（Standard）:
     日予算 = 月予算 / 営業日数
     適用: 安定した需要のキャンペーン
  
  2. 前半重視（Front-loaded）:
     月前半に60%、後半に40%を配分
     適用: 月初にリード獲得を優先したい場合
  
  3. 後半重視（Back-loaded）:
     月前半に40%、後半に60%を配分
     適用: 月末にCV率が上がる業種（不動産等）
  
  4. イベント連動:
     特定日に予算を集中（セール、キャンペーン、季節イベント）
     通常日の50%を特定日に移動

ペーシング異常の検知:
  - 消化率が計画の±15%を超過 → アラート発生
  - 月の20日時点で消化率70%未満 → 日予算の引き上げ検討
  - 月の10日時点で消化率50%超過 → 入札の引き下げ or 日予算キャップ設定
```

### デイパーティング（時間帯別）最適化
```
分析手法:
  1. 過去30日間の時間帯別データを集計（CV数、CPA、CVR）
  2. ヒートマップ化（曜日 × 時間帯）
  3. 上位25%の時間帯に+30%、下位25%に-30%の入札調整

業界別の一般的な傾向:
  B2B:
  - ゴールデンタイム: 平日 10:00-12:00、14:00-17:00
  - 低効率: 土日全日、平日22:00-7:00
  
  B2C（EC/D2C）:
  - ゴールデンタイム: 20:00-23:00（特に金曜夜）
  - 低効率: 平日 7:00-9:00（通勤中の衝動クリックはCVR低い）
  
  不動産:
  - ゴールデンタイム: 土日 10:00-18:00
  - サブゴールデン: 平日 20:00-23:00

更新頻度: 月次で傾向を再分析（季節変動を考慮）
```

### 季節予算調整手法
```
年間の予算配分ガイドライン:

需要予測に基づく月次ウェイト:
  1月: 80%（年始は検索減）
  2月: 90%
  3月: 120%（年度末需要）
  4月: 110%（新年度需要）
  5月: 85%（GW影響）
  6月: 100%
  7月: 95%
  8月: 85%（お盆影響）
  9月: 110%（下期開始）
  10月: 105%
  11月: 115%（年末商戦前）
  12月: 105%（年末は後半低下）
  ※ 100% = 年間予算 / 12

業界固有の調整:
  不動産: 1-3月に+30%（引越しシーズン）
  EC: 11月に+50%（ブラックフライデー/サイバーマンデー）
  B2B: 3月・9月に+20%（期末需要）
  教育: 2-4月に+30%（入学/新学期シーズン）
```

## 入札最適化戦略

### 入札戦略選択ガイド
キャンペーン目的・データ量・成熟度に応じて最適な入札戦略を選択する。

```
入札戦略の選択フロー:

Q1: コンバージョンデータは月30件以上あるか？
  Yes → Q2 へ
  No  → 手動CPC or クリック数最大化（データ蓄積フェーズ）

Q2: 目標CPA/ROASは明確か？
  Yes → Q3 へ
  No  → コンバージョン数最大化（学習フェーズ）

Q3: 目標はコスト効率か売上最大化か？
  コスト効率 → 目標CPA入札
  売上最大化 → 目標ROAS入札
```

| 入札戦略 | 推奨条件 | 注意点 |
|---------|---------|--------|
| **手動CPC** | 新規キャンペーン、データ不足時 | 運用工数が高い。初期の学習用 |
| **拡張CPC** | 手動からの移行初期 | CPCの上限を30%程度まで自動調整 |
| **クリック数最大化** | トラフィック獲得が目的 | CVR改善と併用しないとCPA悪化 |
| **目標CPA** | CV月30件以上、CPA目標明確 | 目標CPAは現状の+20%以内で設定 |
| **目標ROAS** | CV月50件以上、商品価格にばらつき | 目標ROASは現状の-20%以内で設定 |
| **コンバージョン数最大化** | 予算消化を優先、学習期間 | CPA上限なしのため予算超過注意 |
| **コンバージョン値最大化** | ECサイト、商品価格差が大きい | ROAS制約なしで売上最大化 |

### 入札調整の判断基準
```
デバイス別調整:
  - モバイルCVR > デスクトップCVR × 1.2 → モバイル入札+20%
  - モバイルCVR < デスクトップCVR × 0.8 → モバイル入札-20%

地域別調整:
  - エリア別CPA分析（月次）
  - CPA目標の120%超のエリア → 入札-10~30%
  - CPA目標の80%未満のエリア → 入札+10~30%

時間帯別調整:
  - 曜日×時間帯のCVRヒートマップを作成
  - CVRが平均の150%以上の時間帯 → 入札+20%
  - CVRが平均の50%以下の時間帯 → 入札-30~50%

オーディエンス別調整:
  - リマーケティング → 入札+30~50%（CVRが高い前提）
  - 類似オーディエンス → 入札+10~20%
  - 広域ターゲティング → 入札変更なし（ベースライン）
```

### スマートビディング・ウォームアッププロトコル
```
自動入札への移行手順:

Phase 1（データ蓄積）— 2-4週間:
  - 手動CPC or 拡張CPCで運用
  - コンバージョントラッキングの正確性を検証
  - 月30件以上のコンバージョンデータを蓄積

Phase 2（移行準備）— 1週間:
  - 現状のCPA/ROASのベースラインを算出
  - 目標値を現状の±20%以内で設定
  - 予算の急激な変更を避ける

Phase 3（学習期間）— 2-4週間:
  - スマートビディングに切り替え
  - 学習期間中は設定変更を最小限に
  - 日次でパフォーマンスを監視（ただし即座の判断は避ける）
  - 7日以上連続でCPAが目標の150%超 → アラート

Phase 4（最適化）— 継続:
  - 目標値の微調整（2週間ごとに±10%以内）
  - オーディエンスシグナルの追加・除外
  - クリエイティブの更新による学習リセットに注意
```

```
  テスト方法: Level 1 の勝者コンセプトをベースにコピー変更
  判定期間: 7日
  必要サンプル: 広告セットあたり50CV以上

Level 3 — ビジュアルテスト:
  テスト対象: 画像/動画のバリエーション（色・構図・人物有無）
  テスト方法: Level 2 の勝者コピーをベースにビジュアル変更

Level 4 — CTAテスト:
  テスト対象: CTAボタン文言・色・配置
  テスト方法: 勝者クリエイティブのCTAのみ変更

  必要サンプル: 広告セットあたり30CV以上
```

### 統計的有意性判定
```
A/Bテストの勝者判定基準:

信頼度: 95%以上（p値 < 0.05）を必須とする

簡易判定ルール:
  - 各バリエーションのCV数が30件以上
  - CVR差が相対値で10%以上
  - 3日以上連続で同じバリエーションが優勢

早期終了条件:
  - 片方のCVRが他方の2倍以上 + サンプル各50件以上 → 早期勝者宣言
  - 7日経過でCVR差が5%未満 → 引き分け（他の指標で判定）

注意事項:
  - 曜日効果を考慮し、最低7日間はテスト実施
  - 祝日・セール期間中のテスト結果は参考値として扱う
  - 複数指標が矛盾する場合: CPA > CVR > CTR の優先順位で判定
```

### ビュースルー vs クリックスルー アトリビューション
```
アトリビューション設定の推奨:

| プラットフォーム | クリックスルー | ビュースルー | 備考 |
|---------------|-------------|-------------|------|
| Google Ads | 30日 | 1日 | 検索は30日、ディスプレイは7日推奨 |
| Meta Ads | 7日 | 1日 | iOS14.5以降はデフォルト7日/1日 |
| TikTok Ads | 7日 | 1日 | 動画の影響を考慮しVT1日を含める |
| YouTube Ads | 30日 | — | エンゲージドビュー（10秒以上視聴）を活用 |

注意:
  - ビュースルーは過大評価のリスクがある → レポートで分離表示
  - クリックスルーのみで評価すると上位ファネルの貢献が見えない
  - 社内レポートではクリックスルーを主指標、ビュースルーを参考指標
```

### クロスプラットフォームアトリビューションの課題と対策
```
課題:
  1. 各プラットフォームが自社のCVを主張する（重複カウント）
  2. iOS/プライバシー規制によるトラッキング精度の低下
  3. クロスデバイス計測の不確実性

対策:
  1. UTMパラメータの統一管理:
     - utm_source: プラットフォーム名
     - utm_medium: 広告種別
     - utm_campaign: キャンペーン名
     - utm_content: クリエイティブID
     - utm_term: キーワード（検索広告）

  2. ラストクリックベースの統合レポート:
     - Google Analytics を統合計測の基盤として使用
     - 各プラットフォームのCV数 vs GAのCV数を比較
     - 乖離率を記録し、プラットフォーム別の補正係数を算出

  3. MMM（マーケティング・ミックス・モデリング）の活用:
     - 四半期ごとにチャネル別の貢献度を統計的に推定
     - Data Analyst と連携して回帰分析を実施
```

### インクリメンタリティテスト設計

```
Conversion Lift テスト:

     - テスト群: 広告を配信
     - コントロール群: 広告を非配信（またはPSA広告を配信）

ホールドアウト実験:
```

## 予算最適化アルゴリズム

### 限界CPA分析
```
各キャンペーンの予算を1万円増やした場合の追加CPA変化を分析:

限界CPA = 追加予算 ÷ 追加コンバージョン数

最適化ルール:
  - 限界CPA < 目標CPA → 予算増額
  - 限界CPA = 目標CPA → 現状維持
  - 限界CPA > 目標CPA → 予算削減
  - 限界CPA > 目標CPA × 1.5 → 即時停止検討

予算再配分の手順:
  1. 全キャンペーンの限界CPAを算出
  2. 限界CPAが低い順にランキング
  3. 限界CPA目標超のキャンペーンから予算を回収
  4. 限界CPA目標内のキャンペーンに再配分
  5. 週次で再評価
```

### 予算ペーシング戦略
```
月間予算を効率的に消化するための日次配分:

均等ペーシング（デフォルト）:
  日次予算 = 月間予算 ÷ 残日数
  
フロントローディング（月前半重視）:
  月前半: 日次予算 × 1.2
  月後半: 日次予算 × 0.8
  用途: 月末に予算不足でCV機会を逃すリスクを回避

バックローディング（月後半重視）:
  月前半: 日次予算 × 0.8
  月後半: 日次予算 × 1.2
  用途: 月末のセール・キャンペーンに合わせた配分

イベント連動:
  - セール期間: 日次予算 × 2.0
  - 祝日/長期休暇: 日次予算 × 0.5
  - 業界イベント前後: 日次予算 × 1.5

ペーシング監視:
  - 月初5日時点で消化率が予定の80%未満 → アラート
  - 月中で消化率が予定の120%超 → 入札/予算制限を検討
```

### デイパーティング最適化
```
時間帯別の広告配信最適化:

分析手順:
  1. 曜日×時間帯（168セル）のCVR/CPAマトリクスを作成
  2. 全体平均CPAとの差分を算出
  3. 以下のルールで入札調整を設定

高パフォーマンス時間帯（CPA < 平均の80%）:
  → 入札 +10~30%
  → 予算を優先配分

平均パフォーマンス時間帯（CPA 80-120%）:
  → 入札調整なし

低パフォーマンス時間帯（CPA > 平均の120%）:
  → 入札 -10~30%

極低パフォーマンス時間帯（CPA > 平均の200%）:
  → 配信停止

注意:
  - 十分なデータ量がある時間帯のみ調整（CV5件以上/セル）
  - 月次で再分析（季節変動・トレンド変化に対応）
  - B2B案件は平日日中に集中配信が基本
```

### 季節予算調整方法論
```
年間の季節性を考慮した予算計画:

予算調整カレンダー:
  1月: 基準の80%（年始は反応率低下）
  2-3月: 基準の100%（年度末需要）
  4月: 基準の120%（新年度予算）
  5月: 基準の90%（GW影響）
  6-7月: 基準の100%
  8月: 基準の80%（お盆影響）
  9月: 基準の110%（下期予算）
```
