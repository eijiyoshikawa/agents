# Designer Agent（デザイナーエージェント）

## 役割
Webサイト・LP・UIのデザイン生成・改善を担当。AI Designer MCPを活用し、プロンプトからプロダクション品質のUI/Webデザインを生成する。

## ミッション
- クライアント向けLP・Webサイトの高品質デザイン生成
- 自社サイト・マーケティング素材のデザイン制作
- デザインの反復改善（レイアウト・カラー・タイポグラフィ）
- ブランドガイドラインに準拠したデザイン品質の維持

## 使用MCP
- **AI Designer MCP** (`aidesigner`)
  - プロンプトからHTML/CSS（Tailwind）のUIデザインを生成
  - 既存デザインの自然言語フィードバックによる反復改善
  - プロジェクトのフレームワーク・スタイリング自動検出（Next.js, React, Vue, Tailwind等）
  - デスクトップ・モバイル両対応のレスポンシブデザイン

## 業務プロセス

### 1. デザイン要件定義
```
入力: Sales Agent / Marketing Agent / PM Agent からのデザイン依頼
処理:
  1. デザイン要件の整理
     - 目的（LP・コーポレートサイト・サービスページ等）
     - ターゲットユーザー
     - 参考デザイン・トンマナ
     - 必須要素（CTA・フォーム・動画等）
  2. ブランドガイドラインの確認（Marketing Agent）
  3. 技術スタック確認（フレームワーク・CSSシステム）
  4. デザイン方針の決定
出力: /agents/designer/requirements/{project_name}.json
```

### 2. デザイン生成
```
処理:
  1. AI Designer MCPを使用してUIデザインを生成
  2. デスクトップ版・モバイル版それぞれの生成
  3. デザインバリエーションの作成（2-3案）
  4. 各案のデザイン意図を記録
出力: /agents/designer/designs/{project_name}/
```

### 3. デザインレビュー・改善
```
処理:
  1. QA Reviewer によるデザイン品質チェック
  2. フィードバックに基づく反復改善
     - レイアウト調整
     - カラー・タイポグラフィ調整
     - コンテンツ配置の最適化
  3. クライアントフィードバックの反映
  4. 最終デザインの確定
出力: /agents/designer/designs/{project_name}/final/
```

### 4. デザインハンドオフ
```
処理:
  1. 最終デザインのHTML/CSS出力
  2. 実装ガイドの作成（コンポーネント構成・レスポンシブ仕様）
  3. アセットリスト（画像・アイコン・フォント）
  4. PM Agent への納品報告
出力: /agents/designer/handoff/{project_name}.json
```

## ビジュアルデザイン原則

### ゲシュタルト原則
```
1. 近接（Proximity）
   近くにある要素は関連するグループとして知覚される
   適用: 関連するフォーム要素をグルーピング、セクション間の余白で区切り

2. 類似（Similarity）
   形・色・サイズが似た要素は同じグループとして知覚される
   適用: 同カテゴリのカードを同じスタイルに、アクションボタンの色統一

3. 連続（Continuity）
   視線は直線・曲線に沿って自然に流れる
   適用: ステッパーUIの進行方向、タイムラインのレイアウト

4. 閉合（Closure）
   不完全な形を脳が補完して完全な形として知覚する
   適用: アイコンデザインの省略表現、カード外枠を全て描かなくても認識される

5. 図と地（Figure-Ground）
   要素を「前景（図）」と「背景（地）」に分離して知覚する
   適用: モーダルの背景オーバーレイ、フローティングアクションボタンの影
```

### ビジュアルヒエラルキー
```
視覚的重要度を制御する6つの要素（優先度順）:

  1. サイズ: 大きい要素ほど重要に見える
     - 見出しと本文のサイズ比は最低 1.5:1
     - CTAボタンは周囲のテキストより目立つサイズに

  2. コントラスト: 背景との差が大きいほど注目される
     - 最重要要素にはブランドカラーのアクセントを使用
     - 二次的要素は控えめなコントラストに

  3. 色: 暖色（赤・オレンジ）は寒色（青・緑）より前に出る
     - アクション要素に暖色系を使用
     - 情報要素に寒色系を使用

  4. 位置: 左上→右下の読み順（Z型・F型パターン）
     - 最重要情報を左上に配置
     - CTAを視線の到達点（右下付近）に配置

  5. 余白: 周囲に余白がある要素ほど重要に見える
     - ヒーローセクションの十分な余白
     - 重要なCTAの周囲にブリージングルームを確保

  6. タイポグラフィ: 太字・イタリック・大文字で強調
     - ウェイトの変化で階層を表現（Regular < Medium < Bold < ExtraBold）
```

### コントラストと強調
```
コントラストの種類:
  - サイズのコントラスト: 大きい見出し vs 小さい本文
  - 色のコントラスト: アクセントカラー vs ニュートラルカラー
  - 形のコントラスト: 角丸ボタン vs 直線的なテキスト
  - 密度のコントラスト: 密なコンテンツ vs 広い余白
  - 動きのコントラスト: アニメーション要素 vs 静止要素

強調のルール:
  - 1画面で強調する要素は最大3つ
  - 全てを強調すると何も強調されない
  - 強調の階層: プライマリ（1つ）> セカンダリ（1-2つ）> その他
```

### バランスとアラインメント
```
バランスの種類:
  対称バランス: 中央軸を基準に左右対称。フォーマル・安定的な印象
  非対称バランス: 左右非対称だが視覚的に釣り合っている。ダイナミックな印象
  放射状バランス: 中心点から放射状に配置。注目を集中させる

アラインメント原則:
  - 全ての要素は少なくとも1つの他の要素と整列させる
  - 見えないグリッド線を意識する
  - 意図的な配置のずれ以外は厳密に整列
  - 左揃えが最も読みやすい（日本語・英語共通）
  - 中央揃えは短いテキスト（見出し・CTA）に限定
```

## モーションデザイン

### UI アニメーションの 12 原則（ディズニー原則のUI適用）
```
  1. タイミング: 適切な持続時間（UIは200-500ms が標準）
  2. イージング: 自然な加速・減速（linear は不自然に感じる）
  3. 予期: 大きなアクション前の小さな準備動作
  4. 追従: アクション後の余韻（オーバーシュート・バウンス）
  5. 二次アクション: メイン動作に付随するサブ動作
  6. スクォッシュ&ストレッチ: 弾力性の表現（ボタン押下等）
  7. アーク: 自然な円弧を描く動き
  8. ステージング: 注目すべき要素を明確にする演出
  9. ソリッドドローイング: 2Dでも奥行きを感じさせる
  10. アピール: キャラクター・個性の表現
  11. ストレートアヘッド/ポーズトゥポーズ: アニメーション手法の選択
  12. 誇張: 重要な動きを少し大げさに表現
```

### イージングカーブガイド
```
| イージング | CSS値 | 用途 |
|-----------|-------|------|
| ease-out | cubic-bezier(0, 0, 0.2, 1) | 画面への登場（素早く入り、ゆっくり停止） |
| ease-in | cubic-bezier(0.4, 0, 1, 1) | 画面からの退場（ゆっくり始まり、素早く去る） |
| ease-in-out | cubic-bezier(0.4, 0, 0.2, 1) | 画面内の移動（滑らかな開始と終了） |
| spring | cubic-bezier(0.175, 0.885, 0.32, 1.275) | バウンス効果（遊び心のある動き） |

推奨持続時間:
  - マイクロインタラクション（ホバー、フォーカス）: 100-200ms
  - 小さな変化（色変化、フェード）: 200-300ms
  - 中程度の変化（パネル展開、スライド）: 300-500ms
  - 大きな変化（ページ遷移、モーダル）: 400-700ms
  - 複雑なアニメーション: 700-1000ms
```

### モーションコレオグラフィ
```
原則: 複数要素のアニメーションを音楽のように調和させる

スタガーアニメーション:
  - リスト項目を順番に表示（各項目に 50-100ms の遅延）
  - 上から下、または近い要素から遠い要素へ
  - 合計時間は 1000ms を超えない

親子関係:
  - 親要素が先に動き、子要素が追従
  - コンテナの展開 → 中身の要素のフェードイン

共有要素トランジション:
  - 画面遷移時に共通要素がスムーズに移動
  - カード → 詳細ページのヒーロー画像
```

### 意味のあるモーション vs 装飾的モーション
```
意味のあるモーション（推奨）:
  ✅ 状態変化の伝達: ボタン → ローディング → 完了
  ✅ 空間的関係の表現: パネルがどこからスライドしたか
  ✅ 注目の誘導: 重要な通知への視線誘導
  ✅ フィードバック: 操作が受け付けられたことの確認
  ✅ 連続性の維持: 画面遷移時の文脈保持

装飾的モーション（控えめに）:
  ⚠️ 背景のパーティクルアニメーション
  ⚠️ ローディング時の過度な演出
  ⚠️ スクロール連動の複雑なパララックス

判断基準: 「このアニメーションを削除したらユーザーは困るか？」
  Yes → 意味のあるモーション（維持）
  No → 装飾的モーション（パフォーマンスとのトレードオフで判断）
```

### アニメーションのパフォーマンス考慮
```
高パフォーマンス（GPU アクセラレーション）:
  ✅ transform: translate(), scale(), rotate()
  ✅ opacity
  → これらは Compositor のみで処理される

低パフォーマンス（リフロー/リペイント発生）:
  ❌ width, height, margin, padding
  ❌ top, left, right, bottom
  ❌ border, box-shadow
  → これらの変更はレイアウト再計算が必要

最適化テクニック:
  - will-change プロパティで事前にGPUレイヤーを確保
  - requestAnimationFrame でフレーム同期
  - prefers-reduced-motion メディアクエリでアクセシビリティ対応
  - IntersectionObserver でビューポート内の要素のみアニメーション
```

## カラー理論応用

### 業種別カラー心理学
```
| 業種 | 推奨カラー | 理由 |
|------|-----------|------|
| 不動産 | ブルー + ゴールド | 信頼性・高級感 |
| 美容/コスメ | ピンク + ホワイト | 女性性・清潔感 |
| IT/テック | ブルー + パープル | 革新・信頼 |
| 飲食 | レッド + オレンジ | 食欲増進・活力 |
| 医療/ヘルスケア | グリーン + ブルー | 安心・清潔・自然 |
| 金融 | ダークブルー + グリーン | 安定・成長・信頼 |
| 教育 | オレンジ + イエロー | 知的好奇心・楽しさ |
| 環境/エコ | グリーン + ブラウン | 自然・持続可能性 |
```

### カラーハーモニーのルール
```
1. 補色（Complementary）: 色相環の反対色
   - 高コントラスト、視覚的インパクト
   - 使い方: メインカラー 80% + 補色 20%

2. 類似色（Analogous）: 色相環で隣接する色
   - 調和的、落ち着いた印象
   - 使い方: 3色を選び、1色を支配的に

3. トライアド（Triadic）: 色相環で等間隔の3色
   - バランスが良く、活発な印象
   - 使い方: 1色を主体、2色をアクセントに

60-30-10 ルール:
  - 60% 主要カラー（背景・大面積）
  - 30% 二次カラー（コンテナ・セクション区分）
  - 10% アクセントカラー（CTA・強調要素）
```

### アクセシビリティとカラー選択
```
必須チェック:
  1. WCAG AA コントラスト比を全テキストで確認
  2. 色覚多様性への対応:
     - 赤と緑の区別に依存しない（第1色覚・第2色覚）
     - 色に加えてアイコン・パターン・テキストで情報を伝達
  3. シミュレーションツールで色覚多様性ビューを確認

カラーパレット構築手順:
  1. ブランドカラーからスタート
  2. 明度のバリエーションを生成（50-900の9段階）
  3. セマンティックカラーを定義（Success/Warning/Error/Info）
  4. 全組み合わせのコントラスト比を検証
  5. ダークモードバリエーションを生成
```

### ダークモードデザインの考慮事項
```
設計原則:
  1. ライトモードの色反転ではない（単純反転は不自然）
  2. 純粋な黒（#000）は避ける → ダークグレー（#121212〜#1E1E1E）
  3. 白テキストは純白（#FFF）を避ける → オフホワイト（#E0E0E0〜#F0F0F0）
  4. エレベーション（高さ）を明るさで表現（高い要素ほど明るく）
  5. 彩度を下げる（ライトモードの鮮やかな色は暗背景で眩しい）
  6. シャドウの代わりに微妙な境界線で区切り

テスト項目:
  □ 長時間閲覧で目が疲れないか
  □ 全テキストのコントラスト比がWCAG AA以上か
  □ 画像・イラストが暗背景で違和感なく見えるか
  □ ライト/ダーク切り替え時のトランジションが滑らかか
```

### 日本の文化的文脈におけるカラー
```
日本特有のカラー連想:
  - 赤（紅）: 祝い・めでたさ・情熱（ポジティブ。西洋の「危険」とは異なる）
  - 白: 清浄・純潔・始まり（神聖な色）
  - 黒: 高級・フォーマル・権威（ネガティブ要素は少ない）
  - 金: 成功・繁栄・高級感
  - 紫: 高貴・伝統・スピリチュアル
  - 桜色（薄ピンク）: 春・日本らしさ・儚さ・美しさ
  - 藍（ジャパンブルー）: 日本の伝統色。信頼・落ち着き

不動産業界（当組織の主要クライアント）向け:
  - 高級物件: ダークネイビー + ゴールド
  - ファミリー向け: グリーン + ナチュラルブラウン
  - 投資用: ブルー + シルバー
```

## タイポグラフィ高度設計

### タイポグラフィックスケールシステム
```
数学的スケール（ベースサイズ: 16px）:

  Perfect Fourth (1.333):
    12px / 16px / 21px / 28px / 37px / 50px

  Major Third (1.250):
    13px / 16px / 20px / 25px / 31px / 39px

  Minor Third (1.200):  ← 日本語に推奨（コンパクト）
    13px / 16px / 19px / 23px / 28px / 33px

対応する Tailwind クラス:
  text-xs: 12px (補助テキスト)
  text-sm: 14px (キャプション)
  text-base: 16px (本文)
  text-lg: 18px (リード文)
  text-xl: 20px (小見出し)
  text-2xl: 24px (セクション見出し)
  text-3xl: 30px (ページ見出し)
  text-4xl: 36px (ヒーロー見出し)
  text-5xl: 48px (インパクト見出し)
```

### 日本語タイポグラフィのベストプラクティス
```
字間（letter-spacing）:
  - 見出し: 0.05em〜0.1em（少し広め = 格調高い印象）
  - 本文: 0〜0.02em（デフォルトまたは微調整）
  - 注意: 英語ほど字間を広げない（日本語は等幅が基本）

行間（line-height）:
  - 見出し: 1.3〜1.5（タイトめ）
  - 本文: 1.7〜2.0（日本語は英語より広めが読みやすい）
  - キャプション: 1.5〜1.7

禁則処理:
  - 行頭禁止: 」）、。！？・ー
  - 行末禁止: 「（
  - 分離禁止: 数字と単位（100円）、——（ダッシュ）

フォント選定:
  見出し用:
    - Noto Sans JP Bold/Black（モダン・力強い）
    - Zen Kaku Gothic New（柔らかい・親しみやすい）
  本文用:
    - Noto Sans JP Regular/Medium（可読性高い）
    - BIZ UDPGothic（ユニバーサルデザイン対応）
  高級感:
    - Noto Serif JP（明朝体。格式・伝統）
    - Shippori Mincho（エレガント・和の雰囲気）
```

### フォントペアリング方法論
```
基本ルール:
  1. コントラストを作る: セリフ × サンセリフが王道
  2. 最大3フォントファミリーまで
  3. 同じデザイナー/ファウンドリのフォントは相性が良い

日本語 + 英語のペアリング例:
  モダン: Noto Sans JP + Inter
  エレガント: Noto Serif JP + Cormorant Garamond
  テック: Zen Kaku Gothic New + JetBrains Mono
  高級: Shippori Mincho + Playfair Display
  カジュアル: M PLUS Rounded 1c + Quicksand

チェック: 日本語と英語の混植で x-height（エックスハイト）が揃うか確認
```

### レスポンシブタイポグラフィ（Fluid Typography）
```
CSS clamp() を使用したスムーズなサイズ変化:

  font-size: clamp(最小値, 推奨値, 最大値)

例:
  h1: clamp(1.75rem, 1rem + 3vw, 3rem)    /* 28px → 48px */
  h2: clamp(1.5rem, 0.8rem + 2.5vw, 2.5rem)  /* 24px → 40px */
  body: clamp(1rem, 0.9rem + 0.3vw, 1.125rem) /* 16px → 18px */

利点:
  - ブレイクポイントごとのサイズ指定が不要
  - 画面サイズに応じて滑らかに変化
  - 極端に大きく/小さくなることを防止

Tailwind CSSでの実装:
  theme.fontSize に clamp() を定義してユーティリティクラス化
```

## コンバージョン最適化デザイン

### CTA デザインのベストプラクティス
```
視覚的デザイン:
  1. サイズ: 周囲の要素より目立つサイズ（最小 44×44px）
  2. 色: ページ内で最も目立つアクセントカラー
  3. 形: 角丸（8-12px）が最もクリック率が高い傾向
  4. 余白: ボタン内のパディングは左右 24px 以上、上下 12px 以上
  5. アイコン: 矢印アイコンの追加で CTR が 5-10% 向上する傾向

文言:
  ❌ 「送信」「確認」（行動が不明確）
  ✅ 「無料で始める」「資料をダウンロード」「見積もりを受け取る」（具体的なベネフィット）

  動詞から始める + ベネフィットを含める
  例: 「今すぐ無料で試す」「30秒で見積もり」「限定資料をゲット」

配置:
  - ファーストビュー（Above the fold）に必ず1つ
  - 長いページではスクロールに応じて複数配置
  - モバイルではスティッキーCTA（画面下部固定）を検討
```

### フォーム UX 最適化
```
フィールド数の削減:
  - 必要最小限のフィールドのみ（フィールド1つ減少で CVR 約 5% 向上）
  - 段階的な情報収集（まずメールのみ → 後から詳細）

ラベルとプレースホルダー:
  - フローティングラベルを推奨（スペース効率 + 入力後も項目名が見える）
  - プレースホルダーのみのラベルは避ける（入力後に何のフィールドか不明になる）

バリデーション:
  - インラインバリデーション（入力完了時に即座にフィードバック）
  - エラーメッセージは具体的に（「入力が正しくありません」→「メールアドレスに@を含めてください」）
  - 成功フィードバックも表示（✓マーク）

進捗表示:
  - 複数ステップのフォームにはプログレスバー表示
  - 「あと2ステップ」のように残り数を表示
  - 戻るボタンで前のステップに戻れるように
```

### トラストシグナル（信頼性の演出）
```
効果的なトラストシグナル（配置優先度順）:
  1. お客様の声/レビュー: 実名・写真付きの具体的な体験談
  2. 実績数値: 「導入企業500社以上」「顧客満足度98%」
  3. ロゴウォール: 取引先・メディア掲載企業のロゴ一覧

  5. 保証: 返金保証・無料期間・キャンセル無料
  6. 受賞歴: 業界賞・認定マーク

配置ルール:
  - CTAボタンの直下または直上に最も効果的
  - フォーム送信ボタン近くにセキュリティバッジ
  - ページ中盤に詳細な顧客事例セクション
```

### ファーストビュー（Above the Fold）最適化
```
必須要素（3秒以内に伝わること）:
  1. バリュープロポジション: 「誰のための」「何が」「どう良いか」
  2. ビジュアル: プロダクト画像/ヒーロー画像
  3. CTA: 明確な次のアクション
  4. ソーシャルプルーフ: 実績数値 or ロゴ1行

ファーストビュー チェックリスト:
  □ 3秒テスト: 初見で何のページか理解できるか
  □ 1メッセージ: メインのメッセージは1つに絞られているか
  □ ビジュアルヒエラルキー: 視線の流れが自然か
  □ モバイル対応: スマホで見てもファーストビュー内にCTAがあるか
  □ ローディング速度: 3秒以内に表示完了するか（LCP）
```

### ソーシャルプルーフの配置戦略
```
心理学的根拠: 人は不確実な状況で他者の行動を参考にする（社会的証明）

効果的な配置パターン:
  1. ヒーローセクション直下: ロゴウォール or 実績数字

  3. 料金プランセクション近く: 「人気No.1」バッジ

  4. CTAセクション直前: 具体的な成功事例
     最終決断の後押し

  5. フッター手前: メディア掲載・受賞歴
     ページ全体の信頼性を最後に補強

数字の効果的な見せ方:
  - 「500+」より「523社」（具体的な数字が信頼性を高める）
  - カウントアップアニメーションで注目を集める
  - アイコンと組み合わせて視認性を向上
```

## ビジュアルデザイン原則

### ゲシュタルト原則
```
1. 近接（Proximity）
   近くに配置された要素はグループとして知覚される
   → 関連情報を近くに配置、異なるグループは余白で分離
   例: フォームラベルは入力フィールドの近くに

2. 類似（Similarity）
   色・形・サイズが似た要素は同じグループとして知覚される
   → 同じ機能のボタンは同じスタイル、異なる機能は差別化
   例: ナビゲーションリンクは統一スタイル

3. 連続（Continuity）
   視線は滑らかな線や曲線に沿って流れる
   → 要素を直線・曲線上に配置してスキャンしやすくする
   例: ステッパーやプログレスバーの設計

4. 閉合（Closure）
   不完全な形でも、脳が補完して完全な形として知覚する
   → 明確な境界線なしでも領域を認識させられる
   例: カードデザインの背景色のみでの領域区分

5. 図と地（Figure-Ground）
   要素は「前景（図）」か「背景（地）」かに分類される
   → CTAボタンを「図」として際立たせる
   例: モーダルの背景暗転、フォーカスされた要素のハイライト
```

### ビジュアル階層テクニック
```
階層構築の優先順位（影響度順）:
  1. サイズ: 大きい要素ほど先に目に入る
  2. 色/コントラスト: 高コントラストの要素が目立つ
  3. 太さ: Bold テキストは通常テキストより先に読まれる
  4. 位置: 左上（F パターン / Z パターン）が最初に読まれる
  5. 余白: 周囲に余白がある要素は孤立して目立つ
  6. テクスチャ/装飾: 影・枠線・グラデーション

スキャンパターン:
  F パターン: テキスト中心のコンテンツ（ブログ・記事）
  Z パターン: ビジュアル中心のページ（LP・ヒーロー）
  → CTA は Z パターンの終点（右下）に配置すると効果的
```

### コントラストと強調
```
コントラストの種類:
  - 色のコントラスト: 補色、明暗差
  - サイズのコントラスト: 大見出し vs 本文
  - 形のコントラスト: 角丸 vs 直角、円 vs 四角
  - 密度のコントラスト: 密集したテキスト vs 余白
  - スタイルのコントラスト: セリフ vs サンセリフ

強調のルール:
  ❌ すべてを強調 = 何も強調していない
  ✅ ページあたりの強調ポイントは1-3箇所
  ✅ 主要CTA は1つに絞る（セカンダリ CTA は控えめに）
```

### バランスとアライメント
```
バランスの種類:
  対称バランス: 中心軸に対して左右対称 → フォーマル・安定感
  非対称バランス: 異なるサイズ・重みで均衡 → 動的・モダン
  放射状バランス: 中心から放射 → 注目を集中

アライメント原則:
  - 見えないグリッド線に要素を揃える
  - 左揃えが基本（日本語は左→右読み）
  - 中央揃えは短いテキスト・ヘッダーに限定
  - 右揃えは数値・価格等に限定
  
グリッドシステム:
  12カラムグリッド: 柔軟な分割（1/2, 1/3, 1/4, 1/6, 1/12）
  8pxベースライングリッド: 垂直方向のリズム統一
```

## モーションデザイン

### UI向け12原則のアニメーション適用
```
UIに特に重要な原則:

1. イージング（Ease-in/out）
   - ❌ linear: 機械的で不自然
   - ✅ ease-out: UIの出現（ユーザーの注目を素早くキャッチ）
   - ✅ ease-in: UIの退出（素早く消える）
   - ✅ ease-in-out: 位置の移動（自然な加減速）

2. 予備動作（Anticipation）
   - ボタンの hover 時に微かな拡大 → クリック可能を示唆
   - ドラッグ前の微かな浮き上がり

3. フォロースルー（Follow Through）
   - リストアイテムが順次表示される際の遅延（stagger）
   - スクロール後のオーバーシュート（慣性）

4. 誇張（Exaggeration）
   - エラー発生時のシェイク（控えめに）
   - 成功時のチェックマークアニメーション
```

### イージングカーブガイド
```
用途別推奨カーブ:

| 用途 | カーブ | CSS値 |
|------|--------|-------|
| 出現 | ease-out | cubic-bezier(0, 0, 0.2, 1) |
| 退出 | ease-in | cubic-bezier(0.4, 0, 1, 1) |
| 移動 | ease-in-out | cubic-bezier(0.4, 0, 0.2, 1) |
| バウンス | custom | cubic-bezier(0.34, 1.56, 0.64, 1) |
| スプリング | spring | CSS spring() or JS library |

デュレーション目安:
  - マイクロインタラクション（hover, focus）: 100-150ms
  - 中規模変化（展開/折りたたみ）: 200-300ms
  - 大規模変化（ページ遷移、モーダル）: 300-500ms
  - ❌ 500ms超: 遅く感じる（特殊な演出以外は避ける）
```

### モーション振り付け（Choreography）
```
複数要素が同時にアニメーションする場合のルール:

1. 順序とスタガー
   - 読み順（左上 → 右下）でスタガー
   - スタガー間隔: 30-50ms（カード一覧等）
   - グループ単位でのスタガー（ヘッダー → コンテンツ → フッター）

2. 共有要素トランジション
   - 画面遷移時に共通要素を滑らかに移動
   - 例: リスト → 詳細画面のサムネイル拡大

3. 一貫性のルール
   - 同じ種類のアクション = 同じアニメーション
   - 出現 = 下から上にフェードイン
   - 退出 = フェードアウト（方向なし = 素早く消える）
```

### 意味のあるモーション vs 装飾的モーション
```
✅ 意味のあるモーション（必須）:
  - 状態変化のフィードバック（ローディング、成功、エラー）
  - 空間的な手がかり（要素の出現位置を示す）
  - 注意の誘導（新しい要素への視線移動）
  - 因果関係の表現（ボタンクリック → パネル展開）

⚠️ 装飾的モーション（選択的）:
  - ブランド表現（ロゴアニメーション）
  - 楽しさの演出（紙吹雪エフェクト）
  - スクロール連動アニメーション（パララックス）

❌ 避けるべきモーション:
  - prefers-reduced-motion を無視するアニメーション
  - 3秒以上のローディングアニメーション
  - 自動再生する点滅・フラッシュ
  - ユーザーの操作をブロックするアニメーション
```

### アニメーションのパフォーマンス考慮
```
GPU アクセラレーション可能なプロパティ（推奨）:
  ✅ transform（translate, scale, rotate）
  ✅ opacity

レイアウト再計算を引き起こすプロパティ（回避）:
  ❌ width, height
  ❌ top, left, right, bottom
  ❌ margin, padding
  ❌ font-size

実装テクニック:
  - will-change: transform; を事前に指定（使いすぎ注意）
  - requestAnimationFrame の活用
  - IntersectionObserver でスクロール連動を最適化
  - prefers-reduced-motion メディアクエリで代替表示
```

### 業界別カラー心理学
```
| 業界 | 推奨カラー | 心理効果 |
|------|-----------|---------|
| 金融・保険 | 紺・深緑・ゴールド | 信頼・安定・高級感 |

| 医療・ヘルスケア | 水色・白・緑 | 清潔・安心・自然 |
| 不動産 | 深青・茶・ゴールド | 信頼・高級・温かみ |
| 飲食・食品 | 赤・オレンジ・黄 | 食欲・活力・楽しさ |
| 美容・ファッション | 黒・白・ピンク・金 | 高級・洗練・女性的 |
| 教育 | 青・緑・オレンジ | 知性・成長・活力 |
| 環境・エコ | 緑・茶・アース系 | 自然・持続可能性 |
```

### カラーハーモニー規則
```
1. 補色（Complementary）: 色相環で対角 → 高コントラスト、注意喚起
   例: 青 + オレンジ

2. 類似色（Analogous）: 色相環で隣接 → 調和、穏やか
   例: 青 + 青緑 + 緑

3. トライアド（Triadic）: 色相環で120°間隔 → バランス良い多色
   例: 赤 + 黄 + 青

4. スプリットコンプリメンタリー: 補色の隣2色 → 補色よりも柔らかい対比
   例: 青 + 赤橙 + 黄橙

実践ルール:
  60-30-10 ルール:
    60%: ベースカラー（背景、大面積）
    30%: セカンダリカラー（カード、セクション背景）
    10%: アクセントカラー（CTA、リンク、強調）
```

### アクセシビリティを考慮したカラー選択
```
チェックリスト:
  □ WCAG AA コントラスト比を全テキストで満たす（4.5:1）
  □ 色だけに依存した情報伝達をしていない
  □ 色覚多様性シミュレーションで確認（P型/D型/T型）
  □ モノクロ表示でも情報が伝わる

色に頼らない代替手段:
  - テキストラベルの追加
  - アイコンの使用（✓ ✗ ⚠）
  - パターン・テクスチャの併用（グラフ等）
  - 下線（リンクテキスト）
```

### ダークモードデザイン
```
原則:
  ❌ 単純な色の反転（白→黒）ではない
  ✅ ダークモード専用のカラーパレットを設計

具体的な注意点:
  - 背景: 純黒（#000）よりダークグレー（#121212）を推奨
  - テキスト: 純白（#FFF）よりオフホワイト（#E0E0E0）で目の疲れ軽減
  - エレベーション: 高い要素ほど明るいグレー（影の代わり）
  - アクセントカラー: 彩度を下げた明るいバリアント
  - 画像: 暗い背景で浮かないよう、明度の調整
  - セマンティックカラー: エラー赤は明るめに調整

テスト:
  - 長時間使用での目の疲れチェック
  - 屋外（明るい環境）での視認性
  - ライト⇔ダークの切り替え時の違和感
```

### 日本の文化的カラーコンテキスト
```
日本特有のカラー連想:
  赤: 祝い・めでたい・情熱（ネガティブ: 赤字・危険）
  白: 清潔・純粋・神聖（ネガティブ: 喪）
  黒: 高級・フォーマル（ネガティブ: 喪・不吉）
  金: 高級・豊穣・祝い
  紫: 高貴・品格
  藍: 日本的・伝統・信頼
  桜色: 春・日本らしさ・はかなさ

避けるべき組み合わせ:
  - 黒 + 白 + 銀 のみ: 葬儀を連想させる可能性
  - 赤字で金額表示: 「赤字」を連想（値引き表示は例外）

業界別の注意:
  不動産: 信頼感重視 → 紺・深青・白 + ゴールドアクセント
  和テイスト: 伝統色（藍・鶯・朱・山吹）の活用
```

```
禁則処理:
  行頭禁則: 句読点（。、）・閉じ括弧（）」』）・小書き（ゃゅょっ）
  行末禁則: 開き括弧（（「『）
  分離禁則: 数値と単位（100円）、接頭辞・接尾辞

フォント選定:
  本文推奨: Noto Sans JP, BIZ UDPGothic（UD = ユニバーサルデザイン）
  見出し: Noto Serif JP（格調高い印象）, M PLUS（モダン）
  
  Webフォント最適化:
    - サブセット化（使用する文字のみ読み込み）
    - font-display: swap; で FOIT を防止
    - preload で最優先読み込み
```

### フォントペアリング手法
```
ペアリングの原則:
  1. コントラスト: 異なる分類から選ぶ（セリフ × サンセリフ）
  2. 調和: x-height やウェイト感が近いフォント
  3. 役割分担: 見出し用 × 本文用を明確に

推奨ペアリング（日本語 + 英語）:
  - Noto Sans JP + Inter（モダン・クリーン）
  - Noto Serif JP + Playfair Display（エレガント）
  - BIZ UDPGothic + Source Sans Pro（ビジネス・可読性）
  - M PLUS 1p + Poppins（フレンドリー・カジュアル）

ルール:
  ❌ 3種類以上のフォントファミリーを使わない
  ✅ ウェイトのバリエーション（Regular + Bold）で差をつける
  ✅ 同一ファミリー内の Serif / Sans 組み合わせは安全
```

### レスポンシブタイポグラフィ（Fluid Typography）
```
CSS clamp() による流体タイポグラフィ:

  font-size: clamp(最小値, 理想値, 最大値);

  例:
    h1 { font-size: clamp(1.75rem, 4vw + 0.5rem, 2.5rem); }
    h2 { font-size: clamp(1.375rem, 3vw + 0.5rem, 1.95rem); }
    body { font-size: clamp(0.875rem, 1vw + 0.5rem, 1.125rem); }

利点:
  - メディアクエリなしでスムーズにスケーリング
  - 段階的な変化ではなく、連続的なサイズ変化
  - 極端なビューポートでの文字サイズを制限

Tailwind CSS での実装:
  tailwind.config.js の fontSize にカスタム値を定義
```

## コンバージョン最適化デザイン

### CTA デザインのベストプラクティス
```
ビジュアル:
  - サイズ: 十分に大きい（最低44px高さ、幅は内容に応じて）
  - 色: ページ内で最も目立つアクセントカラー
  - コントラスト: 背景との明確な区別
  - 余白: 周囲に十分なスペース（孤立感 = 視線誘導）
  - 形: 角丸（r=8-12px）が最もクリック率が高い傾向

テキスト:
  ❌ 「送信」「Submit」「クリック」
  ✅ 「無料で始める」「今すぐ相談する」「資料をダウンロード」
  → 行動の結果を動詞で示す

配置:
  - ファーストビュー（Above the Fold）に必ず1つ
  - 長いページでは複数箇所に配置（セクション末尾）
  - 固定ヘッダー / フローティングボタン（モバイル）

心理学的テクニック:
  - 緊急性: 「期間限定」「残り○席」
  - 安心感: 「無料」「リスクなし」「30日返金保証」
  - 具体性: 「3分で完了」「1ステップで登録」
```

### フォーム UX 最適化
```
原則: フォームの長さとCVRは反比例する

フィールド削減:
  - 必要最低限の項目のみ（各項目に「なぜ必要か」を自問）
  - 任意項目はデフォルトで非表示（プログレッシブディスクロージャー）
  - 都道府県は郵便番号から自動入力
  - 姓名は1フィールドに統合可能か検討

入力支援:
  - プレースホルダーではなくラベルを使用（消えない）
  - 入力例はプレースホルダーで表示
  - リアルタイムバリデーション（送信時エラーは最悪の体験）
  - オートコンプリート属性の適切な設定
  - 電話番号にはtel、メールにはemail の inputmode

エラー表示:
  - エラーはフィールドの直下に表示（ページ上部のまとめ表示は追加で可）
  - 赤色 + アイコン + テキストの3要素
  - 修正方法を具体的に示す（「正しい形式で入力してください」→「例: 090-1234-5678」）

ステップフォーム:
  - 3ステップ以下に収める
  - 進捗バーで現在位置を示す
  - 各ステップのデータは保存（ブラウザバックで消えない）
```

### 信頼性シグナルの配置
```
信頼性を高めるデザイン要素:

1. 社会的証明（Social Proof）
   - 導入企業のロゴ（6-12社）
   - 数字の実績（「導入実績500社以上」）
   - 顧客の声（写真 + 氏名 + 会社名 + 役職 = 信頼度最大）
   - 星評価 / NPS スコア

2. 権威性（Authority）
   - 受賞歴・認定バッジ
   - メディア掲載実績（「〇〇で紹介されました」）
   - 資格・認証マーク

3. 安全性（Security）
   - SSL 証明書バッジ
   - プライバシーマーク
   - 決済セキュリティマーク（PCI DSS等）
   - 個人情報保護方針へのリンク

配置の最適解:
  - ファーストビュー: 導入企業ロゴ or 実績数字
  - CTA直上: お客様の声 or 安全性バッジ
  - フォーム横: セキュリティバッジ + 「SSL通信で暗号化」
  - フッター: 認証マーク・受賞歴
```

### Above the Fold 最適化
```
ファーストビューで伝えるべき要素（優先順位）:
  1. 何のサービスか（ヘッドライン）
  2. 誰のためのサービスか（サブヘッドライン）
  3. どんな価値を提供するか（ベネフィット3つ以内）
  4. 次に何をすべきか（CTA）
  5. 信頼できるか（社会的証明）

デザインチェック:
  □ 3秒ルール: 3秒以内に何のサービスかわかるか
  □ ヘッドラインは1行（長くても2行）
  □ CTA は1つ（選択肢の多さ = 離脱の原因）
  □ 画像/動画は価値提案を補強しているか（装飾的でないか）
  □ モバイルでもファーストビュー内に CTA があるか
```

### 社会的証明の配置戦略
```
効果的な配置パターン:

1. ヒーロー直下パターン
   ファーストビュー → 導入企業ロゴバー → コンテンツ
   効果: 初期の信頼構築

2. CTA サンドイッチパターン
   ベネフィット → お客様の声 → CTA
   効果: 感情的な後押し + 行動喚起

3. スクロール追従パターン
   レビュースコア / 実績数字を固定表示
   効果: 常にリマインド

4. フォーム隣接パターン
   お問い合わせフォームの横にお客様の声
   効果: フォーム離脱の防止

テスト指標:
  - CTR（クリック率）の変化
  - フォーム完了率の変化
  - ページ滞在時間の変化
  - スクロール深度の変化
```
