# SNS分析レポート 自動生成パイプライン実行手順書

## 概要
クライアントのSNS（TikTok等）運用実績スクショから、テンプレ『【テンプレ】分析レポート』(Google Slides 15枚) を複製し、数値・表・グラフ画像を流し込んで月次レポートを自動生成する専用パイプライン。**手動指示トリガー**で起動し、生成後に Notion の一覧へ追記する。

## 設計の前提（重要）
- **Google スライドの中身は MCP では編集できない**（複製・読取・新規作成は可、プレースホルダ差し替え/画像挿入は不可）。
  → 描画は **Google Apps Script レンダラ**（`/scripts/report-generator/Code.gs`）が担う。
- **数値抽出は Claude が担当**。スクショは OCR テキスト層（`read_file_content`）と画像ビジョン（`download_file_content`→画像読取）を**二重照合**して精度を担保する。
- 責務分離: **抽出(Claude) / 描画(Apps Script) / 一覧管理(Notion)**。
- データ受け渡しは `report_data.json`（契約: `/scripts/report-generator/schema/report_data.schema.json`）の一本に集約。

## フォルダ構造の前提
```
（クライアント名フォルダ）例: REVECAREERAGENCY
  └── （月次フォルダ）例: 2026年06提出分   ← これが増える単位＝1レポート
        ├── アカウント概要.png
        ├── 概要_7日間 / _28日間 / _60日間 / _365日間.png
        ├── オーディエンス_7日間 / _28日間 / _60日間 / _365日間.png
        ├── 投稿別インサイト/  （投稿01〜N本目.png）
        ├── report_data.json   ← Claudeが生成（Step2成果物）
        └── {client}_{月}_分析レポート（複製スライド） ← Step4成果物
```

## 前提条件
- Claude Code（Max プラン）で実行
- MCP: **Google Drive**（複製・読取・データ書込）/ **Notion**（一覧追記）が接続済み
- Apps Script レンダラがデプロイ済みで `TEMPLATE_ID` に**トークン化マスターテンプレ**のIDが設定済み（ワンタイム設定。README参照）

## 実行手順

### Step 0: COO による対象確定
- 対象の月次フォルダID、クライアント、プラットフォーム（TikTok/IG/YT）を確認
- 既存レポートの重複が無いかチェック

### Step 1: 画像の棚卸し（Data Analyst）
- `search_files (parentId = '<folderId>')` でフォルダ直下と `投稿別インサイト/` を列挙
- ファイル名規則で役割を分類（`概要_*`=アカウント分析、`オーディエンス_*`=属性、`投稿NN本目`=伸びた投稿）

### Step 2: 数値抽出 → report_data.json（Data Analyst + Report Builder）
**出力:** 対象フォルダ内 `report_data.json`（MCPの `create_file` で書込）
1. 各画像を `read_file_content`（OCRテキスト層）で取得
2. 主要指標画像は `download_file_content`→PNG保存→画像読取（ビジョン）で**桁を再確認**
3. `schema/report_data.schema.json` に従い構造化。**不明値は空文字 `""`、推定値は入れない**
4. `summary` / `next_actions` は数値傾向から下書きし、人レビュー前提でマーキング

**完了条件:** `meta` / `account_analytics` が埋まり、`dashboard_images` にファイルIDが入っている
**[QA Check 1]** 前月比の符号、桁区切り、リーチ/視聴者リーチ/プロフィール閲覧の取り違えが無いか

### Step 3: Devil's Advocate（異常値検証・推奨）
- 前月比が桁外れ（>±999%等のダッシュボード表記）をそのまま転記していないか
- フォロワー純増 = 新規 − 減少 の整合
- 投稿別の突出値（バズ投稿）の取り違えが無いか

### Step 4: Apps Script レンダラ実行（描画）
**実行:** `generateReportForFolder('<folderId>')`（メニュー or 直接実行）
1. フォルダ内 `report_data.json` を読込
2. `TEMPLATE_ID`（トークン化マスター）を複製し `{client}_{月}_分析レポート` と命名・同フォルダ配置
3. `{{TOKEN}}` を実値へ一括置換
4. slide8/9 に表を生成、slide6 にグラフ画像、slide10-12 に投稿画像を挿入
5. 生成スライドURLを返す

**完了条件:** 複製スライドが生成され、URLが取得できる
**[QA Check 2]** 主要トークンの未置換（`{{...}}` 残り）が無いか

### Step 5: QA Reviewer（生成物の目視整合）
- 数値・空欄・画像のはみ出し/位置をチェック。差し戻し時は Step2 の `report_data.json` を修正して再実行（冪等）

### Step 6: Notion 一覧へ追記
- 一覧DB（**新規作成 or 既存ハブ配下：方針確定後**）に1行追記
  - 推奨プロパティ: クライアント / 対象月 / レポートリンク / データ取得期間 / ステータス / 作成日

## 実行トリガー
| トリガー | 実行主体 | 契機 |
|---|---|---|
| 手動指示（既定） | 運用担当 | 「REVECAREERAGENCYの2026年6月提出分でレポート生成して」 |
| （将来）定期ポーリング | GitHub Actions / Apps Script トリガー | 親フォルダを走査し新規月次フォルダを検知 |

## エラー時の対応
| 問題 | 対応 |
|------|------|
| スクショOCRの桁が読めない | Step2でビジョン再読取。なお不明なら空文字のまま残し、人手補完を促す |
| 月次集計スクショが無い（slide8用） | `post_analysis_monthly` を空にし、当月は当該表を非表示 or 手入力 |
| テンプレのトークン未置換が残る | マスターテンプレのトークン名と `buildTokenMap_` の対応を確認 |
| 前月フォロワーが不明（followers_start） | 過去レポート/前月概要から補完。無ければ空 |
| 画像が枠からはみ出す | `fitWithin_` の対象枠サイズをテンプレ側で調整 |

## 学習ループ
- 抽出ミスのパターンを `/learnings/sessions/{date}_report_{client}.json` に記録
- 頻出する読み取り誤り（例: 視聴者リーチとリーチの取り違え）は本手順書の[QA Check 1]に追記
