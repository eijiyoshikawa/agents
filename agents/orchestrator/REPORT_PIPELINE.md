# SNS分析レポート 自動生成パイプライン実行手順書

## 概要
クライアントのSNS（TikTok等）運用実績スクショから、月次分析レポートを自動生成する専用パイプライン。**手動指示トリガー**で起動する。
**主成果物は Notion**：DB「📊 SNS分析レポート一覧」に1行＝1レポートを生成し、各ページ本体がレポート（指標表・伸びた投稿表・ダッシュボードリンク）を兼ねる。Claude が MCP だけで端から端まで完結できる最短経路。

## 採用方針（2026-06-07 確定）
- **主軸 = Notion**。一覧DBと各レポート本体を同一成果物で兼ねる。`report_data.json` を中間契約として保持し、後付けでSlides出力も可能（付録A）。
- 既存DB:
  - 一覧: `📊 SNS分析レポート一覧` / data_source_id `7c23288c-fabf-4b60-aa1b-7f1494f2da79`（親: 株式会社LET公式Notion）

## 設計の前提（重要）
- **数値抽出は Claude が担当**。スクショは OCR テキスト層（`read_file_content`）と画像ビジョン（`download_file_content`→画像読取）を**二重照合**して精度を担保する。**不明値は空欄、推定値は入れない**。
- 責務分離: **抽出+構造化(Claude) / レポート生成+一覧追記(Claude/Notion MCP)**。
- データ受け渡しは `report_data.json`（契約: `/scripts/report-generator/schema/report_data.schema.json`）の一本に集約。
- **画像方針**: クライアント機微データのため Drive 画像は公開化せず、Notion には**リンク**で掲載する（インライン埋め込みが必要な場合のみ、別途ホスティングを検討）。
- Google スライド出力（付録A）は MCP では中身編集不可のため Apps Script が必要。必要時のみ後付けする。

## 実行手順

### Step 0: COO による対象確定
- 対象の月次フォルダID、クライアント、プラットフォーム（TikTok/IG/YT）を確認
- 既存レポートの重複が無いかチェック

### Step 1: 画像の棚卸し（Data Analyst）
- `search_files (parentId = '<folderId>')` でフォルダ直下と `投稿別インサイト/` を列挙
- ファイル名規則で役割を分類（`概要_*`=アカウント分析、`オーディエンス_*`=属性、`投稿NN本目`=伸びた投稿）

### Step 2: 数値抽出 → report_data.json（Data Analyst + Report Builder）
**出力:** 対象フォルダ内 `report_data.json`（MCPの `create_file` で書込）
1. 各画像を `read_file_content`（OCRテキスト層）で取得
2. 主要指標画像は `download_file_content`→PNG保存→画像読取（ビジョン）で**桁を再確認**
3. `schema/report_data.schema.json` に従い構造化。**不明値は空文字 `""`、推定値は入れない**
4. `summary` / `next_actions` は数値傾向から下書きし、人レビュー前提でマーキング

**完了条件:** `meta` / `account_analytics` が埋まり、`dashboard_images` にファイルIDが入っている
**[QA Check 1]** 前月比の符号、桁区切り、リーチ/視聴者リーチ/プロフィール閲覧の取り違えが無いか

### Step 3: Devil's Advocate（異常値検証・推奨）
- 前月比が桁外れ（>±999%等のダッシュボード表記）をそのまま転記していないか
- フォロワー純増 = 新規 − 減少 の整合
- 投稿別の突出値（バズ投稿）の取り違えが無いか

### Step 4: Notion へレポート生成（＝一覧へ1行追記）
**実行:** `notion-create-pages`（parent = data_source_id `7c23288c-fabf-4b60-aa1b-7f1494f2da79`）
1. プロパティを設定: レポート名 / クライアント / 媒体 / 対象月 / データ取得期間 / ステータス(ドラフト) / フォロワー / リーチ / いいね / Driveフォルダ / 作成日
2. ページ本体を生成: `## 01 総括` `## 02 アカウント分析`(指標表＋オーディエンス＋ダッシュボードリンク) `## 03 投稿分析`(伸びた投稿表＋評価) `## 04 次回施策`(ToDo)
3. ダッシュボード/投稿画像は Drive **リンク**で掲載（公開化しない）
4. 生成ページURLを返す

**完了条件:** DBに1行（=1ページ）が生成され、URLが取得できる
**[QA Check 2]** 主要指標がプロパティ・本文で一致、空欄に推定値が入っていないか

### Step 5: QA Reviewer（生成物の目視整合）
- 数値・空欄・リンク有効性をチェック。差し戻し時は `report_data.json` を修正して再生成（冪等）。`summary`/`next_actions` は人が確定後、ステータスを「確定」へ更新

> **クライアント体裁（Slides）が必要なとき** … 付録A の Apps Script で同じ `report_data.json` からデッキを生成する。

## 実行トリガー
| トリガー | 実行主体 | 契機 |
|---|---|---|
| 手動指示（既定） | 運用担当 | 「REVECAREERAGENCYの2026年6月提出分でレポート生成して」 |
| （将来）定期ポーリング | GitHub Actions / Apps Script トリガー | 親フォルダを走査し新規月次フォルダを検知 |

## エラー時の対応
| 問題 | 対応 |
|------|------|
| スクショOCRの桁が読めない | Step2でビジョン再読取。なお不明なら空文字のまま残し、人手補完を促す |
| 月次集計スクショが無い | `post_analysis_monthly` を空にし、当月は当該表を省略 or 手入力 |
| 前月フォロワーが不明（followers_start） | 過去レポート/前月概要から補完。無ければ空 |
| Notion画像をインラインで見せたい | Drive画像は機微情報。公開化せずリンク掲載が既定。必要なら別ホスティングを検討 |
| 同一フォルダで再実行 | 既存ページを更新（`notion-update-page`）するか、重複行を作らない |

## 学習ループ
- 抽出ミスのパターンを `/learnings/sessions/{date}_report_{client}.json` に記録
- 頻出する読み取り誤り（例: 視聴者リーチとリーチの取り違え、コメント↔シェアの順）は本手順書の[QA Check 1]に追記

## 付録A: クライアント提出用 Slides 出力（任意・後付け）
Notion主軸とは独立に、クライアント提出体裁が必要な場合のみ使用する。
同じ `report_data.json` を入力に、`/scripts/report-generator/Code.gs`（Apps Script）が
テンプレ『【テンプレ】分析レポート』を複製して流し込む。
ワンタイム設定（マスターテンプレのトークン化・Apps Scriptデプロイ）は
`/scripts/report-generator/README.md` を参照。MCPではSlides中身を編集できないため、
この経路だけは人手の初期設定が必要。
