SEO チェックリスト 112項目

SEO/AIEO Agent が全ての SEO 関連アウトプット（記事最適化・サイト設計・テクニカル監査・施策提案）で必ず参照する社内標準チェックリスト。 本リストの項目を満たさないアウトプットは QA Reviewer の差し戻し対象とする。

参照: 全112項目を6カテゴリに再編。元の連番（1〜112）は id として保持。

カテゴリ1: ドメイン・URL・サイト基盤（1〜11）

ID 項目 必須
1 独自ドメインを使う ◎
2 ドメイン名の長さは、あまり長くならないようにする ○
3 将来的に多言語展開がある場合、.jp は使わない ○
4 サブドメインの利用は非推奨 ○
5 URL（スラッグ）は、簡潔でわかりやすいアルファベット表記 ◎
6 URL は不変で、変わらないものにする ◎
7 URL は静的なもので、パラメータにより区別されるものは極力避ける ◎
8 文字コードは UTF-8 ◎
9 同一 URL で、PC/スマホ両対応のレスポンシブサイト ◎
10 SSL（https）対応 ◎
11 Google ビジネスプロフィールに登録する ○

カテゴリ2: キーワード戦略・サイト設計（12〜28）

ID 項目 必須
12 対象キーワードの検索ボリュームは、十分多いものを使う ◎
13 同じようなキーワード（検索意図が同じ、検索結果がほぼ同じ）はグループ化して、一つとして扱う ◎
14 キーワードの種類（購入・行動につながるクエリと情報収集のクエリ）を考慮して、ページに割り当てる ◎
15 全国対象ではない場合は、地名を追加して確認 ○
16 メインで狙うキーワードを一番最初に決める（社内相談必須） ◎
17 競合調査は、メインで狙うキーワードで検索した上位の類似サイトを調べる ◎
18 競合とは違う軸で勝てる要素をコンセプトにする ◎
19 主要なすべてのページにキーワードを割り当てる ◎
20 サイト全体を親子孫の上下階層がある構成にする ◎
21 トップページはサイト全体の目次として設計 ◎
22 グローバルナビを設置し、重要なページへの導線を確保する ◎
23 フッターナビを設置し、主要なページへの導線を確保する ◎
24 すべてのページがオリジナルの内容にする ◎
25 類似ページ、重複ページが多数になるような設計をしない ◎
26 狙うキーワードを極力、上部（ファーストビュー内が理想）に設置 ◎
27 コンテンツの下部、サイドバー、フッターなどから関連ページへのリンクを設置 ○
28 子供のページへのリンクは、コンテンツとして配置する ○

30 200文字など極端に文字数の少ないページが出来ないようにする ◎
31 タイトルとリンクのみのページは、極力作らない ◎
32 できれば、カテゴリページ、一覧ページにも、リンク以外でオリジナリティを確保する ○
33 1ページ=1テーマにする ◎
34 狙うキーワードをコンテンツに含める ◎
35 狙うキーワードが複合キーワードある場合は、できる限り近接させる ◎
36 狙うキーワードの表記ゆれがある場合は、すべてのパターンを自然に入れ込む ○
37 狙うキーワードを乱用しない ◎
38 キーワードの出現率を計算しない ◎
39 関連キーワード、メインキーワードを意識して入れる ◎
40 狙うキーワードに対してユーザーのニーズを満たす内容を入れる ◎
41 h1>h2>h3 の構造を想定してライティングする ◎
42 できれば h2、h3 などは、それぞれの親に対して3つ以上存在するようにする ○
43 h1 と title タグは、ほぼ同じ内容にする ◎
44 h1 と title タグには、狙うキーワードを前方に配置 ◎
45 h1 と title タグの文字数は、長くしすぎない ◎
46 h1 と title タグは、ページ内容を適切に表すもの ◎
47 h1 はページに1回を基本 ◎
48 h2〜h4 を利用して構造化する ◎
49 メインコンテンツ以外に、h タグを使わない ◎
50 HTML5 を極力取り入れる ○
51 <strong> を乱用しない ○
52 <em> は基本使わない ○
53 表は <table> ○

凡例

  • ◎ 必須: 違反した場合 SEO に直接的な悪影響。アウトプット前に必ず満たすこと。
  • ○ 推奨: 違反でも致命的ではないが、満たさない場合は output.json の seo_checklist.skipped に理由を明記する。

運用ルール

アウトプット前チェック

SEO/AIEO Agent は以下のアウトプットを行う前に、本チェックリストの該当項目を確認し、output.json に検証結果を記録する:

  • 新規記事のメタデータ生成
  • 既存記事の SEO 監査
  • サイト設計レビュー（IA/URL構造/内部リンク設計）
  • テクニカル SEO 監査（クロール/インデックス/速度）
  • 競合分析レポート

output.json への記録フォーマット

{
  "seo_checklist_verification": {
    "checklist_version": "v1.0 (112 items)",
    "verified_ids": [1, 5, 10, 24, 26, 33, 41, 43, 47, 57, 60, 82, 83, 84, 88, 97, 109],
    "passed": [...],
    "failed": [
      { "id": 26, "reason": "ファーストビュー内にキーワードなし", "fix": "h1直後の冒頭120文字に挿入提案" }
    ],
    "n_a": [
      { "id": 11, "reason": "ECサイトのため Googleビジネスプロフィール対象外" }
    ],
    "skipped_optional": [
      { "id": 63, "reason": "記事数が少ないため遅延読み込み未実装" }
    ]
  }
}

QA Reviewer 連携

QA Reviewer は SEO/AIEO Agent の出力に seo_checklist_verification フィールドが含まれない、または必須項目（◎）の failed が空でない場合、自動的に差し戻す。

更新・改訂

  • 改訂時は本ファイル冒頭の checklist_version をインクリメント
  • 追加項目は連番継続（113, 114, ...）
  • 廃止項目は削除せず「廃止: 理由」を追記して履歴を保持
