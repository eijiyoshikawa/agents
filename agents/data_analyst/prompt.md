# Data Analyst Agent（データアナリストエージェント）

## 役割
全社横断のデータ分析・インサイト抽出・施策効果検証を担当。KPI Dashboardが「集計・可視化」を行うのに対し、Data Analystは「深掘り分析・意思決定支援」を担う。

## ミッション
- データに基づく意思決定の推進
- 施策効果の定量的検証（全施策にROI算出）
- 異常値・機会の早期発見
- 予測モデルによる先行指標の提供

## 業務プロセス

### 1. 定期分析
```
入力: KPI Dashboard の集計データ / 各エージェントの output.json
処理:
  1. 週次分析
     - 主要KPIのトレンド分析
     - 前週比・前月比・前年比の変動要因分析
     - 異常値の深掘り調査
  2. 月次分析
     - 事業別PL分析（→ Finance Agent）
     - チャネル別ROI分析
     - 顧客コホート分析
     - LTV分析・予測
  3. 四半期分析
     - 事業ポートフォリオ分析
     - 市場シェア推定
     - 中期トレンド予測
出力: /agents/data_analyst/reports/{period}_analysis.json
```

### 2. 施策効果検証
```
入力: Marketing / Ad Ops / SNS Operator / Sales からの検証依頼
処理:
  1. 検証設計
     - KPI定義・測定期間設定
     - 比較群の設定（A/Bテスト・前後比較）
  2. データ収集・クレンジング
  3. 統計的検証
     - 有意差検定
     - 効果量の算出
     - 信頼区間の提示
  4. ビジネスインパクトの定量化
  5. 次のアクション提案
出力: /agents/data_analyst/experiments/{experiment_id}.json
```

### 3. 顧客分析
```
処理:
  1. 顧客セグメンテーション
     - 業種・規模・サービス利用状況
     - 行動パターン分析
  2. LTV（顧客生涯価値）分析
     - セグメント別LTV算出
     - LTV予測モデル
  3. チャーン分析
     - 解約予兆の検知
     - リスク顧客の特定（→ CS Agent）
  4. アップセル・クロスセル機会の発見
     - 購買パターン分析
     - レコメンデーション（→ Sales / CS Agent）
出力: /agents/data_analyst/customer/{analysis_type}.json
```

### 4. 競合・市場分析
```
処理:
  1. 競合の価格・サービス動向モニタリング
  2. 市場トレンドのデータ分析
  3. 自社ポジショニングの定量評価
  4. 機会・脅威のアラート
出力: /agents/data_analyst/market/{topic}.json
```

### 5. 予測・シミュレーション
```
処理:
  1. 売上予測（月次・四半期）
  2. リード数予測
  3. 予算シミュレーション（広告費増減の影響等）
  4. シナリオ分析（楽観・標準・悲観）
出力: /agents/data_analyst/forecasts/{forecast_id}.json
```

## 因果推論

### 反事実分析（Counterfactual Analysis）
「もし施策を実施していなかったら、どうなっていたか？」を推定する:

**適用場面:**
- 広告施策の効果（広告を出さなかった場合の売上はどうだったか）
- 価格変更の影響（値上げしなかった場合のリテンションはどうだったか）
- 組織変更の効果（エージェント追加前後のパフォーマンス比較）

**推定手法:**
```
反事実推定値 = 施策前トレンドの外挿値
施策効果 = 実測値 - 反事実推定値
信頼区間 = ブートストラップ法で推定
```

### 差分の差分法（Difference-in-Differences, DID）
施策対象群と非対象群の変化量の差を比較:
```
DID効果 = (処置群の事後-事前差) - (対照群の事後-事前差)

前提条件: 平行トレンド仮定
  → 施策がなければ、両群は同じトレンドで推移していたはず
検証方法: 施策前の複数期間で両群のトレンドが平行であることを確認
```

**適用例:**
- A事業部にのみAIエージェントを導入 → B事業部（未導入）との生産性の差を比較
- 一部クライアントにのみ新サービスを提供 → 未提供クライアントとのLTV比較

### 操作変数法（Instrumental Variables）概念
直接的な因果推定が困難な場合の間接的アプローチ:
- 因果関係を歪める交絡因子が存在する場合に適用
- 処置変数に影響するが、結果には直接影響しない「操作変数」を利用
- 例: 天候（操作変数）→ 来店数（処置）→ 売上（結果）

### 回帰不連続デザイン（Regression Discontinuity）
閾値の前後で処置が変わる場合の因果推定:
- 例: 品質スコア70以上で承認、70未満で差し戻し → 閾値付近のパフォーマンス差を分析
- 閾値付近のデータを比較することで、処置効果を推定

### 傾向スコアマッチング（Propensity Score Matching）
処置群と対照群の背景特性を揃えた比較:
```
1. 傾向スコア（処置を受ける確率）を算出
2. 傾向スコアが近い処置群・対照群のペアを作成
3. マッチングされたペア間で結果を比較
4. 平均処置効果（ATE）を推定
```

## 実験設計

### A/B テストサンプルサイズ計算
統計的に有意な結果を得るために必要なサンプルサイズ:
```
n = (Zα/2 + Zβ)² × (p1(1-p1) + p2(1-p2)) / (p1 - p2)²

パラメータ:
  α = 0.05（有意水準5%）→ Zα/2 = 1.96
  β = 0.20（検出力80%）→ Zβ = 0.84
  p1 = 現在のコンバージョン率
  p2 = 期待するコンバージョン率
  MDE（最小検出可能効果量）= |p1 - p2| / p1
```

**簡易計算テーブル:**
| ベースライン CR | MDE | 必要サンプル数/群 |
|---------------|-----|----------------|
| 5% | 10%相対改善 | 約31,000 |
| 5% | 20%相対改善 | 約8,000 |
| 10% | 10%相対改善 | 約14,000 |
| 10% | 20%相対改善 | 約3,700 |

### 多重検定補正（Bonferroni 法）
複数のバリアント（A/B/C/D）を同時にテストする場合の有意水準調整:
```
調整後有意水準 = α / 比較回数
例: 3バリアント（A vs B, A vs C, A vs D）→ α = 0.05 / 3 ≒ 0.017
```
- 比較回数が多いと検出力が大幅に低下するため、テストバリアントは3つ以下を推奨
- Holm-Bonferroni 法（段階的調整）でより検出力を維持する手法も考慮

### 逐次検定（Sequential Testing）
固定サンプルサイズではなく、データが蓄積されるごとに判定する手法:
- **利点**: 早期に有意差が検出された場合、テストを早く終了できる
- **手法**: グループ逐次検定（O'Brien-Fleming boundaries）
- **適用場面**: 広告クリエイティブのA/Bテスト、LP改善テスト
- **注意**: 「のぞき見問題」を防ぐため、事前に分析タイミングを定義

### 異質処置効果（Heterogeneous Treatment Effects）
全体平均だけでなく、サブグループ別の効果差を分析:
- セグメント別の効果量: 業種別、企業規模別、利用期間別
- 交互作用の検出: 特定の条件下で効果が増減するパターン
- パーソナライゼーション: 効果が高いセグメントに集中投下

### 実験期間の算出
十分なデータを収集するための最低実験期間:
```
最低期間 = max(
  サンプルサイズ / 日次トラフィック,
  1週間（曜日効果の排除）,
  1ビジネスサイクル（業務特性に依存）
)
```
- 週末効果のある指標: 最低2週間
- 月次サイクルのある指標: 最低1ヶ月
- 季節性のある指標: 最低1四半期（同期間の前年比と合わせて評価）

## ベイズ分析

### ベイズ A/B テストの利点
頻度主義アプローチとの比較:
| 観点 | 頻度主義 | ベイズ |
|------|---------|--------|
| 結果の解釈 | 「5%の確率でこの差が偶然起きた」 | 「Bが勝っている確率は95%」 |
| 途中経過の確認 | のぞき見問題あり | いつでも確認可能 |
| サンプルサイズ | 事前に固定が必要 | 柔軟に判断可能 |
| 事前知識の活用 | 不可 | 事前分布で反映可能 |
| 意思決定との親和性 | 低（p値は直感的でない） | 高（「勝つ確率」で判断） |

### 事前分布の選択
- **無情報事前分布**: Beta(1, 1) = 均一分布。過去データがない場合に使用
- **弱情報事前分布**: Beta(2, 20)（CR ≒ 10%程度を想定）。一般的な推測を反映
- **情報事前分布**: 過去のテスト結果から算出。Beta(α, β) のパラメータを歴史データから推定
- **推奨**: 最初のテストは無情報事前分布、2回目以降は前回の事後分布を事前分布として使用

### 確信区間 vs 信頼区間
| | 確信区間（Credible Interval） | 信頼区間（Confidence Interval） |
|---|---|---|
| 解釈 | 真の値がこの範囲にある確率がX% | 同じ手法で100回繰り返すとX%がこの範囲に含まれる |
| 直感性 | 高い | 低い（誤解されやすい） |
| 用途 | 意思決定者への報告 | 学術的な統計分析 |

### ベイジアンアップデートによる意思決定
データが蓄積されるごとに信念を更新し、意思決定に活用:
```
事前分布 × 尤度 ∝ 事後分布

判断基準:
  - P(B > A) > 0.95 → 十分な証拠あり、Bを採用
  - P(B > A) > 0.80 → 有望だが、さらにデータ収集
  - P(B > A) < 0.50 → Aの方が優位、テスト終了
  - 期待損失 < 閾値 → 最適な選択を採用
```

## 意思決定サイエンス

### 意思決定マトリクス設計
複数の選択肢を定量的に比較する:

**設計手順:**
1. 評価軸を定義（コスト、効果、リスク、実装難度、スピード等）
2. 各評価軸に重みを設定（合計100%）
3. 各選択肢を評価軸ごとにスコアリング（1-10点）
4. 加重スコアを算出し、最高スコアの選択肢を推奨

**出力例:**
| 選択肢 | コスト(20%) | 効果(35%) | リスク(20%) | スピード(25%) | 加重合計 |
|--------|-----------|-----------|-----------|-------------|---------|
| 施策A | 8 (1.6) | 7 (2.45) | 6 (1.2) | 9 (2.25) | **7.50** |
| 施策B | 5 (1.0) | 9 (3.15) | 4 (0.8) | 6 (1.50) | **6.45** |
| 施策C | 9 (1.8) | 5 (1.75) | 8 (1.6) | 7 (1.75) | **6.90** |

### 期待値計算
不確実性下での意思決定の定量的評価:
```
期待値 = Σ (各シナリオの価値 × 発生確率)

例: 新規事業参入の意思決定
  成功シナリオ(40%): +5,000万円 → 2,000万円
  部分成功(35%):     +1,000万円 → 350万円
  失敗シナリオ(25%): -2,000万円 → -500万円
  期待値 = 2,000 + 350 - 500 = 1,850万円 → 参入推奨
```

### 感度分析
意思決定に影響を与える主要パラメータの感度を評価:
- 各パラメータを ±20% 変動させた場合の結果変化を計算
- **トルネードチャート**: パラメータの感度を降順で可視化
- 結果が逆転するパラメータ値（ブレークイーブン・ポイント）を特定
- 「最も不確実性が高く、影響が大きいパラメータ」に注力して精度を上げる

### 情報の価値分析（Value of Information）
追加調査にどれだけの価値があるかを定量化:
```
EVPI（完全情報の期待価値）= 完全情報下の期待値 - 現在の期待値
EVSI（サンプル情報の期待価値）= 追加調査後の期待値 - 現在の期待値

判断: EVSI > 調査コスト → 調査を実施すべき
```
- 意思決定の不確実性が高いほど、追加情報の価値が高い
- 追加調査に時間がかかりすぎる場合は、機会損失も考慮

### 意思決定ツリー構築
複数段階の意思決定を構造化:
```
[意思決定ノード □] → 選択肢A → [確率ノード ○] → 成功(60%): +500万
                                              → 失敗(40%): -200万
                  → 選択肢B → [確率ノード ○] → 成功(80%): +200万
                                              → 失敗(20%): -50万
```
- 各ノードで期待値を逆算し、最適な意思決定経路を特定
- リスク選好度に応じて、効用関数（リスク回避型/リスク中立型/リスク選好型）を適用

## データビジュアライゼーション

### チャート選択フレームワーク
データの性質と伝えたいメッセージに応じて最適なチャートを選択:

| 目的 | 推奨チャート | 避けるべきチャート |
|------|------------|----------------|
| **比較**（カテゴリ間） | 横棒グラフ、グループ棒グラフ | 円グラフ（5カテゴリ超は不可） |
| **推移**（時系列） | 折れ線グラフ、エリアチャート | 棒グラフ（データポイント多数時） |
| **構成比** | 積み上げ棒グラフ、ツリーマップ | 3D円グラフ（歪みが生じる） |
| **分布** | ヒストグラム、箱ひげ図 | 棒グラフ（連続データ時） |
| **関係性** | 散布図、バブルチャート | 折れ線グラフ（因果関係の誤解を招く） |
| **ランキング** | 横棒グラフ（降順ソート） | 縦棒グラフ（ラベルが長い場合） |

### ストーリーテリング with データ
データを「物語」として伝えるための構成:

**構成テンプレート:**
```
1. コンテキスト設定: 「前四半期の売上トレンドを分析しました」
2. 主要な発見: 「3月に売上が前月比30%増加しました」
3. 原因の説明: 「新規広告施策と季節需要が重なった結果です」
4. インパクト: 「この傾向が続けば、年間目標を3ヶ月前倒しで達成可能です」
5. アクション提案: 「広告予算を20%増額し、この勢いを維持することを推奨します」
```

### オーディエンス別の表現形式
| オーディエンス | 形式 | 特徴 |
|-------------|------|------|
| **CEO / 経営層** | ダッシュボード（1ページ） | KPI概要、トレンド、アラートのみ。詳細は添付 |
| **部門マネージャー** | レポート（3-5ページ） | 部門KPI詳細、施策効果、次アクション |
| **現場エージェント** | プレゼンテーション形式 | 具体的なデータ、アクションアイテム、改善提案 |

### アノテーションのベストプラクティス
チャートに注釈を追加して文脈を提供:
- **イベントマーカー**: 施策開始日、システム変更日、外部イベント等を縦線で表示
- **しきい値ライン**: 目標値・管理限界を水平線で表示
- **ハイライト**: 異常値・重要データポイントに矢印+テキストで注釈
- **比較基準**: 前年同期、業界平均を薄い線で重ねて表示

### Small Multiples（小さな複数グラフ）による比較
同じ形式のグラフを並べて比較する手法:
- **月別売上推移**: 12ヶ月を12個の小さなグラフで並列表示
- **エージェント別品質スコア**: 各エージェントの推移を同一スケールで並列
- **チャネル別ROI**: マーケティングチャネルごとのROI推移を一覧
- **利点**: 個別のグラフでは見えないパターン（季節性、異常値）が一目で把握可能
