## 2. 設計上の論点と推奨案

### 論点A: 営業とマーケへの「両建て表示」問題（最重要）

**懸念**: SNS運用 月30万×半年（180万）を受注したとき、営業に180万・マーケに180万と表示すると、会社の実売上180万に対して評価上は360万に見える。かつ1件で半年分の粗利基準をほぼ達成してしまう。

**推奨: 「役割売上の両建ては容認」＋「計上は月次発生ベース」の組み合わせ**

1. **両建ては問題ない**と整理する。営業の数字は「受注貢献」、マーケの数字は「運用貢献」であり、**職種ごとに独立した達成率**（分母=その職種の人件費×3）を測るための役割別の物差し。会社の実売上と一致させる必要はなく、シート上に「役割貢献ベースであり会社売上とは異なる」と明記する
   - 対案（役割分配方式: 営業50%/マーケ50%等）は合計が会社売上と一致する利点はあるが、数字が半分になり基準の再調整が必要な上、「自分の売上」という納得感が薄れるため非推奨
2. **「1件で達成」問題は、計上タイミングを月次発生ベースにすれば解消する**
   - 受注時に契約総額180万を一括計上するのではなく、**MF実仕訳と同じ月次発生**（月30万ずつ、実際に請求が立った月に計上）とする
   - 半年査定の期間中に1件だけなら最大180万。営業の基準は 30万×社保係数×6ヶ月×3 ≒ 620万前後になるため、1件では全く届かない。常時複数案件を回して初めて達成できる構造になる
   - 途中解約・返金があれば以降の月の計上が自然に止まる（発生主義の副次効果）
   - 財務ダッシュボード連動（MF実仕訳ベース）とも完全に一致し、実装も既存集計を流用できる
   - 参考情報として「受注総額（契約ベース）」を別枠表示するのは可（評価判定には使わない）

|---|---|---|

### 論点C: チーム評価の連動方式

**要件**: マーケは全案件をチームで遂行するが売上は担当1名に紐づく。個人成績になるがチームで頑張る動機が要る。チーム達成率を個人成績に最終的に掛け合わせる。

**推奨の計算フロー**（旧シートで連動していなかった反省を踏まえ、1本の式で完結させる）:

> ⚠️ **2026-08-28 設計変更**: 下記の乗算方式（最終達成率・チーム係数）は廃止。現行の確定式は以下の2トラック独立判定（詳細は CRITERIA-DRAFT.md v0.4）:
>
> ```
> 個人達成率   = 個人粗利 ÷ (個人人件費 × 職種倍率)   → ランク昇降格を判定
> チーム達成率 = チーム合計粗利 ÷ (チーム合計人件費 × 職種倍率) → ボーナスを判定
> ```
> チームが達成すれば全員にボーナス（個人下限ガードなし・純チーム連動）。チーム未達でも個人達成率次第で昇格はある（逆も同様）。1名チームはチーム達成率＝個人達成率。

```
（旧・2026-08-25案）
個人達成率   = 個人粗利 ÷ (個人人件費 × 3)
チーム達成率 = チーム合計粗利 ÷ (チーム合計人件費 × 3)
最終達成率   = 個人達成率 × チーム係数(チーム達成率から算出)
→ 最終達成率 100%以上でボーナス1ヶ月のベースに乗る／ランク昇降格も最終達成率で判定
```

- チーム係数の形は2案:
  - **(a) 段階式**（旧v1.4型: 例 120%+=1.10 / 100〜119=1.00 / 80〜99=0.90 / …）— 分かりやすいが境界で不連続
  - **(b) 連続式**（例: 係数 = 0.7 + 0.3 × min(チーム達成率, 1.2)）— 境界の不公平がない。旧v2.1レビューでも連続式を推奨した経緯あり
- チームの定義: 営業チーム／マーケチームを職種単位で分けるか、事業部単位か → **要決定**
- ④不動産/BPOは単独のためチーム係数なし（個人達成率のみ）

### 論点D: 5段階ランクと昇降格

骨格案（数値はすべて仮・要決定）:

| 項目 | 案 |
|---|---|
| ランク | R1〜R5 の5段階 |
| 査定サイクル | 半年（会計年度に合わせ 10-3月 / 4-9月 が候補） |
| 昇格 | 達成率が基準値以上を1期達成 → 1ランク昇格（判定指標は2026-08-28変更で**個人達成率**） |
| 降格 | 達成率が下限値未満を1期 → **即1ランク降格**（同上・**個人達成率**で判定。2026-08-28に「2期連続」から変更。1期即降格は労務リスクが上がるため社労士確認を必須とする） |
| スタート位置 | R1 or R2 → **保留（後で決定）** |
| ランク別月給 | 昇格ごとの昇給テーブル → 要決定 |

⚠️ **労務上の前提**: 降格・査定給減額・賞与変動条項は就業規則の裏付けが必要（旧制度でも未完のTODOだった項目。新制度の運用開始前に社労士確認を推奨）

### 論点E: 個人ページの表示（財務連動）

- データ源は既存の slack-let 集計基盤（MF実仕訳 → 担当マッピング → 暗号化配信）を流用可能。新シート用に「役割売上」の付け替えルール（営業=受注案件の月次売上 / マーケ=運用担当案件の月次売上）を追加実装する
- 個人ページに出すもの（案）: 当期の役割売上・直課費用・粗利 / 達成率ゲージ2本（**個人=昇降格用・チーム=ボーナス用**。2026-08-28変更で「最終」ゲージは廃止）/ ボーナスライン到達見込み / 現ランクと次回査定までの残期間
- 従業員向け表示ルールは旧シートで確立した仕様を引き継ぐ: 通信費・家賃の按分は表示しない（2026-08-25 役員指示）
