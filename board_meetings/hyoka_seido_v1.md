# 評価・報酬制度 確定仕様（v1）

- **ステータス**：確定版 v1（2026-08-17 役員会議・社内MTGで骨子合意）
- **会社／期**：株式会社LET（第9期）
- **関連**：評価サイト [let-hyoka](https://let-hyoka.vercel.app/)／財務ダッシュボード [slack-let](https://slack-let.vercel.app/)
- **位置づけ**：本仕様を Claude Code 専用セッションへ引き継ぎ、let-hyoka／制度運用に実装する前段の確定ドキュメント。

---

## 1. 全体構造（二レバー）

| レバー | 基準 | 目的 |
|--------|------|------|
| **昇給** | **個人ベース**（職種別5段階評価＋面談・日頃の行動） | 差をつける（個人の実力・成長を反映） |
| **ボーナス** | **チームベース**（半期粗利 ÷ 人件費 の比例） | 連帯（チームで勝った時に全員で分ける） |

- 自分の担当を伸ばす → 個人売上 → **昇給**で回収
- 他人を助ける → チーム粗利↑ → **ボーナス**で回収
- **分配（比例配分）ルールは設けない**。助け合いの対価はチームボーナスで報われる設計。
- **成果責任は担当者が全て負う**（進捗管理・継続率・解約含む）。他メンバーが作業を手伝っても、成果責任はオーナー（担当者）に一本化。

---

## 2. 昇給（個人ベース）

- 職種ごとに **5段階評価**（各コアを5段階で判定）。面談は月次または3ヶ月に1回で測定。
- 定量が出しにくい職種（マーケ等）は、コミュニケーション頻度・制作量なども評価に組み込む。
- 各段階には**行動アンカー（何ができたらその段か）**を文章で定義し、評価者間のブレを抑える。
- 昇給は恒久コストのため、**単月では上げない**（複数期の連続達成＋等級テーブルで判定）。降級条件も併せて定義。

> 個人換算（担当企業＝1人のオーナーに割り付け、個人売上として計上）により、自分でやるか・担当を持ち替えるかで自然に業務を触り合う流れを作る。

---

## 3. ボーナス（チームベース）＝確定式

### 3.1 計算式
> **支給（ヶ月分）＝ 半期粗利 ÷（半期人件費 × 3）**
> ※ 半期粗利 ＜ 半期人件費×3 のときは 0／**上限なし**

- 倍率 `m = 半期粗利 / 半期人件費` とすると **支給ヶ月 = m / 3**
- アンカー：**3x → 1ヶ月 ／ 6x → 2ヶ月**（その間・その先は比例）

### 3.2 定義
| 項目 | 定義 |
|------|------|
| 測定・精算 | **半期（6ヶ月）ごと・年2回** |
| 分母（人件費） | **役員報酬は含まない**。1人あたり人件費 ＝ 基本給25万 − 固定残業代4万 ＝ **21万/月**（社保等のフルロードは含めない前提。※必要なら要見直し） |
| 判定粗利 | 売上 −（原価）。ただし**投資認定費用は差し引かない**（下記3.4） |
| 発動条件 | 半期粗利 ≥ 半期人件費×3（**黒字条件は設けない**） |
| 上限 | **なし**（比例で青天井。自己資金性が高いため） |
| 支給対象 | ランプ期間中（入社3ヶ月）を除く在籍メンバー |

### 3.3 感度表（倍率 → 支給ヶ月）
| 半期粗利/半期人件費 | 支給ヶ月 |
|---|---|
| 3.0x | 1.00 |
| 4.0x | 1.33 |
| 4.29x（粗利150万/人・月相当） | 1.43 |
| 5.0x | 1.67 |
| 6.0x | 2.00 |
| 9.0x | 3.00 |

### 3.4 投資認定費用の除外（ガバナンス）
- **AI関連費（Claude／ChatGPT／API等）は投資と認定**し、判定粗利から差し引かない。
- **期初に役員が承認した投資リストで固定。期中の再分類は禁止**（閾値ゲーム防止）。
- 財務科目整理（8/10決定）と整合：通信費／ソフトウェア利用料＝固定費、**AI関連費＝投資・削減対象にしない**。

### 3.5 ランプ期間
- **入社3ヶ月間は、本人の人件費・生んだ粗利の両方を判定から除外**（新人採用で閾値が跳ね上がり既存メンバーが損をする逆インセンティブを回避）。

---

## 4. ⚠️ 代表確認ポイント：「半期計測＝年2ヶ月（手厚い方）」

半期計測のため、**同じ経営強度でも年間支給は年次計測の2倍**になる。

- **3x運転** → 半期ごと1ヶ月 → **年2ヶ月分**（年次計測なら年1ヶ月）
- 賞与が消費する粗利の割合：年次換算 約2.8% → **半期計測で約5.6%/年**

**現状の確定：半期計測（＝年2ヶ月＝手厚い方）で運用する。**
※ もし「年で1ヶ月相当に抑えたい」場合は、半期アンカーを半分（**半期3x→0.5ヶ月／6x→1ヶ月**）に読み替える。← 代表判断で切り替え可能。

## 5. 数値イメージ（人件費21万/月/人・実額ベース）

3名・**人件費 21万/月/人**（＝基本給25万−固定残業代4万、役員除く）→ 月63万・**半期人件費＝378万**。
※ ボーナス「1ヶ月分」の支給額も同じ21万ベースで算定（固定残業代を含む25万ベースにするなら ×25/21 で読み替え）。

| シナリオ | 半期粗利 | 倍率 | 支給ヶ月 | 半期総額 | 年間（×2回） |
|---|---|---|---|---|---|
| 3x 達成 | 1,134万 | 3.0x | 1.00 | 63万（1人21万） | 126万 |
| 4.29x | 1,620万 | 4.29x | 1.43 | 90万（1人30万） | 180万 |
| 6x 達成 | 2,268万 | 6.0x | 2.00 | 126万（1人42万） | 252万 |
| **粗利150万/人・月（現行目標）** | **2,700万** | **7.14x** | **2.38** | **150万（1人50万）** | **300万** |

### ⚠️ 追加の代表確認ポイント（人件費21万の影響）
- 人件費を **21万（社保等フルロードなし）** に置くと、**「×3」の閾値が低く**なり、ボーナスが手厚く出やすい。
- 特に**現行の粗利目標「一人150万/月」を達成した時点で約7.1x → 半期2.38ヶ月（年約4.76ヶ月）**に達する。
- 選択肢：**(a) このまま手厚く運用**／**(b) 人件費を社保込みのフルロードに変更して倍率を締める**／**(c) 3x・6xのアンカーを引き上げる**。← 代表判断ポイントとして保留。

## 6. レビューで挙がった懸念と対応（Devil's Advocate 結論）

| # | 懸念 | 対応・結論 |
|---|------|-----------|
| 1 | 縦割り×個人売上換算の帰属矛盾 | **解消**。担当＝1人のオーナー、助けは権利移譲/成果責任一本化で帰属は明確。分配を作らない設計で移譲レート問題も消滅 |
| 2 | チームボーナスのフリーライド／トップ流出 | **割り切り**。差別化は昇給側に集約。ボーナスはフラット比例で連帯。降級含む昇給側を強く運用することが前提 |
| 3 | 前提データの不備（広告費/紹介料混在・一括入金按分・入金超過1,400万未記帳・江原目標未設定） | **実装前提**。let-hyoka／MFのデータ確定を先行。確定まで金額反映は試験運用扱いが安全 |
| 4 | 恒久昇給に不安定シグナル | 昇給は複数期＋等級テーブルで判定（単月で上げない） |
| 5 | 3x→6xの死角 | **解消**。3x超は比例（m/3）で連続化 |
| 6 | 採用で閾値が跳ね上がる | **解消**。入社3ヶ月ランプ除外 |
| 7 | 投資フェーズが閾値を潰す | **解消**。投資認定費用を判定から除外（期初固定） |
| 8 | 黒字ゲート無しの払い過ぎ | **許容**。比例式は支給が粗利の一定割合に収まり自己資金性が高いため、黒字条件なしでも構造的にリスク小 |
| 9 | 継続率・アカウント価値が個人指標から抜ける | **昇給側で担保**。守りの指標（継続率・解約防止・売掛滞留ゼロ）を個人スコアカードに組み込む（slack-letアラート指標を流用） |

## 7. 実装・引き継ぎタスク（Claude Code 専用セッション向け）

1. **let-hyoka にボーナス試算機能を実装**：半期粗利÷(半期人件費×3) を自動算出し、メンバー別支給ヶ月・金額を表示（役員報酬は分母から除外）。
2. **投資認定リストの期初固定フロー**：AI関連費など投資費用を判定粗利から除外する仕組み＋期中再分類ロック。
3. **ランプ判定**：入社3ヶ月のメンバーを人件費・粗利の両方から自動除外。
4. **昇給側 5段階評価テンプレート**：職種別コア項目＋行動アンカー＋守りの指標（継続率等）を整備。
5. **データ確定の前提整備**：広告費/紹介料の分離、一括入金の月次按分、入金超過の記帳確認、全メンバー目標設定（江原含む）。
6. **半期／年1ヶ月の切替パラメータ**：アンカー（3x→1 or 0.5ヶ月）を設定値化し、代表判断で切替可能に。
