# 7日サイクル運用（Weekly Sprint）

**1週間 = 1スプリント** でCRTV検証を回す高速イテレーション運用。`weekly_optimization.md` の上位概念として、CRTV量産優先の案件で適用。

## 1. 適用条件

- 月予算が小〜中規模（〜30万円/月）でCV最適化より**訴求方向性の発見**が目的
- 媒体は TikTok 主軸 or Meta 静止画中心（学習期が短い形式）
- CRTV制作リソースが週次で確保できる

**統計的「方程式化」までは到達しない**前提。仮説の方向性を高速に絞り込み、Phase 2 検証で本格化させる。

## 2. 1スプリントの定義

```
Day 0 (火) : 前スプリント結果集計・分析・新仮説起票
Day 1 (水) : 新CRTV制作・媒体投入準備
Day 2 (水夜): 配信開始
Day 3 (木) : 触らない（学習期1日目）
Day 4 (金) : 触らない（学習期2日目）
Day 5 (土) : Hook率・CTRで中間スクリーニング、明らかに負けてる弾は停止可
Day 6 (月) : 中間レビュー、勝ち弾の予算微増（+20%まで）
Day 7 (火朝): 配信終了 → Day 0 に戻る
```

**配信実時間 ≈ 4.5日**（Day 2夜〜Day 7朝）。短いが、CRTVの Hook率・CTR・3秒視聴率は判定可能。
CV(応募)は予算不足で統計サンプル届かない可能性大 → **副指標として扱う**。

## 3. スプリントごとの目標

| 項目 | 目標 |
|---|---|
| 新規CRTV投入 | **6-12本/スプリント** |
| 継続CRTV（前回勝ち弾） | 2-4本（疲弊監視） |
| 仮説起票数 | 3-5本 |
| KPI主指標 | Hook率（3秒視聴）/ CTR / Save率 |
| KPI副指標 | LP→Apply CVR / 応募CPA |
| 学び1件 | `learnings/instincts/recruit_ads.json` に最低1件追加 or 強化 |

## 4. 役割と担当

| 担当 | 月-火 | 水 | 木-月 | 火 |
|---|---|---|---|---|
| Marketing | 仮説起票・統計検定依頼 | レビュー | - | 集計レビュー |
| Content Creator | CRTV ブリーフィング受領 | **CRTV6-12本制作・納品** | 次サイクルCRTV準備 | - |
| Ad Operations | 媒体構成設計 | キャンペーン投入 | モニタ・予算配分 | 結果エクスポート |
| Data Analyst | - | - | - | 統計検定・学び抽出 |
| Engineer | LP/タグ確認 | - | LP CVR レビュー | - |
| PM | スプリント全体管理 | - | - | レトロ実施 |

## 5. CRTV量産パイプライン

「6-12本/週」を維持するための制作フロー:

```
[Day 0 火 夕方] 仮説起票 → CRTV ブリーフ作成
   ├ 訴求軸（H1〜H6）どれか
   ├ ペルソナ
   ├ フック1秒目案
   ├ 形式（UGC / テロップ / 静止画 / カルーセル）
   └ コピー2-3案

[Day 1 水] CRTV制作
   ├ AM: 撮影 or 素材集めor AI生成
   ├ PM: 編集・字幕焼き込み・BGM・サムネ
   └ 夕: 納品・命名規則チェック

[Day 1 水 夕] 媒体投入準備
   ├ 命名規則チェック（naming_conventions.md 準拠）
   ├ UTM 付与確認
   ├ LP メッセージマッチ確認
   └ Legal クイックチェック（NG表現スキャン）

[Day 2 水 夜] 配信開始
```

### CRTV量産のコツ

- **1本フル制作 + 派生5-7本**: ベース動画1本作って、テロップ違い・サムネ違い・尺違いで派生
- **AI生成の活用**: AI ナレーション・AIアバター・Canva 動画テンプレで制作コスト圧縮
- **Spark Ads 活用**: 自社オーガニック投稿 or インフルエンサー投稿の権利化（TikTok）
- **静止画は無限に出せる**: テキスト訴求 + ストック写真の組合せで日10本可能
- **再利用**: 過去の勝ち訴求×新ペルソナの組合せはほぼ常に有効

## 6. Day 0 火曜 のレトロスペクティブ

毎週火曜の Day 0（90分想定）で実施:

```
1. 数値確認 (15min): 前スプリント結果を register.csv に転記
2. CRTV別分析 (30min): Hook率/CTR/CVR ランキング
3. 勝ち負け判定 (15min): 統計検定 or 経験則で確定
4. インスティンクト更新 (15min): learnings/instincts/recruit_ads.json
5. 次サイクル仮説起票 (15min): 3-5本の H-statement
```

## 7. 7日サイクルのアンチパターン

- [ ] Day 3-4 でCPAだけ見て一喜一憂・停止判断（学習期）
- [ ] CRTVを「来週5本」と緩める（疲弊スピードに負ける）
- [ ] 同じ訴求軸ばかり回す（探索カバレッジ低下）
- [ ] 仮説書かずに「とりあえず新CRTV投入」
- [ ] レトロをスキップ（学習が貯まらない）
- [ ] 1本のCRTV予算を厚くしすぎて他が学習できない

## 8. 卒業条件（→ 隔週/月次サイクルへ）

以下を満たしたらスプリントをスローダウン可:

- 訴求軸ごとの勝ち負け方向性が固まった（インスティンクト confidence ≥ 0.7 が3軸以上）
- 月予算が増えて Phase 2 検証フェーズに移行
- 同じLP・同じペルソナで CPA レンジが安定（変動係数 < 30%）

→ `06_formulas/formulas/F-{area}-{industry}.md` 起票検討。
