# データ共有ガイド（Data Sharing Guide）

採用広告プロジェクト開始前に「**何があれば早い・何がなくても進められる**」を明確化し、共有方法を統一する。

## 1. データの3段階

| 段階 | 必要性 | 内容 |
|---|---|---|
| **MUST**（無いと配信できない） | 必須 | 募集要項・連絡先・LP有無・媒体アカウント |
| **SHOULD**（あると圧倒的に早い） | 強推奨 | 過去広告データ・採用済社員情報・ブランド素材 |
| **NICE**（中長期で精度UP） | 推奨 | CRM全データ・採用ファネル時系列・競合分析 |

## 2. 共有形式マップ

| データ種類 | 推奨形式 | 共有先 | 機密度 |
|---|---|---|---|
| 募集要項（求人票） | Markdown / PDF | `clients/{name}/data/job_descriptions/` | 公開可 |
| 会社概要・ブランド | Markdown + 画像 | `clients/{name}/data/brand/` | 公開可 |
| 既存LP URL | URL | intake.md に記載 | 公開可 |
| 媒体アカウント情報 | アカウントID + 権限付与 | intake.md（IDのみ）/ 秘密情報は1Password等 | **高** |
| 過去広告データ | CSV（命名規則準拠） | `clients/{name}/data/past_ads/` | 中 |
| 採用済社員リスト | CSV（PIIマスク） | `clients/{name}/data/employees/`（社内限） | **高** |
| 社員ヒアリング録 | Markdown | `clients/{name}/data/interviews/` | 中 |
| 写真・動画素材 | ファイル | Google Drive / `assets/` （大容量はDrive推奨） | 中 |
| 競合広告スクショ | 画像 + メモ | `clients/{name}/data/competitors/` | 公開可 |
| CRM全データ | CSV / API連携 | 別途設計（直接コミットしない） | **最高** |

## 3. リポジトリへ入れて良いもの／NGなもの

### コミット OK
- 募集要項の本文
- ブランドガイド・ロゴ（社の許可範囲内）
- 集計済の数値（個人特定不可な形）
- 競合の公開広告スクショ
- 仮説・戦略文書

### コミット NG（絶対に入れない）
- 個人氏名・電話番号・メール（応募者・社員問わず）
- 媒体アカウントの **パスワード・APIキー・トークン**
- CRMの生データ
- 撮影同意なしの社員写真
- 顧客企業の機密情報

PIIや認証情報は `.env` / 1Password / Notion秘匿ページに格納し、リポジトリには**参照キーのみ**置く（例: `meta_account_id: 1234567890 / 認証情報は 1Password "LET-Meta"`）。

## 4. データの形式テンプレ

### 4.1 募集要項（job_description.md）

```markdown
# 求人: {職種名} / {勤務地}
- 雇用形態: 正社員 / パート / 業務委託
- 給与: 月給 ○○円〜○○円 / 時給 ○○円
  - 固定残業: ○○h ○○円分含む（あれば必ず明記）
  - 賞与: 年○回 / ○ヶ月分
- 勤務地: 〒○○○ ○○県○○市○○ / 最寄駅 ○○線○○駅 徒歩○分
- 勤務時間: ○:○○〜○:○○ (休憩 ○○分)
- 休日休暇: 完全週休2日 / 年間休日○日
- 福利厚生: 社保完備 / 通勤手当 / 退職金 / 〇〇
- 応募資格: 必須 / 歓迎
- 仕事内容: ...
- 採用人数: ○名
- 試用期間: ○ヶ月 / 条件変更有無
- 募集背景: 増員 / 欠員 / 新規事業
- 担当者連絡先: （CRM側、リポジトリには書かない）
```

### 4.2 過去広告データ（past_ads.csv）

最低限の列:
```
date,media,campaign,adset,ad,imp,click,ctr,cost,form_start,apply,valid_apply,interview,hire,notes
```

媒体ダッシュボードのエクスポートをそのまま頂くだけでも OK（後で揃えます）。

### 4.3 採用済社員データ（employees_masked.csv）

PIIを必ずマスクして:
```
employee_id,role,hired_at,age_range,gender,prev_industry,channel,decision_factor_top1,decision_factor_top2,still_active,retention_days
```

例:
```
E001,介護福祉士,2025-04-01,30s,F,販売,Indeed,夜勤なし,通勤距離,true,420
```

### 4.4 社員ヒアリング（interview_{employee_id}.md）

```markdown
# Interview: E001（介護福祉士・30代女性）
- 実施日: 2026-05-15
- 面談者: HR Agent / Marketing Agent
- 内容
  - 前職: アパレル販売
  - 転職理由: 子供の小学校入学、時短勤務希望
  - 当社を選んだ理由: 「夜勤なし日勤のみ」が明確だった
  - 応募媒体: Indeed → LP閲覧 → LINE経由応募
  - 決め手: 第一に時間、第二に給与、第三に職場の雰囲気
  - 不満・改善要望: 入社後の引き継ぎが手薄だった
- インサイト
  - 30代女性パートはやはり時間軸訴求が最強
  - LINE 経由応募の体験が良かった → 同チャネル拡張余地
```

## 5. データ受け取り後のフロー

```
[共有受領]
  ↓
[Retriever / Data Engineer が一次受け]
  ├ 形式統一（CSV列名揃え、PIIマスク確認）
  ├ /clients/{name}/data/ 配下に配置
  └ data_index.md を更新（何が揃っているかのインデックス）
  ↓
[Marketing / Data Analyst が分析]
  ├ ペルソナ補強（industry_personas.md に追記）
  ├ 既存KPI抽出（kpi_definitions.md のレンジに照合）
  └ 仮説生成
  ↓
[intake.md にサマリ追記]
  ↓
[Phase 1 探索の EXP-ID 起票]
```

## 6. 推奨ツール

| 用途 | ツール |
|---|---|
| 大容量素材（動画・画像） | Google Drive（DriveのMCP連携で参照可） |
| 共有ドキュメント | Notion（Retriever Agent 経由で取得） |
| 認証情報 | 1Password / Bitwarden（**直接共有禁止**） |
| 集計データ | Google Sheets / CSV |
| ヒアリング録音 | Google Drive（文字起こしのみコミット） |

## 7. 共有時に伝えてほしいこと

データを渡す際は以下を一緒に教えてください:

1. **誰が** いつ集めたデータか
2. **どの範囲を含むか**（例: 2025年4月〜2026年3月の全応募者）
3. **欠損や除外があるか**（例: テスト応募を除いた）
4. **再加工OKか**（例: PII含むので外部共有時はマスク必要）
5. **公開して良い範囲**（例: 数字はOKだが、個人特定情報はNG）

## 8. データなしでも始められる最低ライン

何も無くても以下が揃えば配信は可能:

- [ ] 募集要項（職種・給与・勤務地・連絡先）
- [ ] 会社概要（簡単な紹介）
- [ ] 媒体アカウント開設（無ければ並行で開設依頼）
- [ ] LP（無ければ標準雛形で2-3日で作成可）
- [ ] 配信予算と開始時期

不足分は社員ヒアリング1-2件で補い、Phase 1 探索からデータを貯めていきます。
