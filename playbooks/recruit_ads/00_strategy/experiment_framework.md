# 実験設計フレームワーク

採用広告で「大量の施策を打ちながら検証する」ための原則。**仮説なき配信は実験ではなく浪費**。

## 1. 実験単位（変数の分離）

1キャンペーンで複数変数を同時に変えると、何が効いたか分からなくなる。**変数は1軸ずつ**動かす。

| レイヤー | 変数の例 | 分離方法 |
|---|---|---|
| **訴求（Hook）** | 給与訴求 / 働き方訴求 / 仲間訴求 | Ad Set を分ける |
| **クリエイティブ形式** | UGC風 / インタビュー / モンタージュ / 静止画 | Ad を分ける |
| **ターゲティング** | 通勤圏15km / 駅周辺3km / 県全域 | Ad Set を分ける |
| **LP** | 短尺LP / 長尺LP / フォーム直 | URL を分ける（UTM `content` で識別） |
| **媒体** | Meta / TikTok / LINE | キャンペーンを分ける |

**1実験 = 1仮説 = 1変数**。複数変数を同時に動かすのは「探索フェーズ」のみ許容、検証フェーズでは禁止。

## 2. 仮説の書き方（H-statement）

```
H-{EXPID}: [セグメント]に対し、[訴求/CRTV/ターゲティング/LP]を[A→B]に変えると、
           [KPI]が[期待方向]に[期待幅]動く。理由は[根拠]。
```

例:
```
H-EXP-20260601-003: 介護職×埼玉県南エリアに対し、訴求を「給与強調」→「夜勤なし強調」に
変えると、応募CVRが+30%動く。理由はペルソナ（30代女性主婦層）の優先順位が
時間 > 賃金 という1次データ（社内CSヒアリング）から。
```

## 3. 実験フェーズ

```
[Phase 1: 探索]   予算少・変数多・期間短  → 勝ち筋の方向性を見つける
   ↓ （CPAが市場相場の±50%以内に入った）
[Phase 2: 検証]   予算中・変数1・期間中  → 統計的に有意か確認
   ↓ （p < 0.1 かつ 3回再現）
[Phase 3: 拡張]   予算大・水平展開       → エリア・業種を変えて再現性確認
   ↓ （別エリア/別業種でも再現）
[Phase 4: 方程式化] formulas/ に登録    → 誰でも使える資産化
```

## 4. 統計的有意性の最低ライン

| 指標 | 最低サンプル | 判定 |
|---|---|---|
| CTR | imp 5,000 以上 | 95%信頼区間で差が出るか |
| CVR | クリック 500 以上 | 同上 |
| CPA | CV 30 以上 | カイ二乗 or 二項検定 |
| 採用率 | 応募 50 以上 | 同上 |

**サンプル不足での「効いた/効かなかった」判定は禁止**。register.csv の `statistical_power` 列で十分性を明示する。

## 5. 学習サイクル（週次）

```
月: 前週の実験結果を register.csv に集計
火: Data Analyst が統計検定 → 勝ち/負け/保留に分類
水: Marketing + Ad Ops で次週の仮説を起票（最低5本）
木: クリエイティブ・LP・タグを準備
金: 配信開始
土〜日: 配信、低パフォーマンスはAd Set単位で停止
```

## 6. やってはいけないこと（アンチパターン）

- [ ] 仮説なしで「とりあえず回す」
- [ ] 初日のCPAだけで停止判断（学習期間を無視）
- [ ] 複数変数を同時に変えて「Bが勝った」と結論
- [ ] サンプル不足のまま方程式化
- [ ] エリアや業種が違う実験を同列に比較
- [ ] LPのCV計測タグが入っていない状態で配信
- [ ] 募集要項の法令チェック（Legal）を経ずに配信

## 7. 探索 vs 検証の予算配分

```
全体広告予算 100% のうち
├ Phase 1（探索）        : 20%   ← 常時 5〜10 本の新仮説をテスト
├ Phase 2（検証）        : 30%   ← 探索で芽が出た仮説を本検証
├ Phase 3（拡張）        : 40%   ← 勝ちパターンの水平展開
└ 緊急対応・予備         : 10%
```

CPAが安定したからといって100%を拡張に振ると、市場変化で全滅する。**常に20%は探索に回す**。
