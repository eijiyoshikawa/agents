# エリアセグメント定義

「エリア × 業種の方程式」を作るため、**エリアの切り方を共通化**する。

## 1. エリアの3つの粒度

| 粒度 | 用途 | 例 |
|---|---|---|
| **マクロ**（都道府県・地方） | 全社戦略・予算配分 | `kanto` / `tokyo` |
| **メゾ**（市区 / 都市圏） | キャンペーン単位 | `tokyo23` / `chiba-north` |
| **ミクロ**（駅・半径km） | Ad Set単位 | `radius-15km-funabashi` |

## 3. ミクロ（駅・半径）の切り方

```
radius-{km}km-{駅 or 拠点名}
```

| 業種 | 推奨半径 | 理由 |
|---|---|---|
| 介護施設 | 8-15km | 通勤可能距離 |
| 飲食店 | 3-5km | 自転車圏 |
| 建設現場 | 30-50km | 車通勤・現場移動前提 |
| 工場 | 15-30km | 車通勤・寮ありなら全国 |
| 営業職 | 20-30km | 公共交通通勤 |
| 配送ドライバー | 営業所半径20km | センター集合型 |

例: `radius-10km-funabashi` / `radius-30km-toyota-honsha`

## 4. 通勤圏 vs 居住エリア

**Meta/TikTok の「People living in this location」と「People recently in this location」で挙動が異なる**。

| 設定 | 拾える人 | 推奨用途 |
|---|---|---|
| Living in | 居住者のみ | 主婦・地元雇用 |
| Recently in | 通勤・通学者含む | 都心の事業所・夜勤系 |
| Travelling in | 旅行者含む | NG（応募率低い） |

採用広告は原則 **Living in**。都心オフィス勤務の正社員等は **Recently in** も検討。

## 5. エリア戦略の考え方

### A. 半径攻めパターン（推奨初手）

事業所中心 → 半径段階拡大（5km → 10km → 15km）で CVR/CPAをモニタ。
半径拡大に伴い応募の質は下がるため、**有効応募CPAの増加カーブで限界点を測る**。

### B. 駅周辺集中パターン

主要駅から半径3km × 5駅 を別Ad Setで比較。
業種により駅特性が出る（例: 介護は住宅街駅、飲食は繁華街駅）。

### C. 競合エリア配信パターン

競合の店舗周辺で配信（条件比較訴求）。Meta は競合店舗から半径500m〜2kmで配信可能。
※ 競合誹謗はNG。「うちは○○です」と自社訴求のみ。

## 6. 都道府県別 採用市場の特性メモ

| 都道府県 | 特性 |
|---|---|
| 東京 | 競合多・CPM高・採用しやすい層は限定（パート主婦は強い） |
| 神奈川 | 横浜・川崎で都心並みCPM、湘南は別市場 |
| 千葉北 | 都心通勤者多、介護・運輸が手厚い |
| 埼玉 | 東京通勤圏、主婦パート市場大きい |
| 大阪 | 関東より総じてCPC安い、競合密度は東京並み |
| 名古屋 | 自動車関連製造・運輸の独自市場 |
| 福岡 | 若年層多・CPCやや安い |
| 地方都市 | CPC最安、ただし母数限定で配信規模に注意 |

## 7. 方程式化のためのエリア記録

各実験の `register.csv` に必ず `area_code` を記入。
同一 `industry × area_code` で3実験以上累積 → `06_formulas/formulas/F-{area}-{industry}.md` 作成のトリガー。
