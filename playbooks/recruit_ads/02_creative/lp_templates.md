# 求人LP雛形

応募CVR を最大化するLP構造。**広告の訴求とLPの第1ビューを必ず一致**させる（メッセージマッチ）。

## 1. 基本構造（縦長LP）

```
┌─────────────────────────────────┐
│ 1. ファーストビュー（FV）         │ ← 広告と同じ訴求・写真・キャッチ
│   - 強フック1行 + 副コピー        │
│   - メインビジュアル              │
│   - 即CTA（応募ボタン）          │
├─────────────────────────────────┤
│ 2. 信頼指標                       │ ← 応募数・在籍者数・受賞・メディア掲載
├─────────────────────────────────┤
│ 3. 仕事内容（写真多め）          │ ← イメージ払拭・透明性
├─────────────────────────────────┤
│ 4. 待遇・条件サマリ              │ ← 給与・休日・福利厚生 表形式
├─────────────────────────────────┤
│ 5. 1日の流れ                     │ ← 時系列で具体的に
├─────────────────────────────────┤
│ 6. 先輩の声（3-5名）             │ ← 顔写真・年齢・前職・入社理由
├─────────────────────────────────┤
│ 7. よくある質問（FAQ）           │ ← 不安の先回り解消
├─────────────────────────────────┤
│ 8. 応募フォーム                  │ ← 質問は最小限（後述）
├─────────────────────────────────┤
│ 9. 会社情報・地図                │ ← 信頼補強
└─────────────────────────────────┘

※ 各セクション後にCTAボタン or フォーム再掲（離脱対策）
```

## 2. ファーストビュー（FV）チェックリスト

- [ ] 広告クリエイティブと同じビジュアル要素（顔・場所・色）
- [ ] 広告と同じフックコピー（メッセージマッチ）
- [ ] スマホ1画面内に「キャッチ + CTA」が収まる
- [ ] CTAボタンは画面下部固定（Sticky）も併用
- [ ] 表示速度 LCP < 2.5秒（画像最適化必須）

## 3. フォーム最適化（最重要）

CVR を倍増させる最大レバー。**質問は本当に必要なものだけ**。

### Minimum Viable Form（初回）

```
1. お名前（フルネーム）            必須
2. 電話番号                       必須
3. 希望勤務地（プルダウン）        必須
4. 希望シフト or 連絡可能時間帯    必須
[送信]
```

→ 4項目以内が黄金比。住所・職歴・自己PRは後段で取得。

### NGなフォーム

- [ ] 10項目以上の長尺フォーム
- [ ] 自己PR欄が必須
- [ ] 履歴書添付が必須（応募ハードル激高）
- [ ] パスワード設定（会員登録方式）
- [ ] 確認画面が3画面以上

### 推奨機能

- 入力中の自動保存（離脱→復帰）
- スマホで電話番号タップ → 即ダイヤル併設
- 送信完了後、即「ありがとう」ページ + 次のアクション（LINE登録等）
- リアルタイムバリデーション（赤エラー表示）

## 4. LPバリアント

`utm_content` で識別可能にし、複数LPを並行運用してCVRを比較。

| LP-ID | 種別 | 特徴 | 用途 |
|---|---|---|---|
| `lp-{industry}-v1` | 縦長フルLP | 全要素入り | 標準・キャリア転職層 |
| `lp-{industry}-v2-short` | 短尺LP | FV+条件+フォームのみ | 即応募志向層 |
| `lp-{industry}-v3-form` | フォーム直 | LPなし | LeadAds類似、最大CVR・最低品質 |
| `lp-{industry}-v4-line` | LINE誘導 | 友だち追加経由 | 主婦・シニア層 |

## 5. メッセージマッチの実装

広告で「夜勤なし」と訴求 → LPのFVも「夜勤なし」 → フォーム前にも「夜勤なし」明記。

`utm_content` から動的にFVコピーを切り替える実装も推奨:
```
?utm_content=ugc_c014_nokin-nashi → FV: 「夜勤なし日勤のみ」
?utm_content=ugc_c014_salary       → FV: 「月収32万・賞与年4ヶ月」
```

## 6. 計測タグ（必須）

LPに以下を必ず設置:

- Meta Pixel + Conversions API
- TikTok Pixel + Events API
- LINE Tag + Conversion API
- GA4
- 自社CRM 計測タグ

イベント:
- `PageView` (FV表示)
- `ScrollDepth_50` (中段到達)
- `FormStart` (フォーム初回フォーカス)
- `Lead` (フォーム送信完了)

各タグの dedup 用 `event_id` を共通発行（`04_measurement/tracking_setup.md` 参照）。

## 7. 法令チェック（配信前 Legal Agent 必須）

- [ ] 募集要項が職業安定法準拠（年齢・性別限定の例外要件確認）
- [ ] 給与表記が労基法準拠（固定残業代の明示等）
- [ ] 「正社員」表記時の試用期間条件明示
- [ ] 個人情報取得目的・第三者提供の明示（個情法）
- [ ] プライバシーポリシー・特商法表記（事業者の場合）

## 8. デザインリファレンス

CLAUDE.md の「デザインシステム」セクションに従い、和文B2B案件は `/design-md/feer/DESIGN.md` をデフォルト基準とする。

モーションは `/design-md/motion-library/MOTION_30.md` の `motion_key` を引用。
求人LPは過剰アニメーション NG（読みやすさ最優先 → `grow-from-bottom` 程度に抑える）。

## 9. LP雛形コードベース

実装は `agents/engineer` または `agents/frontend_engineer` が担当。
Next.js + Tailwind CSS で `/app/lp/recruit/[industry]/page.tsx` 構造を想定。
雛形コード自体は `app/` 配下に配置（このプレイブック側はドキュメントのみ）。
