# LET 営業コックピット（sales-cockpit）

bizba-lead / bizba-sales のアレンジ版を社内用に内製した、**Notion を単一ソースにした「リード獲得 → 契約 → 継続」一体型ダッシュボード**です。Notion に溜まっているデータを、週次会議でそのまま使える形に可視化します。

## できること（第1弾）

- **週次 / 月次トグル**で架電数・アポ数・アポ率の推移を表示
- **KPIカード**: 今週/今月の架電数・アポ率、MRR、稼働契約数、新規契約数
- **担当者別 実績**（今月の架電・アポ・アポ率）
- **パイプライン・ファネル**（顧客ステータス別の件数）
- **MRR・稼働契約数の推移**（直近6ヶ月）
- **架電リスト + クリック発信**: 電話番号クリックで OS既定の電話アプリ（Zoom Phone を既定にすれば Zoom）で発信。顧客名・電話番号・IS担当・ステータスで絞り込み可能

> 架電の集計は **📞架電記録（顧客紐付け）と 📞IS架電KPI を統合**しています。

## 日次・週次・月次と、アポ管理（2026-11-09 追加）

- **ホーム上部「今日・今週・今月」**: 架電・接触・アポ獲得・商談実施・新規契約を実績/目標で表示（目標は目標設定の値を営業日で按分）
- **日次ボード（/daily）**: 担当者別の実績（今日/今週/今月）、**今日できていないこと**（架電目標の不足、期限が来たフォローの未対応、アポの実施予定日時の未入力、予定日を過ぎたアポの結果の未回答、アポ管理への未登録、入口商材の未入力、今週の架電 0件の日）、**日別×結果の件数表**
- **📅 アポ管理**（1アポ=1行）: 架電結果で「アポイント獲得」を記録すると実施予定日時の入力を求め、1行作る。予定日を過ぎたら日次ボードで「実施／リスケ／キャンセル／先方不在」を回答。リスケは今の行を閉じて新しい予定日で次の行を作り、元の予定日・リスケ回数を引き継ぐ（2回以上は要注意）。実施なら顧客ステータスを「アポイント獲得」→「商談中」
- **入口商材**: 架電結果の記録で選べる（前回の選択を端末に記憶）
- **顧客ステータス → 契約管理DB**: 顧客を契約中にすると契約締結前の契約を契約中に、契約終了にすると解約済み（終了日つき）に、契約中から見込み客などに戻すと契約締結前に。案件KPI・担当マッピングは masterAI の 5 分おきの同期が契約管理DB から追従する

## データソース（Notion）

| 用途 | DB |
|---|---|
| 顧客マスタ・ファネル・電話番号 | 📊 DB_顧客管理 |
| 実架電ログ | 📞 架電記録 |
| MRR・契約・継続 | 🤝 契約管理DB |
| 月次目標つき架電ログ（任意） | 📞 IS架電KPI |
| アポの実施予定・結果・リスケ | 📅 アポ管理（`NOTION_DB_APPOINTMENTS`。既定は実DB） |

## セットアップ

### 1. Notion インテグレーションを作成

1. https://www.notion.so/my-integrations で「新しいインテグレーション」を作成（内部）
2. 「Internal Integration Secret」(`ntn_...`) を控える
3. 上記4つのデータベースをそれぞれ開き、右上「...」→「コネクト」→ 作成したインテグレーションを追加（**これを忘れると403/データ0件になります**）

### 2. 環境変数

```bash
cp .env.example .env.local
# .env.local を編集して NOTION_TOKEN を設定
# DB ID は既定で LET公式Notionの実DBを指しています。別環境なら差し替え。
```

### 3. 起動

```bash
npm install
npm run dev      # http://localhost:4100
```

### 4. デプロイ（Vercel）

- Root Directory を `sales-cockpit` に設定
- Environment Variables に `.env.example` の各値を登録
- 静的書き出しではなくサーバーランタイムで動作します（Notion をライブ取得するため）

## クリック発信について

- 既定スキームは `tel:`。**Zoom Phone をOSの既定電話アプリに設定**すれば、発信ボタンで Zoom Phone が起動します。
- 別スキームを使いたい場合は `NEXT_PUBLIC_CALL_SCHEME`（例: `callto`）を変更してください。
- 通話結果の自動記録（Zoom Phone API 連携）は第2弾の予定です。現状は Notion へ手動入力します。

## 設計メモ

- `lib/notion.ts` — Notion 依存（スキーマ・プロパティ抽出）をここに集約
- `lib/aggregate.ts` — 純粋な集計関数（週次/月次/ファネル/MRR）
- `lib/period.ts` — すべて **JST(+9h)** 基準で週(月曜始まり)・月にバケット化
- `components/*` — 表示は正規化済みドメイン型のみ参照
- デザインは CLAUDE.md の和文B2Bデフォルト（feer ベース）に準拠

## 目標値の一括設定

`config/targets.json` をまとめて編集 → コミット → 再デプロイ（`vercel --prod`）で反映されます。

| 項目 | キー | 説明 |
|------|------|------|
| 営業日数 | `workingDaysPerMonth` | 日別目標→月次換算に使用 |
| 月のアポ獲得目標 | `company.monthlyAppointments` | 全社・当月 |
| 月の契約数目標 | `company.monthlyContracts` | 全社・当月 |
| 日別の架電目標（共通） | `dailyCallsDefault` | 全担当の既定値 |
| 日別の架電目標（担当別） | `dailyCallsByRep` | 担当ごとに上書き |
| 月次の架電目標（担当別/任意） | `monthlyCallsByRep` | 直接指定したい場合のみ。日別より優先 |

担当者別の月次架電目標の優先順位は **`monthlyCallsByRep` → 日別×営業日数 → Notion(IS架電KPIの月次目標架電数)** です。ダッシュボード上部の「目標達成状況」に、本日の架電・月次架電・アポ・契約の達成率が表示されます。
