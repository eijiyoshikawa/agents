## 各エージェント業務詳細

### 1. Retriever（議事録取得・分解）
- **業務**: Notion MCPを使い会議議事録を検索・取得し、構造化データに変換
- **出力項目**: 会議タイトル、日時、参加者、議題、キーポイント、アクションアイテム、クライアント情報
- **使用ツール**: notion-search, notion-fetch, ファイル書き込み
- **強み**: 議事録の自動取得と標準フォーマットへの変換
- **課題**: Google Drive過去資料の検索がオプショナルで活用度が低い

### 2. Issue Structurer（イシュー言語化・構造化）
- **業務**: クライアントの事業文脈を整理し、最重要コアクエスチョンを定義。課題を4カテゴリ（市場・競合・顧客・内部）に分解し、リサーチクエリを生成
- **出力項目**: core_question, issues（カテゴリ別・優先度付き）, research_queries（5-10個）
- **使用ツール**: ファイル読み書きのみ
- **強み**: 構造化された課題分解により後続エージェントの精度向上に寄与
- **課題**: フレームワーク（3C, SWOT等）の明示的適用がない

### 3. Market Researcher（市場調査 + 顧客分析）
- **業務**: WebSearchで市場規模・成長率・トレンド・競合戦略・ベンチマーク・顧客行動を収集
- **出力項目**: insights（market/competitor/benchmark/customer）, customer_segments（3-5個）
- **使用ツール**: WebSearch, WebFetch, ファイル読み書き
- **強み**: Web検索による最新データ収集、顧客セグメント定義
- **課題**: データの信頼性検証プロセスがない

### 4. Analogy Finder（異業種アナロジー事例収集）
- **業務**: 課題構造を抽象化し、異業種の類似事例を5-8件収集。転用可能なインサイトを抽出
- **出力項目**: cases（業界・企業・要約・転用インサイト・ソースURL）
- **使用ツール**: WebSearch, WebFetch, ファイル読み書き
- **強み**: 異業種からの発想転換による独自性のある提案
- **課題**: アナロジーの適用可能性評価が主観的

### 5. Strategist（戦略構築 + 批判的検証）
- **業務**: 全リサーチを統合し戦略オプション3-5個を構築。Devil's Advocate（前提検証・リスク分析・問題再定義）を経て最終推奨戦略を選定
- **出力項目**: strategic_options, critical_reviews, recommended_strategy
- **使用ツール**: ファイル読み込み（3ファイル）、ファイル書き込み
- **強み**: 批判的検証プロセスが組み込まれた戦略立案
- **課題**: 実行計画（タイムライン・KPI・予算）の具体性が不足

### 6. Report Builder（提案資料構成作成）
- **業務**: 10-15枚のスライド構成を設計。各スライドのタイトル・箇条書き・スピーカーノートを作成
- **出力項目**: slides配列（slide_number, type, title, bullets, speaker_notes）
- **使用ツール**: ファイル読み込み（4ファイル）、ファイル書き込み
- **強み**: 標準的なコンサル提案書フォーマットに準拠
- **課題**: ビジュアルデザイン指示・データ可視化指示がない

## 組織診断

### 現状評価

#### エージェント数: 6体（+ オーケストレーター）

#### 役割適正度
| エージェント | 適正度 | 理由 |
|------------|--------|------|
| Retriever | ★★★★☆ | 議事録取得に特化し明確。CRM連携があればなお良い |
| Issue Structurer | ★★★★★ | パイプラインの要。後続全体の精度を左右する重要ポジション |
| Market Researcher | ★★★★☆ | 調査範囲は適切。データ検証レイヤーが欲しい |
| Analogy Finder | ★★★★☆ | 独自性の源泉。適用可能性スコアリングがあればより良い |
| Strategist | ★★★★★ | Devil's Advocate内蔵は優秀。実行計画の具体化が次の課題 |
| Report Builder | ★★★☆☆ | 構成のみでスライド生成まで完結しない。デザイン指示不足 |

#### 相互干渉（チェック&バランス）の状態
```
Retriever ──→ Issue Structurer ──→ Market Researcher ──→ Strategist ──→ Report Builder
                                 └→ Analogy Finder  ──→↗
```

**問題点:**
1. **一方向フロー**: データが上流から下流への一方通行。フィードバックループがない
2. **品質チェック不在**: 各エージェントの出力を検証するレビュアーがいない
3. **Retriever が孤立**: 他のエージェントからのフィードバックを受けない
4. **Report Builder が末端**: 戦略の実行可能性を提案書視点で検証する仕組みがない
