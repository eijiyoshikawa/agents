# 架電数トラッキング（架電記録DB ＋ 日次集計）

「最終更新日」は架電以外の編集でも動き、回数・履歴も残らないため、**架電という行為を1件1レコードで記録**する方式に切り替える。

## ✅ 自動生成済み（Notion側セットアップ完了）
以下はNotion APIで作成済み:

### 「📞 架電記録」DB（顧客情報ページ配下）
- database_id: `f2a72c6221ed4de5acb000848c9b0cbe`
- data source: `d0e6622b-bd21-4172-9468-e72aa03f0799`
- プロパティ:
  | プロパティ | 種類 | 用途 |
  |---|---|---|
  | 件名 | Title | 例「2026-06-03 ○○商事」 |
  | **架電日時** | Date | 集計の基準 |
  | **担当者** | Select（江原/佐久間in/海野in/三輪in/境田in/吉田/吉川/長野/ロビンソンin） | 担当者別カウント。既存のIS担当に合わせた |
  | **結果** | Select（通話/不在/不通/受付拒否/担当者不在/担当者拒否/再コール/クレーム/見込み客/資料請求/アポイント獲得） | 既存ステータス語彙に合わせた |
  | 顧客 | Relation → DB_顧客管理 | 双方向。顧客側に「架電記録」プロパティが自動追加済み |
  | メモ | Text | 通話内容 |

### DB_顧客管理に追加したロールアップ
- **架電回数**: 架電記録の件数（Count）
- **最終架電日**: 架電記録の最新日（Latest date）

> 既存の「コール数」（手動number）はそのまま残してあります。今後は架電記録から自動算出される「架電回数」に寄せるのがおすすめ（コール数は過去分の参考値として保持 or 後日移行）。

## 日次集計スクリプト（call-report.mjs）
`CALL_LOG_DB_ID` は既に上記DBを既定値に設定済み。トークンだけ用意すれば動く:
```bash
export NOTION_TOKEN="ntn_..."

npm run report                     # 本日(JST)の架電数
DATE=2026-06-02 npm run report     # 指定日
DATE_FIELD=created_time npm run report   # 作成日時で集計したい場合
```
出力例:
```
📞 架電レポート 2026-06-03（JST）
総架電数: 87 件
— 担当者別 —
  江原: 41
  吉田: 46
— 結果別 —
  不在: 50
  通話: 25
  アポイント獲得: 7
```

## プロパティ名を変えた場合
`DATE_PROP` / `ASSIGNEE_PROP` / `RESULT_PROP` / `CALL_LOG_DB_ID` で上書き可能。

## 週次・月次
架電記録DBに「今週」「今月」フィルタのビュー、またはチャートで件数推移を可視化するのが手軽。
