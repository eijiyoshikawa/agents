# 架電数トラッキング（架電ログDB ＋ 日次集計）

「最終更新日」は架電以外の編集でも動き、回数・履歴も残らないため、**架電という行為を1件1レコードで記録**する方式に切り替える。

## 全体像
```
[架電ログDB] 1架電 = 1レコード（架電日時 / 担当者 / 結果 / メモ / 顧客リレーション）
      │ relation
      ▼
[DB_顧客管理] ロールアップで「最終架電日 = max(架電日時)」「架電回数 = count」を表示
```
→ 日次架電数 = 架電ログDBを日付で絞って件数。担当者・結果でグループ化すれば内訳も出る。

---

## STEP 1. 架電ログDBを作る（Notion UI）
顧客情報ページ内などに新規データベース（フルページ推奨）を作成し、以下のプロパティを用意:

| プロパティ名 | 種類 | 用途 |
|------------|------|------|
| 件名（タイトル） | Title | 例「2026-06-03 ○○商事」 |
| **架電日時** | Date（時刻ON） | 集計の基準。既定で当日をセット |
| **担当者** | Person（またはSelect） | 担当者別カウント |
| **結果** | Select | 通話 / 不在 / 留守電 / アポ獲得 / 見送り / 再架電 など |
| 顧客 | Relation → DB_顧客管理 | どの顧客への架電か |
| メモ | Text | 通話内容 |

> 集計を「レコード作成時刻」で済ませたい場合は `架電日時` の代わりに自動の「作成日時(created time)」を使ってもOK（スクリプトは `DATE_FIELD=created_time` で対応）。

## STEP 2. 顧客DBにロールアップを追加
DB_顧客管理に、STEP1のリレーション（顧客 ← 架電ログ）に基づくロールアップを2つ追加:

- **架電回数**: Rollup → リレーション「架電ログ」→ `架電日時` → 計算「Count（すべて）」
- **最終架電日**: Rollup → リレーション「架電ログ」→ `架電日時` → 計算「最新の日付（Latest date）」

これで顧客一覧に「何回かけたか」「最後にいつかけたか」が並ぶ。

## STEP 3.（任意）ワンクリック記録ボタン
DB_顧客管理に Button プロパティ「📞 架電を記録」を追加し、アクションを
「架電ログDBにページを追加 → 架電日時=今日 / 担当者=自分 / 顧客=このページ」に設定。
1クリックで1架電が記録できる。

## STEP 4. 日次集計スクリプト（call-report.mjs）
架電ログDBの `database_id` を控えて環境変数にセット:
```bash
export NOTION_TOKEN="ntn_..."
export CALL_LOG_DB_ID="（架電ログDBのID）"

npm run report                     # 本日(JST)の架電数
DATE=2026-06-02 npm run report     # 指定日
DATE_FIELD=created_time npm run report   # 作成日時で集計する場合
```
出力例:
```
📞 架電レポート 2026-06-03（JST）
総架電数: 87 件
— 担当者別 —
  山田: 41
  佐藤: 46
— 結果別 —
  不在: 50
  通話: 25
  アポ獲得: 7
  ...
```

### Slack に自動投稿（任意）
Slack の Incoming Webhook URL を設定すると、レポートを Slack にも投稿:
```bash
export SLACK_WEBHOOK_URL="https://hooks.slack.com/services/..."
npm run report
```
毎朝/毎夕の自動実行は cron で:
```bash
# 例: 平日19時に当日分を集計してSlackへ
0 19 * * 1-5  cd /path/to/scripts/notion-kansai-a && NOTION_TOKEN=... CALL_LOG_DB_ID=... SLACK_WEBHOOK_URL=... node call-report.mjs
```

## プロパティ名が異なる場合
スクリプトは環境変数で列名を上書きできる:
`DATE_PROP` / `ASSIGNEE_PROP` / `RESULT_PROP`（既定: 架電日時 / 担当者 / 結果）
