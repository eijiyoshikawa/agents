# 自動化：ステータス更新 → 架電記録に自動追加 → Slack通知（Notion標準オートメーション）

公開APIではオートメーションを作成できないため、**Notion UI で設定**する。サーバー不要・Notionクラウドで動作。

> 前提：Notion 有料プラン（Plus 以上）。Slack 通知には Notion に Slack を接続しておく（設定 → 連携、またはアクション設定時に接続）。

---

## 設定手順

### 1. オートメーションを新規作成
1. **DB_顧客管理** を開く
2. 右上の **⚡（オートメーション）→ 新規オートメーション**
3. 名前：「架電記録＋Slack通知」

### 2. トリガー：ステータスが変わったとき
- トリガー種別：**プロパティが編集されたとき** → プロパティ **「ステータス」**
- **条件を追加（推奨）**：ステータス が次のいずれか
  `受付拒否 / 不通 / 担当者不在 / 担当者拒否 / 再コール / クレーム / 見込み客 / 資料請求 / アポイント獲得`
  （契約中・失注・パートナー等の「架電ではない」状態を除外し、二重カウントも軽減）

### 3. アクション1：架電記録にページを追加
- アクション：**ページを追加** → データベース **「📞 架電記録」**
- 設定する項目：
  | 架電記録の項目 | セットする値 |
  |---|---|
  | 件名 | 例：`@顧客名`（トリガー元のタイトル）＋日付 |
  | 顧客（リレーション） | **このページ（トリガー元）** を関連付け |
  | 担当者 | トリガー元の **`IS担当`** を反映（※選択肢名は架電記録側と一致させてあるので、UIで値の参照が可能ならそのまま入る） |
  | 結果 | トリガー元の **`ステータス`** を反映（参照できない場合は §補足の「ステータス別」方式へ） |
  | 架電日時 | **今日**（設定欄が無い場合は §補足のとおり作成日時で代用） |

### 4. アクション2：Slackに通知
- 同じオートメーション内で **アクションを追加 → 「Slack に送信」**
- 送信先チャンネルを選択（未接続ならここで Slack ワークスペースを接続）
- メッセージ例：
  `📞 @顧客名 に架電：@ステータス（担当 @IS担当）`
  （`@` はプロパティ参照。UI上で挿入する）

### 5. 保存して有効化 → テスト
- 1社のステータスを「再コール」等に変更
- 「📞 架電記録」に1行増える＋Slackに通知が来ることを確認
- 顧客側の **架電回数／最終架電日** が更新されることも確認

## 補足

### A. 「結果」を確実にステータスと一致させたい場合（ステータス別オートメーション）
UI で「ステータスの値を結果に反映」がうまく選べない場合は、**架電ステータスごとに1つずつオートメーションを作る**のが確実：
- 例：トリガー「ステータスが『再コール』になったとき」→ 架電記録を追加（結果＝固定値「再コール」）
- 9種（受付拒否/不通/担当者不在/担当者拒否/再コール/クレーム/見込み客/資料請求/アポイント獲得）分を複製して値だけ変える
- 手間は増えるが、結果の値が常に正確に入る

### B. 架電日時が自動で入らない場合
架電記録の **作成日時（created_time）** はページ作成時に自動で入る。オートメーションで追加された行は「追加された瞬間＝架電時刻」なので、日次集計はこれで代用できる：
```bash
DATE_FIELD=created_time npm run report
```

### C. 二重カウントについて
1回の架電でステータスを複数回触ると複数行記録される。§2の「特定ステータスに変わったとき」条件で軽減する。気になる場合は B の created_time 集計で「同一顧客・同日」を目視確認するなどで対応。

### D. 日次サマリのSlack通知（任意・併用推奨）
1架電ごとの通知に加えて「本日の総架電数／担当者別」を毎日まとめて流したい場合は、別途 `call-report.mjs` ＋ Slack Webhook ＋ cron を使う（`CALL_TRACKING.md` 参照）。役割分担：
- **オートメーション**＝リアルタイムの1件通知＋記録作成
- **call-report**＝1日の集計サマリ
