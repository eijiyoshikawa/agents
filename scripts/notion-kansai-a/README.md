# set-kansai-a — 関西・従業員30名以上の見込み度合いを一括「A」に

Notion DB「DB_顧客管理」（`database_id: 1ac3fae434994991b465e375bef7d66c`）に対し、
下記3条件（AND）に一致する企業の「見込み度合い」を一括で `A` に設定する冪等スクリプト。

## 抽出条件
1. `従業員数` >= 30
2. `住所` に「大阪府 / 京都府 / 兵庫県」のいずれかを含む（滋賀県は B 扱いのため含めない）
3. `住所` に「東京都」を含まない
   （東"京都府"中市が「京都府」に部分一致する誤検出を、API側 `does_not_contain` で除外）

## 冪等性
- 既に `A` のページはスキップ。途中で止まっても再実行で残りから処理できます。
- 手動で先に `A` 済みの大手約60社（ニチイ学館・ソラスト・ツクイ等）も自動でスキップされます。
- 更新したページIDは `updated-log.csv` に追記されます。

## 事前準備
1. https://www.notion.so/my-integrations で内部インテグレーションを作成し、シークレット（`ntn_...`）を取得
2. 「DB_顧客管理」を開き、右上 `…` → **コネクトの追加** → 作成したインテグレーションを接続
3. トークンをセット:
   ```bash
   export NOTION_TOKEN="ntn_..."
   ```

## 実行手順
```bash
cd scripts/notion-kansai-a
npm install          # @notionhq/client を導入

# 1) まず件数だけ確認（更新しない）
npm run dry          # = DRY_RUN=1 node set-kansai-a.mjs

# 2) 問題なければ本実行
npm run run          # = node set-kansai-a.mjs
```

## 出力
完了時に「該当件数 / 更新件数 / スキップ件数 / 失敗件数」と、更新前の見込み度合い内訳を表示します。

## 補足
- 想定該当件数は1,000件超（大手介護・物流チェーンの各支店を含む）。仕様通りで問題ありません。
- レート制御: 更新間に約350msスリープ。429は `Retry-After` 準拠、5xxは指数バックオフでリトライします。
- `DATABASE_ID` を環境変数で上書きすれば別DBにも適用可能です。

# set-small-d — 従業員10名以下を一括「D」に（エリア指定なし）

同じDBに対し、**エリアを絞らず「従業員数が10名以下」**の企業の「見込み度合い」を `D` に設定する冪等スクリプト。

## 抽出条件
- `従業員数` <= 10（エリア条件なし）
- 任意で下限を設定可能：`EMP_MIN=1` を付けると 0名・空欄相当を除外（例: `EMP_MIN=1 npm run dry:d`）

> 注意: `従業員数` が**未設定（空欄）のページは number フィルタに一致しないため対象外**です。意図せず空欄企業をDにしてしまう事故は起きません。

## 冪等性
- 既に `D` のページはスキップ。途中停止しても再実行で残りから処理できます。
- 更新したページIDは `updated-log-small-d.csv` に追記されます（A設定のログとは別ファイル）。

## 実行手順
依存・トークン・コネクト接続は set-kansai-a と共通（このフォルダで `npm install` 済みなら追加導入は不要）。
```bash
# 1) まず件数確認（更新しない）
npm run dry:d        # = DRY_RUN=1 node set-small-d.mjs

# 2) 問題なければ本実行
npm run run:d        # = node set-small-d.mjs
```
