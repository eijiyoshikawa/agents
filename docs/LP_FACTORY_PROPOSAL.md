# LP テンプレート化（LP ファクトリー）の検討メモ — 2026-10-21

オーナーからの要望: 各担当が別リポジトリで作っている LP のデザインをテンプレートとしてシステムに保管し、新規案件では「色・会社情報・キャッチコピー」を入れるだけで LP が見せられる状態にして、新規導入から開始までの時間を縮めたい。各リポジトリを 1 つに集約する案でもよい。

## 2. 提案: 「LP ファクトリー」を 1 リポジトリで新設し、既存は現状維持

```
新規案件 → masterAI の案件ページ「LP を作る」で入力（色・会社情報・コピー・数字・LINE URL・画像）
        → LP ファクトリーが <案件スラッグ>.lp.let-inc.net に即時公開（プレビュー）
        → OK なら独自ドメインを割り当て（Vercel API で自動）
        → 応募フォームは masterAI の応募 Webhook（/api/kpi/applicants）へ直結 → 応募者タブに自動登録
        → 制作物・リンクタブに公開URL / GitHub / Vercel を自動登録
```

### 構成

- リポジトリ: `let-incjp/lp-factory`（新設・1 つ）。Next.js + Tailwind。**1 つの Vercel プロジェクトで全案件を配信**（ホスト名 or パスで案件を判定）
- テンプレート: `templates/<名前>/`。最初は 2 種類
  1. `recruit-onepage` — 1 枚完結の採用 LP（**構成はアルファガード、実装の土台は八百一の CSS 変数設計**。ヒーロー → 数字 → 働き方 → 入社後の流れ → 1 日 → 社員の声 → 向いている人 → 募集要項 → 流れ/Q&A → ENTRY）
  2. `recruit-site` — 採用サイト型（TECNES/千代田型。トップ + 事業・環境・人・フロー）
- 案件ごとの中身: `sites/<slug>/site.json`（下の項目）+ `sites/<slug>/images/`。デザインはテンプレートが持ち、案件側は値だけ
- 色: `site.json` の `brand`（メイン・アクセント・背景・文字の 4 色）を CSS 変数に流し込む。テンプレートは全部この変数だけで塗る（担当が色を直書きしない）
- 文言: `LP_TEXT.md` の構造をそのまま JSON 化（見出し・リード・要点 3 つ・数字 4 つ・社員の声 3 名・募集要項・Q&A・CTA 文言）。足りない項目はテンプレートの既定文で埋まるので、最小入力でも「見せられる」状態になる
- 応募導線: 「LINE へ誘導」「フォーム（→ 応募 Webhook）」「電話」を切り替え。LINE 待機ページ（カウントダウン付き）はテンプレートに同梱
- 計測: GA4 / Meta Pixel / TikTok Pixel の ID を `site.json` に入れるだけで挿入
- 公開: Vercel 1 プロジェクト。`<slug>.lp.let-inc.net` はワイルドカード DNS で自動、クライアントの独自ドメインは Vercel API で追加（CNAME の案内文を自動生成）

### `site.json` の項目（たたき台）

| 区分 | 項目 |
|---|---|
| 会社 | 会社名・ロゴ・所在地・業種・電話・会社URL・特定商取引法/プライバシーポリシー URL |
| ブランド | メイン色・アクセント色・背景色・文字色・フォント（和文 2 択） |
| 訴求 | キャッチコピー・リード文・要点 3 つ・数字 4 つ（例: 月給／残業／休日／教育時間） |
| 働き方 | 1 日の流れ・入社後の流れ・向いている人 |
| 人 | 社員の声 3 名（年齢・職種・コメント・写真） |
| 募集要項 | 雇用形態タブごとの表（職種・給与・勤務地・時間・休日・待遇） |
| 導線 | 応募方法（LINE / フォーム / 電話）・LINE URL・CTA 文言・応募 Webhook の案件 ID |
| 計測 | GA4 / Meta / TikTok の ID |

masterAI の案件データ（会社名・業種・エリア・募集職種・ペルソナ・CPA 目標）から半分は自動で埋められる。

### 既存の「LP複製部」との住み分け

| | LP ファクトリー（新設） | LP複製部（cantera リポジトリの手順） |
|---|---|---|
| 向く案件 | 標準的な採用 LP を**すぐ**見せたい新規案件 | 参考サイトを忠実に再現したい、独自デザインが必要な案件 |
| 入力 | 色・会社情報・コピー・数字・写真 | 参考 URL |
| 所要 | 数分〜1 時間 | 数時間〜数日 |
| 出力 | ファクトリー内の 1 サイト（同じ Vercel プロジェクト） | 専用リポジトリ + 専用 Vercel プロジェクト |

複製部で作った良いデザインは、あとからファクトリーの「型」として取り込める。

## 3. 「全部を 1 リポジトリに集約」案との比較

| 観点 | A. ファクトリー新設（推奨） | B. 既存 30 リポジトリを 1 つに集約 |
|---|---|---|
| 新規案件の速さ | 入力 → 即公開（数分） | 集約しても「コピーして書き換え」は残る |
| 既存 LP への影響 | なし（現状維持・GitHub はアーカイブ扱いでよい） | 全 LP のデプロイ設定を作り直す。事故リスク |
| 担当の作業 | テンプレートの改善だけに集中 | 変わらない |
| 工数 | テンプレート 1 本目で 1〜2 セッション | 移行だけで数セッション、機能は増えない |

既存 LP のうち、今後も改修が続くもの（例: TECNES）だけ、落ち着いたらテンプレートへ載せ替えればよい。

## 4. 進め方

1. **1 セッション目**: `lp-factory` リポジトリ作成、`recruit-onepage` テンプレート（アルファガードの構成・文言を既定値に）、`site.json` スキーマ、Vercel 1 プロジェクトで `<slug>.lp.let-inc.net` 配信、サンプル 1 案件で公開
2. **2 セッション目**: 画像アップロード（Vercel Blob）、応募フォーム → 応募 Webhook、LINE 待機ページ、計測タグ、独自ドメイン追加の自動化
3. **3 セッション目**: masterAI 案件ページに「LP を作る」フォーム（案件データから下書き → `site.json` を保存 → 公開 → 制作物・リンクに自動登録）、`recruit-site` テンプレート
4. 以後: 担当がテンプレートに「型」を追加（業種別の配色セット・セクションの追加）

## 5. オーナーに決めてほしいこと

1. **最初の型**: アルファガード型（1 枚完結）から始めてよいか。参考にしたい LP が他にあれば URL かリポジトリ名
2. **ドメイン方針**: 仮公開は `<案件>.lp.let-inc.net` でよいか（ワイルドカード CNAME `*.lp` を Xserver に 1 件追加）。本公開はクライアント側ドメインか LET 側か
3. **応募導線の既定**: LINE 誘導を既定にするか、フォーム（応募者タブへ自動登録）を既定にするか
4. **写真**: クライアント提供の写真が無い案件向けに、業種別のストック写真セットを用意するか
5. **担当者**: テンプレートの見た目を詰める担当（htmt / yrmt のどちらの方か）。その方のリポジトリの「良い所」を既定デザインに取り込む

決まり次第、1 セッション目から着手できる。
