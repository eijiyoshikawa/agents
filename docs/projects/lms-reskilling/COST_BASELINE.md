# コスト計算（確定前提・実数）

> 本書は「想定受講者数を1つ確定」した上での実数計算。
> [COST_ESTIMATE.md](./COST_ESTIMATE.md) のシナリオ表を**この確定前提で置き換える**。
> **配信方式は Cloudflare R2 + CDN の自前HLS配信（egress＝配信転送料が無料）を採用**し、配信単価を最小化した構成で計算する。
> 為替 $1 = ¥155。金額は概算。最終更新: 2026-07-15 / 検証: Finance・Tech Lead

---

## 1. 確定した前提（ベースライン）

| パラメータ | 値 | 補足 |
|-----------|-----|------|
| テナント（クライアント企業） | **5 社** | 立ち上げ〜受託が乗った初期の現実値 |
| アクティブ受講者 | **200 名** | 常時受講中の人数 |
| コンテンツ総尺 | **30 時間（1,800 分）** | 1コース想定 |
| **月間視聴時間 / 受講者** | **12 時間** | リスキリングは2〜3ヶ月で消化する前提の月割 |
| **動画配信方式** | **Cloudflare R2 + CDN（自前HLS・egress無料）** | ★配信単価を最小化する選択。従量SaaS(Stream/Mux)は不採用 |
| 受講者従量単価（SaaS） | ¥1,200 / 名・月 | 損益試算用（§4） |

> **R2 採用でコスト構造が変わる**: 従量配信SaaS（Stream/Mux）は「視聴分数 × 単価」で配信費が受講量に線形増加した。**R2 は egress（配信転送料）が無料**のため、コストは「保管容量」と「リクエスト数」だけ。**視聴が増えても配信費がほぼ増えない**。代償はアップロード時の ffmpeg エンコード（一度きり）と署名URLの内製で、これは配信単価には効かない。

## 2. 月次ランニングコスト（実数・R2構成）

R2 の課金要素:
```
保管費   = 保管GB × $0.015/GB・月
読取費   = HLSセグメント読取数 × $0.36 / 100万回（Class B）
配信転送 = $0（egress 無料）  ← ここが従量SaaSとの決定的な差
```
保管見積: 30h × 約3GB/h（ABR3画質＋原本）≈ 90GB。

| 項目 | 計算 | 月額(円) |
|------|------|:--------:|
| ホスティング (Vercel Pro) | 定額 $20 | 3,100 |
| DB (Supabase/Neon Pro) | 定額 $25 | 3,900 |
| **動画 保管 (R2)** | 90GB × $0.015 | 210 |
| **動画 配信転送 (R2 egress)** | **無料** | **0** |
| 動画 読取 (R2 Class B) | 200名×12h×約600seg/h ≈ 144万回 | 80 |
| エンコード compute (ffmpeg・按分) | 一度きり処理の月按分 | 1,500 |
| ストレージ (PDF・エクスポート, R2) | | 300 |
| メール / 監視 / ドメイン按分 | | 2,900 |
| **月次合計** | | **≒ ¥12,000/月** |

> 参考: 従量SaaS(Stream/Mux)構成だと同条件で配信費だけで ≒ ¥22,000/月、合計 ≒ ¥34,000/月だった。**R2 採用で月額を約 1/3 に圧縮**。

## 3. 年次ランニングコスト

| 区分 | 年額(円) |
|------|:--------:|
| 定額（ホスティング+DB+監視等） | ≒ 118,000 |
| 動画 保管 (R2, 毎月×12) | ≒ 2,500 |
| 動画 配信転送 | **0** |
| 動画 読取・エンコード按分・その他 | ≒ 24,000 |
| **年次合計** | **≒ ¥145,000/年** |

> 従量SaaS構成の年次 ≒ ¥412,000 と比べ **年間で約 ¥267,000 の削減**。

## 4. ユニットエコノミクス（SaaS 提供時・受講者従量 ¥1,200/名）

| 指標 | 値 |
|------|-----|
| 月次売上 | 200名 × ¥1,200 = **¥240,000/月** |
| 月次直接原価（ランニング） | **¥12,000/月** |
| **月次粗利** | **¥228,000/月（粗利率 95%）** |
| 受講者1名あたり原価 | ¥12,000 / 200 = **¥60/名・月** |
| 受講者1名あたり粗利 | ¥1,200 − ¥60 = **¥1,140/名・月** |
| 損益分岐 受講者数 | 定額 ≒ ¥10,000 ÷ ¥1,140 ≒ **約 9 名**で黒字化 |

- **初期開発費（MVP 約100人日）は別**。R2自前HLSはエンコード基盤・署名配信の内製で **+5〜8人日**（従量SaaS構成比）。内製なら追加API費ゼロ、外注換算 約400〜500万円。
- **初期に +5〜8人日**かけても、**月あたり配信費を約¥22,000圧縮**するので、**数ヶ月で追加工数分を回収**（外注換算でも1年内）。受講量が増えるほど R2 の優位は拡大。

## 5. 感度分析 — R2 採用で「視聴量」がコストにほぼ効かなくなる

配信転送が無料のため、視聴が増えて動くのは R2 読取費（Class B）だけ。これは極小。

### 月間視聴時間/人 を振る（受講者200名固定）
| 月間視聴/人 | 視聴で動く費用(読取) | ランニング合計/月 | 粗利率(¥1,200/名) |
|:-----------:|:-------------------:|:----------------:|:----------------:|
| 6 時間 | ≒ ¥40 | ≒ ¥12,000 | 95% |
| **12 時間(基準)** | ≒ ¥80 | ≒ ¥12,000 | 95% |
| 24 時間 | ≒ ¥160 | ≒ ¥12,000 | 95% |
| 48 時間 | ≒ ¥320 | ≒ ¥12,500 | 95% |

> **ほぼ横ばい。** 従量SaaSでは48時間視聴でランニングが ¥101,000 まで膨らんだが、R2 では ¥12,500 で済む。ここが配信単価削減の本質。

### 受講者数を振る（視聴12h/人固定）
| 受講者 | ランニング合計/月 | 売上(¥1,200) | 粗利/月 | （参考）従量SaaS構成の合計 |
|:------:|:----------------:|:-----------:|:------:|:------------------------:|
| 50 | ≒ ¥11,500 | ¥60,000 | ¥48,500 | ≒ ¥16,000 |
| **200(基準)** | **≒ ¥12,000** | **¥240,000** | **¥228,000** | ≒ ¥34,000 |
| 500 | ≒ ¥12,500 | ¥600,000 | ¥587,500 | ≒ ¥69,000 |
| 1,000 | ≒ ¥13,000 | ¥1,200,000 | ¥1,187,000 | ≒ ¥126,000 |

> **示唆**: R2 構成ではランニングが**受講者数にほぼ比例しない**（保管はコンテンツ量で決まり、配信転送は無料）。1,000名規模で従量SaaS比 **約 1/10**。規模拡大＝ほぼ純増利益。唯一のスケール要因は「コンテンツ総尺（保管GB）」だが、100hに増えても保管費は月¥700程度で誤差。

## 6. まとめ（確定前提・R2構成）

| 区分 | 金額 |
|------|------|
| 前提 | 5テナント / 受講者200名 / 30hコンテンツ / 視聴12h・人 / **R2+自前HLS配信** |
| **月次ランニング** | **≒ ¥12,000/月**（従量SaaS比 約1/3） |
| **年次ランニング** | **≒ ¥145,000/年** |
| 受講者1名あたり原価 | ≒ ¥60/月 |
| 損益分岐 | 受講者 約9名（¥1,200/名課金時） |
| MVP 初期開発 | 約100人日（R2エンコード基盤込・内製なら追加API費ゼロ / 外注換算 約400〜500万円） |
| 追加工数の回収 | R2化の +5〜8人日 は月¥22,000の配信費圧縮で数ヶ月〜1年内に回収 |

> 最大の効果は **配信転送(egress)の無料化**。視聴量・受講者数が増えてもランニングがほぼ横ばいになり、スケールするほど粗利率が高止まりする。唯一のコスト増要因はコンテンツ総尺（保管GB）だが影響は軽微。実運用開始後、初月の実保管GBと読取回数で本表を更新するのが望ましい。
