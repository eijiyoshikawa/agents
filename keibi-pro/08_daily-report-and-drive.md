# 08. 日報回収フロー & Google Drive 連携(仮)

> 本章はスクショのない新機能想定。理想フロー:
> **隊員がフォームで日報(出勤情報+現場サイン)を提出 → サーバ経由で Google Drive に整理保存 → 勤務実績に自動連携 → 取引先へ控えを自動送信。**
> 警備業は「現場で紙にサインをもらう」運用が根強く残るため、紙とデジタルの橋渡しを綺麗に行うのが価値の核。

> 📎 一次ソース補足(`15` JBCAカタログ):提供元の「スマホdeサイン」は**スマホ画面上で電子署名(紙不使用)→クラウド保存→取引先へ控え自動送信**。
> 一方ユーザー要望は「**現場でサインをもらった紙の写真**」。本サービスは**両対応**とする:
> (a) 端末上で電子サイン(ペーパーレス)、(b) 紙サインの写真アップロード(顧客が紙必須の場合)。
> いずれも Drive 保存 + **取引先へ控え自動送信**(誤字脱字・破損・紛失の回避、郵送/交通費削減)。

---

## 1. 全体フロー

```
[隊員モバイル(フォーム)]
   現場選択 → 出退勤・休憩入力 → 紙日報/作業確認書を撮影 → 提出
        │
        ▼
[警備Pro サーバ]
   ・バリデーション(必須項目・写真有無)
   ・勤務実績(該当行)へ自動マッチング/起票
   ・写真を Google Drive へ転送(命名規約・フォルダ自動生成)
   ・Drive ファイルIDを実績行に添付として保存
        │
        ▼
[管理者/配置担当]
   ・承認(出退勤の確定)→ 勤務実績確定
   ・請求/給与のエビデンスとして写真を即参照
   ・管制日報・請求明細から原本写真へワンクリック
```

---

## 2. 隊員が入力するフォーム項目(仮)

| 項目 | 種別 | 備考 |
|------|------|------|
| 日付 | 自動(当日)/ 選択 | |
| 配置先(現場) | 選択 | 当日自分が配置された現場をサジェスト |
| 出勤時刻 / 退勤時刻 | 時刻 | 打刻ボタン(現在時刻ワンタップ)も可 |
| 休憩時間 | 数値/時刻 | |
| 天候 | 選択 | 天候マスタ連携・日報記載 |
| 業務特記・引継ぎ | テキスト | 任意 |
| 事故/ヒヤリハット有無 | トグル+詳細 | 有の場合エスカレーション |
| **現場サイン** | (a)端末で電子署名 / (b)紙の写真撮影 | どちらか必須。顧客の運用で選択 |
| **紙日報・作業確認書の写真** | カメラ/添付(複数可) | 紙運用時。現場サイン入り |
| 交通費・立替 | 数値+レシート写真 | 任意 |
| 位置情報(任意) | GPS | 現場到着確認の補助(同意ベース) |

- **撮影補助**:枠ガイド・自動トリミング・複数枚(表/裏・複数現場)対応。
- **オフライン対応**:電波の弱い現場向けに端末内一時保存 → 圏内で自動送信(`10` UX章参照)。

## 3. Google Drive 保存設計(仮)

### フォルダ構成(自動生成)
```
警備Pro日報/
└─ {得意先名}/
   └─ {配置先名}/
      └─ {YYYY}/
         └─ {YYYY-MM}/
            └─ {YYYY-MM-DD}/
               ├─ 日報_{隊員名}_{隊員番号}_{連番}.jpg
               ├─ 作業確認書_{隊員名}_{連番}.jpg
               └─ レシート_{隊員名}_{連番}.jpg
```

### 命名規約
- `{種別}_{隊員番号}_{隊員名}_{日付}_{連番}.{ext}`
- 検索性・重複回避を担保。メタデータ(得意先/現場/勤務種別)はファイル説明 or サイドカーJSONにも保持。

### 連携方式
- Google Drive API(サービスアカウント or OAuth)。会社のDriveの指定親フォルダ配下に保存。
- **保存先の親フォルダは会社設定で指定**(自社Drive/共有ドライブ)。
- 実績行には **Drive ファイルID + 共有リンク** を保存し、警備Proの画面から直接プレビュー。
- 失敗時リトライ・保存済み/未保存ステータスを実績行に表示。

### バックアップ/保管
- 原本はDrive、警備Pro DBには参照(ID/リンク/サムネイル)を保持。
- 法定保存年限(契約・名簿・賃金台帳等)を見据え、**削除保護・保管期限ラベル**を付与(仮)。

## 4. 勤務実績への自動連携

- 提出フォームの「現場+日付+隊員」で、配置予定(`02` 配置)とマッチング → 該当**勤務実績行へ出退勤・写真を反映**。
- マッチしない場合は「未配置の実績」として起票し、配置担当に通知(飛び込み対応等)。
- **OCR(仮)**:紙日報の出退勤欄・サイン有無を読み取り、入力補助/二重チェック。最終確定は人が承認。
- 写真/電子サインは **管制日報・請求明細書のエビデンス**として紐づき、得意先への証跡提示が容易に。
- **取引先への控え自動送信**:承認済み日報の控え(PDF)を、配置先の送付先(`管制日報送付先アドレス`)へ自動メール/共有。請求の裏付けとしても機能。

---

## 5. 承認フロー(仮)

```
隊員提出 → [隊長/現場監督 確認(任意)] → 配置担当/管理者 承認 → 勤務実績確定 → 締め対象
```
- 差戻し(写真不鮮明・項目不足)→ 隊員へ再提出依頼。
- 一括承認(現場単位/日単位)で締め前の処理を高速化。

---

## 6. シフト(出勤可否)回収フォーム(仮)

日報とは別に、**翌月/翌週のシフト希望**もフォームで回収(`09` 従業員アプリと共通)。
- 入力:勤務可能日 / NG日 / 希望現場・勤務種別 / 連勤上限 など。
- → 休日登録・配置予定入力に**候補/制約として反映**(同配置NG・資格と合わせて配置を支援)。
- LINE/メール通知でリマインド(仮)。

---

## 7. 留意点・論点(要検討)

- 個人情報・位置情報の取得同意(プライバシーポリシー)。
- 紙原本の保管義務とDrive保存の整合(原本廃棄可否は顧客/法務確認)。
- Drive容量・共有ドライブの権限設計(隊員に元データを見せない)。
- 通信できない現場での運用(オフライン→後送信)。
- OCR精度に依存しすぎない(人の承認を必ず挟む)。
