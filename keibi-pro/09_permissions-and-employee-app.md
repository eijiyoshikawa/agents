# 09. 権限管理 & 従業員(隊員)向けアプリ(仮)

> 方針:従業員向けは「別途高額課金」ではなく**安価/含める**前提。
> 管理者権限ごとに管理画面の表示を絞り、隊員はモバイルから日報・シフトを出せる軽量アプリを提供する。

---

## 1. ロール設計(仮)

| ロール | 主な対象 | できること(概略) |
|--------|---------|-------------------|
| **経営者 / システム管理者** | 社長・管理部 | 全機能・全支店・マスタ・権限設定・自社設定 |
| **配置担当(管制)** | 配車・管制 | 受注・配置・勤務実績・日報承認(単価/給与は閲覧制限可) |
| **経理** | 経理 | 請求・入金・給与・帳票・単価(配置の編集は不可) |
| **支店長 / 拠点責任者** | 支店 | 自支店のみ全般(他支店は不可) |
| **隊長 / 現場監督** | 現場リーダー | 自分の担当現場の配置・実績・日報確認のみ |
| **隊員(従業員)** | 警備員 | モバイルで自分の勤怠・日報提出・シフト希望・給与明細閲覧のみ |

※ ロールはカスタム可能(参考元「担当者権限マスタ」相当をWeb化)。

---

## 2. 絞り込みの3階層

権限は **画面 / 機能 / データ範囲** の3階層で制御する。

1. **画面レベル**:ナビに出す/出さない(例:隊員には請求・給与管理メニューを非表示)。
2. **機能(操作)レベル**:閲覧のみ / 編集 / 承認 / 削除 / 出力。
   - 例:配置担当は実績を編集できるが「単価」「給与額」は閲覧不可(マスク表示)。
3. **データ範囲レベル**:
   - **支店スコープ**(自支店のみ)
   - **現場スコープ**(自分が担当する配置先のみ:隊長)
   - **本人スコープ**(自分のデータのみ:隊員)

> 特に **単価・給与・原価情報**は最も機微。ロールにより「金額列を非表示/マスク」する設定を標準装備。

---

## 3. 項目レベルのマスキング(仮)

- 給与額・単価・粗利などのセンシティブ列は、権限がなければ `****` 表示。
- CSV/PDF出力時も同様に除外/マスク。
- 監査ログ(誰がいつ給与/単価を見た・変更したか)を記録。

---

## 4. 従業員(隊員)向けモバイルアプリ(仮)

「課金を抑えたライト機能」を想定。隊員1人あたり低額 or 管理プランに内包。

### できること
| 機能 | 内容 |
|------|------|
| 日報提出 | 出退勤・休憩・現場サイン(電子署名 or 紙写真)提出(`08` 参照) |
| **上下番報告** | **ワンタップ**で上番/下番 → リアルタイム反映 → 管理側へ**ワンクリック取込**(配置ボードのステータスに連動) |
| 出退勤打刻 | 現在時刻ワンタップ + 位置情報(任意) |
| **シフト確認 + 地図ナビ** | 配置された現場・時間・集合場所・現場連絡先。**ワンタップで地図アプリ起動→現場まで最適ルート** |
| **シフト希望提出** | 勤務可能日/NG日/希望現場をフォームで(`08` §6) |
| 連絡受信 | 配置連絡・変更通知(プッシュ/LINE/メール) |
| 給与明細閲覧 | 確定済み明細のWeb閲覧(PDF)・いつでも確認 |
| 休暇申請 | ペーパーレスで申請→承認、申請状況をリアルタイム把握 |
| 各種書類 | 教育記録・資格・契約書類の受領/電子サイン |
| プロフィール | 連絡先・口座(振込)・資格の本人申請(承認制) |

> 📎 `15` JBCAカタログ準拠:上記は提供元「スマホde勤怠」で実証済みの導線(上下番ワンタップ取込・シフト送信+地図ナビ・休暇申請・給与確認)。50名規模で**作業時間76.8%削減**の効果報告あり。

### 管理者→隊員の一斉連絡(お知らせ送信)
- 全体/個人/複数人へ**お知らせを一斉送信**。アプリ起動直後の画面に表示し**確認漏れを防止**。
- 配信状況(既読/未読)をリアルタイム把握。電話連絡コスト・通信費を削減。
- 用途:急な配置変更、当日連絡、欠員時の応援募集、書類提出依頼。

### 見せないもの
- 他人の情報、得意先単価、請求・給与の会社全体データ、配置ボード全体。

---

## 5. シフト回収 → 配置への流れ(仮)

```
[隊員] シフト希望フォーム提出(可能日/NG/希望現場)
   ▼
[警備Pro] 希望を集約 → 休日登録・配置制約に反映
   ▼
[配置担当] 配置ボードで割当(希望・資格・同配置NG・距離を加味)
   ▼
[隊員] 配置確定の通知を受信 → 当日「出発報告」→ 日報提出
```
- 希望と実配置の差異(希望外配置)を可視化し、交渉(△)対象を明示。

---

## 6. 通知チャネル(仮)

- アプリ内プッシュ / メール / LINE(公式アカウント連携)。
- 用途:配置連絡、変更、シフト提出リマインド、給与明細公開、書類サイン依頼。
- 隊員の年齢層を踏まえ、**LINE中心**でも完結できる導線を用意(`10` アクセシビリティ)。

---

## 7. 課金モデルの考え方(仮 / `06` と連動)

- 管理者・内勤ユーザー:プラン課金(機能/拠点で段階)。
- **隊員アカウント:1人あたり少額 or 一定数まで無料枠**(従業員に費用負担をかけない思想)。
- 紙運用しか使わない隊員向けに「アプリ無し(管理者代理入力)」も許容。

---

## 8. 論点(要検討)

- 隊員アカウントの本人確認・退職時の即時無効化。
- 位置情報・写真のプライバシー同意フロー。
- 協力会社(外注)隊員の扱い(アカウント付与する/しない)。
- LINE連携の場合の個人情報保護・なりすまし対策。
